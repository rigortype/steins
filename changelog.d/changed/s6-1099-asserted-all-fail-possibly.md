- **An argument or return whose value the engine holds only on an `Asserted` premise (a docblock or a catalog claim) and that the native type rejects in every member now reports `phpdoc.maybe-argument-mismatch` / `phpdoc.maybe-return-mismatch` under `--profile strict`, where it was silent.** The default profile is unchanged, and a proven (`Verified`) value that fails every member keeps its definite id, while a `Verified` abstract `string` into `?int` stays silent. New findings can appear for a `@param 'a'|'b'` on a `mixed` parameter passed to an `int` parameter, for an `if`/`else` or ternary join of literals none of which the callee accepts, for a preg-seeded capture group (`takes_int($m[1])` on a literal `(x)` group), and for an `@param string` on `mixed` passed to `int` in a strict file.
  - **The message names every member (`its "a", "b" and "c" arms raise a TypeError`) or says `its every arm raises a TypeError` for an abstract type.** The ids are strict-floored and sit in the fp-gate's tripwire bucket.
  - **The new rows stay silent when the variable (or a plain copy of it) is used in the function body in any way beyond the reported call, a copy, a null test (`!== null`, `isset`, `??`) or a `preg_match` out-parameter.** A condition, a stored boolean, a helper call or a closure `use` may already have removed every value the docblock allows, so the rule is a conservative scan of the body rather than a path analysis, and findings the old behaviour never had are not added there.
  - **A `return` inside a `try` (or a `catch`) whose `finally` contains a `return`, `throw` or `exit` is not judged by the new return row, because the `finally` replaces its value.** Existing return findings are unchanged.
