- **A printf call's literal format and a literal strict flag are read at the call site: `sprintf('%d-%s', 1, 'a')` is pure again, `in_array($x, $h, true)` runs no `__toString`, and a setting read that depends on a value the site cannot see is the new `value-dependent-read` gap and never a label.** A label is proven only where the read is unconditional for the call as written: a literal `%f`, `%g` or `%G` reads the locale whatever the value is, so it reports under a pure envelope at the default floor; a literal with none of them drops the read, so a body whose only effect was that read goes back to `{}` and exhaustive; and a `%s` reads the `precision` ini (new label `global.read.setting.precision`, ADR-0101 D4) only if its value is a float, so a value shown a float carries the label, a value shown no float carries nothing, and any other value (and a format that is not a literal or that the parser cannot read, a vector's elements, and a printf name handed over as a callback) is `value-dependent-read`, recorded beside any `user-code-reach` the value carries, which reports at the `strict` floor as `effect.maybe-envelope-exceeded` and is never a default-floor finding (the gap is listed in `annotate`'s `gaps` and the CLI reference). A value is shown no float by its form (a string, integer, boolean or `null` literal, a concatenation, an interpolated string, a comparison, a cast to `int`, `string`, `bool` or `array`), by a ternary or `??` whose branches are, by a parameter or local nothing may leave a float in and whose declared type admits none, by a typed `$this->p` or `self::$p`, by a call whose declared return admits none (a project function or method's native hint, a builtin's mined row, a `Throwable` accessor), and by a global constant or a class constant whose value is not a float; it is shown a float by a float literal, a cast to `float`, a `float` parameter nothing writes, a `float`-typed property, a call declared `float` or a constant whose value is one. The same literal format also says which values reach `__toString` (only a `%s` does), so `sprintf('%d', $o)`, `'%s %d'` with a literal on the `%s`, `'%2$d %1$s'`, `printf("%05d\n", $o)` and `vsprintf('%d-%d', $a)` no longer reach user code, and the `user-code-reach` gap that stood at them in both the effect and the throw lane is gone; a position a `%s` names, a format the call does not show and a format that cannot be read keep it. A literal `true` as the third argument of `in_array` or `array_search` compares by identity and likewise rules out the needle and the haystack. The `numfmt_get_attribute` row stated `int|false` and the miner now corrects it to `int|float|false`, since the function returns a float for the float attributes.
