- **The bcmath functions, `bcscale`, `error_reporting`, `get_include_path`, `set_include_path`, `set_time_limit` and `ini_get_all` now carry the ini residue's setting labels, and the bcmath read depends on the scale (#1000).** A bcmath call reads `bcmath.scale` only when its `$scale` is omitted or `null`, so `bcadd('1', '2', 2)` is pure and `bcadd('1', '2')` reads the setting; `error_reporting()` and `bcscale()` read it, and `error_reporting($l)`, `bcscale($n)` and `set_include_path($p)` also write it; `set_time_limit` writes `max_execution_time`; `ini_get_all` reads the setting parent. Findings can appear: a pure envelope over one of these calls, or over a function that calls one (`error_reporting` in an error handler, `set_include_path` in a test runner), now reports `effect.envelope-exceeded` where it was silently non-exhaustive before, and `effects-envelope` refuses a few more candidates with the new labels named. No `check` finding and no transform edit changes on the ten public packages.
  - **`ini_get`, `ini_set` and `ini_restore` of `max_execution_time` now name the residue cell.** It joins the literal-name table that `include_path` and `error_reporting` are in, so `ini_get('max_execution_time')` is `global.read.setting.ini` where it was the coarse `global.read`.
