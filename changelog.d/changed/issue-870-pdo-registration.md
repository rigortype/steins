- **`PDOStatement::setFetchMode()` and `PDO::setAttribute()` are catalogued, and the class or object a PDO call registers is charged at the registering call, not at the later fetch.** `FETCH_CLASS`'s class name and `FETCH_INTO`'s object (`setFetchMode`'s arguments after the mode), `ATTR_STATEMENT_CLASS` and `ATTR_DEFAULT_FETCH_MODE` (`setAttribute`'s value) reach user code at that call: a missing class autoloads there, and every later `fetch()` runs the constructor and `__set` of what was registered. `setFetchMode`'s mode counts as well, because `FETCH_CLASS | FETCH_CLASSTYPE` registers that every later fetch constructs the class its first column names, and the rule does not read constants, so no `setFetchMode` call reads as complete. This holds in the effect lane and in a `strict_types=1` file; the throw lane has no row for either method and stays `…?`. Both calls already read as `…?` for want of a row, so no body changes completeness; they now keep a label beside the gap: `mutate` for `setFetchMode`, since it changes what the statement's next fetch returns, and `io.db` for `setAttribute`. A body that only fetches is unchanged. On the ten public corpus packages no finding, effect baseline entry, transform plan or annotate margin moves.
