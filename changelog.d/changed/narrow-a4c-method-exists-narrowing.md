- **`method_exists($x, 'm')` now narrows `$x`'s declared type on both sides: where it held, the classes that provably lack `m()` are dropped, and where it failed, the classes that provably declare it, so `if (method_exists($x, 'go')) { return ''; } return $x->go();` over `N|M` reports `call.undefined-method M::go()`.** A class counts as declaring `m()` when its own chain, a composed trait or one of its interfaces holds it, abstract, static or of any visibility, and as lacking it when it and every descendant Steins can enumerate do not; `__call` does not count, as it does not for PHP's `method_exists`. A class that may or may not have it (an open hierarchy, a descendant that declares it, a vendor ancestor) stays on both sides, and so does a non-object part of the type such as `null`. The narrowing applies wherever a condition narrows: `if`, `!`, `&&` and `||`, `assert()` and a variable that stores the test. Findings can appear on the side where the test failed, and `debug.type` dumps show the narrowed type; `is_callable([$x, 'm'])` and `property_exists()` still narrow nothing.
