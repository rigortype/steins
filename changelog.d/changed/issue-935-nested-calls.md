- **A call is judged wherever it is written, not only where its statement spells one (#935, #1050).** `call.undefined-function`, `call.undefined-method`, `call.too-few-arguments`, `call.unknown-named-argument` and the `new` and static-call forms of the arity and visibility ids now report a call nested in an argument, an operand, an array element or key, a `new` argument, a `throw`, `exit` or `print` operand, a named or literal-spread argument, a `static` initializer, or either arm of a `&&`, `||`, `?:` or `??`, each at the call's own column; and a first-class callable (`f(...)`, `$o->m(...)`, `C::m(...)`) is an existence site, since PHP throws when it builds the `Closure`, but never an arity, type or effect site. The value-dependent ids (`call.on-null`, `call.on-non-object`, `call.inaccessible-method`, `phpdoc.undefined-method`, `call.printf-too-few-arguments`, `preg.invalid-pattern`) judge a nested call only where it is evaluated unconditionally and only on a receiver the statement does not rebind; a call under `@`, in an arm a decided `function_exists` or `defined` guard proves unevaluated, or beside a `method_exists` test in the same expression stays silent. A guard assigned first (`$ok = function_exists('f') and f()`, `($has = G) ? f() : 0`) or stored in a variable (`$has = function_exists('f'); if ($has) { f(); }`) discharges what it guards like the bare call does, which also removes a statement-level false positive, and a non-null literal on the left of `??` kills the right. `print` keeps the known values like `echo` does instead of clearing them. New findings appear, mostly `call.undefined-function` for a function the analysing PHP lacks, with the same posture as a statement-level call; a named-only call `$o->m(x: 1)` to an undefined method now reports too.
