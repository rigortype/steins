- **`getenv` and `putenv` name the environment block they read and write, `global.read.setting.env` and `global.write.setting.env`, so an envelope can admit the environment on its own (#1000).** Before, both carried the coarse `global.read` and `global.write`, which still admit the new labels by prefix, so no existing envelope or docblock tag changes meaning. `getenv` carries the read at every arity, `putenv` the write, and `$_ENV` is unchanged: it is a startup copy that neither function reaches. The two labels join the registry, so `effect.unknown-label` stops firing on them and a docblock tag naming them binds as an envelope. No finding appears or disappears on the public corpus under `check`; `effect-diff` reports the functions that call these two, whose labels now carry the narrower name.
