- **`steins check --progress` (or `STEINS_PROGRESS=1`) reports where a run is while it runs.** It writes one stderr line as each phase ends (`discover`, `capture`, `parse`, `universe`, `purity oracle`, `walk`, `report`, `suppress`, `output`) with the phase's time and the time since the run began, and names any single file whose walk took 250 ms or more (`STEINS_PROGRESS_SLOW_MS=<n>` changes the threshold), on the cached path and with `--no-cache`, including under the parallel walk. It is off by default; without it stdout and stderr are byte-identical to before, and with it findings and exit codes do not change.
