- **The locale read of a literal printf format carries a fix: `check --fix` spells `%f` as `%F`, `%g` as `%h` and `%G` as `%H`.** The edit rides `effect.envelope-exceeded` and `effect.liskov-widened` when the exceeding label is `global.read.setting.locale` and its origin is a `sprintf`, `printf`, `vsprintf` or `vprintf` call in the enveloped body with a literal format (#1000). It keeps flags, width, precision and `n$`, leaves `%%f` alone, and is exact on the source bytes in a `'`- or `"`-quoted literal, where an escape-spelled letter such as `"%\x66"` is replaced whole; a format that is not a literal, a heredoc, an octal escape PHP truncates (`\546`) and a callee's printf (the finding names an origin elsewhere) get no fix. `h` and `H` exist from PHP 8.0, so a call with a `g` or `G` conversion gets no fix where the declared PHP floor, or the runtime's minor when none is declared, is below 8.0 or unknown (as under `--no-php` with no target); `%F` is offered on any floor. A Liskov finding is fixed only when every origin of the read is a printf of the method's own body, and one that also reaches the read through a callee, a closure or another method gets none. The output is byte-identical under the `C` locale and always spells the decimal point `.`, which differs only under a locale whose decimal point is not `.`, as the fix title says. A function with no envelope has no finding and no fix, and there is no bulk transform. `--fix` also no longer refuses a run when a locale fix lies inside a statement another fix deletes (a `dumpType(sprintf('%.2f', $x))`): the enclosed edit is left to the larger one. No finding appears or disappears, only the `fix` payload on the findings above; the post-check still refuses the write when any diagnostic id's count would rise, and does not by itself check that the locale read is gone.
