- **`cargo xtask fp-gate` reports each project as it runs and fails a stuck one by name.** Each project writes a start line and an end line to stderr, with its wall time and the phase split of its cold and warm passes, and names any file whose walk took five seconds or more (`STEINS_PROGRESS_SLOW_MS=<n>` changes the threshold); stdout, the report, is unchanged. `--deadline <secs>` (default 1200, `0` disables) bounds each project: one that outlives it is reported on stderr with its elapsed time, the last phase it finished and every file whose walk had begun and not ended, and the gate exits with status 3, apart from a red verdict (1) and a command that could not run (2). This is a harness limit only; the analyzer has no wall-clock budget, and findings do not change.
