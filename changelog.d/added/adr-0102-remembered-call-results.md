- **A guard on a few pure builtins is remembered: after `if (strpos($h, '=') !== false)`, the next `strpos($h, '=')` in the same function is `int<0, max>` and no longer `int<0, max>|false`, and `strlen($s) === 5` makes the next `strlen($s)` the value `5`.** Only an allowlist of builtins that read no ambient state at all is remembered (`strlen`, `ord`, `strpos`, `strrpos`, `str_contains`, `str_starts_with`, `str_ends_with`, `count` of one argument, the `is_*` type predicates, `array_key_exists`, `array_key_first`, `array_key_last`, `ctype_digit`, `ctype_xdigit`, `intdiv`, `abs`), and the ones with `string` parameters only in a `strict_types` file; the arguments must be local variables passed by value or scalar literals. A builtin the effect lane calls `{}` is not enough: `preg_*`, `strtolower`, `strval` and `json_encode` read the locale or an ini setting without a label, so they are never remembered, and neither is any setting read (`sprintf('%.2f', $x)`, `setlocale`), a clock or random call, the filesystem (`is_dir`, `file_exists`), a method or a nested call. The memory ends when a variable the call names is assigned, written through an offset, unset or passed by reference; a loop forgets what its body may write, and a join keeps a call only where both branches remember it. A remembered `===` result decides a second guard on the same call, so its branch is dead and its findings are not reported there; a remembered range or truthiness never decides one. Findings can move where the narrowed second call reaches a check, and through a decided guard the findings inside a now-dead branch go; none appeared or disappeared on the ten public packages. See ADR-0102 §7.
