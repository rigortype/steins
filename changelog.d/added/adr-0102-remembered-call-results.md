- **A builtin call a guard has narrowed is remembered: after `if (strpos($h, '=') !== false)`, the next `strpos($h, '=')` in the same function is `int<0, max>` and no longer `int<0, max>|false`, and `strlen($s) === 5` makes the next `strlen($s)` the value `5`.** The call is remembered by its callee and its arguments (local variables and literals only), only where the effect lane reads the call as `{}` or as a read of a setting (`sprintf('%.2f', $x)`, `setlocale(LC_ALL, '0')`); a call that reads the clock, a generator, the filesystem (`is_dir`, `file_exists`) or anything the lane cannot see is never remembered, and neither is a method call or a nested call. The memory ends where the engine's answer can change: when a variable the call names is assigned, written through an offset, unset or passed by reference, at any statement that holds a site that may rewrite a setting (a `setlocale`, a user function call, a gap) for a call that reads a setting, and at any `ini_set` for every call; a loop forgets what its body writes, and a join keeps a call only where both branches remember it. A remembered `===` result decides a second guard on the same call, so its branch is dead and its findings are not reported there; a remembered range or truthiness never decides one. Findings can move where the narrowed second call reaches a check, and through a decided guard the findings inside a now-dead branch go; none appeared or disappeared on the ten public packages. See ADR-0102 §7.
