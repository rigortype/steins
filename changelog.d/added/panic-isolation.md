- **An internal panic while analyzing one file no longer aborts `steins check`: that file reports `internal.panic`, every other file is analyzed as usual, and the run exits `2`.** The finding names the file and the panic, sits at its line 1, and replaces that file's own findings for the run. It is a mechanics-layer id outside every channel: profiles, `@steins-ignore`, the vendor filter and the baseline all pass it through, and `--set-baseline` refuses to write from such a run. Exit `2` now also means "Steins itself failed", and wins over `1`; the report is still printed in every format. A run that reports one publishes nothing to the warm cache, so no later run replays it. Only the per-file walk is isolated: a panic while parsing, building the project index, or in the effect and throw fixpoints still ends the run. `RUST_BACKTRACE=1` prints the full panic report for a bug report.
