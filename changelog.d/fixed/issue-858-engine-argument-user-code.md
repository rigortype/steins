- **An engine constructor or method that can run your code through an argument no longer reads as complete: `new \RuntimeException($o)`, `new \DateTime($o)`, `parent::__construct($o)` into an engine exception and `parent::query($o)` on a `PDO` subclass now mark the calling body `…?` in both the effect and the throw lane.** Each of those converts an object argument through `__toString()` when the file is not `strict_types=1` (the exception's `$message`, the date string, the SQL statement), and `new PDO(…, $options)` with an options array can name a class the autoloader then loads; Steins read the call as having only the effects and throws its catalog row states. This is the rule `strlen($o)` already followed, now applied to engine methods and constructors, from a curated per-method table. The call keeps its row, so a proven label is unchanged. A call stays complete where the argument is a literal, a `string`-typed parameter or local that is never an object, an interpolation or a concatenation, or the file declares `strict_types=1`.
  - **No finding appears or disappears:** `check --profile strict` is byte-identical on the ten public corpora. What moves is the `…?` marker and the coverage kinds (`user-code-reach`), the `effect-diff` baseline, the tags `effects-envelope` writes, and the loops `loop-to-array-map` accepts. On the corpora 4 bodies become effect-`…?` and 5 throw-`…?` (all but one because the message is an unproven `sprintf()` result, as in `throw new InvalidArgumentException(\sprintf('…', $name))`), and `effects-envelope` writes one tag fewer (852 instead of 853).
  - A call whose arguments Steins cannot read position by position reads as reaching: a named or spread argument list, and a method call on a receiver that is not `$this`, `self`, `parent` or a class name (`$pdo->query($sql)`, `(new PDO($dsn))->query($sql)`).
  - The `Throwable` accessors (`getMessage()` and the rest) take no arguments and stay complete.
