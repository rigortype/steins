- **A builtin call that can run your code through its arguments no longer counts as pure: `strlen($o)` without `declare(strict_types=1)`, `count($countable)`, `in_array()`, `implode()` or `json_encode()` of values that may hold objects, `is_callable('Foo::bar')`, `usort($rows, $comparator)` with a comparator Steins cannot resolve and `array_map('trim', $values)` now mark the calling body `…?`.** Each of those can run `__toString()`, `Countable::count()`, `jsonSerialize()`, the autoloader or a callback, and Steins read the call as having no effect at all. A call stays pure where Steins can see that the arguments rule this out: a literal, a parameter or local whose declared type and every assignment hold no object, a typed property, or, for a `string` parameter, `strict_types=1` in the calling file. On the ten public corpora 364 bodies become `…?`, and `steins transform effects-envelope` writes 46 fewer tags (853 instead of 895), most of them on classes whose `sprintf()` or `implode()` arguments Steins cannot see the contents of.
  - **No finding appears or disappears:** the change only removes exhaustiveness, and `check` reports the same findings on the public corpora. What moves is the `…?` marker, the `effect-diff` baseline, the tags `effects-envelope` writes, and the loops `loop-to-array-map` accepts.
  - `strcmp()`, `strncmp()`, `strcasecmp()`, `strncasecmp()`, `strspn()`, `strcspn()`, `substr_count()`, `ord()`, `chr()`, `bin2hex()`, `hex2bin()`, `dirname()` and `unpack()` are now pure where their arguments are ruled out the same way, which makes 37 bodies exhaustive and adds 4 tags. They stay `…?` elsewhere.
