- **`call.inaccessible-method` and `property.inaccessible` no longer report a protected member that a subclass redeclares when the site's class shares the member's root with it.** With `Base { protected function h() }`, `A extends Base` redeclaring `h()`, and `B extends Base` calling `(new A)->h()`, PHP allows the call on every version because it checks the class that first introduced the method, and Steins checked `A`. This covers `static` methods, abstract roots and constructors whose prototype chain reaches an abstract constructor. Reading `(new A)->p` follows the same rule only from PHP 8.4: 7.4 to 8.3 check the redeclaring class and fatal, so a project whose declared PHP range ends below 8.4 keeps the finding, and an undeclared or straddling range drops it. A private declaration higher up is a different member and still ends the lookup, a member declared only on `A` still reports, and so does a protected member whose root class the site is unrelated to. `class-const.inaccessible` is unchanged: every PHP version from 7.4 to 8.5 refuses a redeclared protected constant fetched from a sibling class. Findings only disappear.
