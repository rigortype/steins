- **`call.inaccessible-method` and `property.inaccessible` no longer report a protected member that a subclass redeclares when the site's class shares the member's root with it.** With `Base { protected function h() }`, `A extends Base` redeclaring `h()`, and `B extends Base` calling `(new A)->h()` or reading `(new A)->p`, PHP allows the access because it checks the class that first introduced the member, and Steins checked `A`. This applies to methods, `static` methods and abstract roots. A private declaration higher up is a different member and still ends the lookup, a member declared only on `A` still reports, and so does a protected member whose root class the site is unrelated to. `class-const.inaccessible` is unchanged: PHP 8.4 and 8.5 refuse a redeclared protected constant fetched from a sibling class. Findings only disappear.
