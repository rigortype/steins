- **A branch entered through `||`, or left through `&&`, now narrows to the join of the paths PHP takes through the condition, so `if (is_int($n) || is_float($n)) { return number_format($n); }` over `int|float|string` no longer reports `type.maybe-argument-mismatch`.** The `if`, `elseif` and `while` sides, the right operand of `&&` and `||`, a ternary's arms and `assert()` all apply the same rule: `a || b` holds along `a` or along `!a && b`, and `a && b` fails along `!a` or along `a && !b`, so `if (!is_int($n) && !is_float($n)) { return; }` narrows the code after it too, and `$s === null || $s === ''` dumps `''|null`. Findings can disappear where every path of such a guard excludes the arm that reported; a guard that leaves the arm live on one path (`is_int($n) || is_string($n)`) keeps reporting.
  - **A condition of more than eight paths narrows as before and says so.** Past the cap the `||` or `&&` that overflows contributes nothing, as it did before this change, and a dump of a variable it reads ends in `(paths capped)`.
