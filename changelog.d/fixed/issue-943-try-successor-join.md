- **The code after a `try` now knows what every way of completing the statement agrees on.** Steins used to forget every variable a `try` statement assigned or used, so after `try { $x = 1; } catch (E $e) { $x = 2; }` the value of `$x` was unknown, and an object that was only used inside the statement lost its class. The code after the statement now sees the merge of the `try` block's end and the ends of the `catch` blocks that complete normally. When there is a `finally` block, that merge then runs through it. `$x` above is `1|2`. A `catch` that returns adds nothing to the merge. A variable that only the `try` block assigns stays unknown, because the `catch` path skipped the assignment, and `variable.maybe-undefined` still reports reading it at `strict`. A `try` statement that contains a `goto` or a label keeps the old behaviour.
  - **Findings can appear:** any finding that depends on a value or a class known after a `try` statement. On the ten public corpus packages at `strict`: 1 `phpdoc.param-mismatch`, nothing at `default`.
  - **Findings can disappear:** a finding that fired because Steins knew too little about a value after a `try` statement. None moved on the public corpus. The `transform` dry-runs plan the same edits, and `effect-diff` reports no event.
