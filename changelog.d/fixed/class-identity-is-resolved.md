- **A class and the other name it goes by are now one class to every type, return and `catch` check, so passing `new Real()` to a parameter typed with an alias of `Real` (or the reverse) is no longer reported as a proven `TypeError`.** A literal `class_alias()` already made the alias resolve for existence, but the acceptance checks compared the two spellings and proved a mismatch. Chained aliases (`class_alias('A1', 'A2')` after `class_alias(Real::class, 'A1')`) now resolve in whatever order the calls are written, and `::class`, string, `__NAMESPACE__`, interface, enum and parent-class aliases all behave the same. Findings can only disappear: `type.argument-mismatch`, `type.return-mismatch` and the other class-vs-class proofs lose the alias false positives, and a mismatch between two unrelated classes still reports.
  - **`Dom\DOMException` is the same class as `DOMException`,** as php-src's stub says and PHP does, so `takes(\Dom\DOMException $e)` accepts `new \DOMException`, and `catch (\Dom\DOMException)` catches a thrown `\DOMException` (and the converse), which removes the matching `type.argument-mismatch` and `throw.undeclared` false positives, with and without `--no-php`. The catalog reads it from the stub's class-level `@alias`.
  - **A target class that names nothing Steins can see now declines instead of proving a mismatch while a dynamic `class_alias($a, $b)` (or an `eval`, or an include it cannot follow) stands in the project,** since the runtime-minted class might be that name. A mismatch between two classes Steins can see still reports.
