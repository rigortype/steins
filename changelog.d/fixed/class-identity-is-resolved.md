- **A class and the other name it goes by are now one class to every type, return and `catch` check, so passing `new Real()` to a parameter typed with an alias of `Real` (or the reverse) is no longer reported as a proven `TypeError`.** A literal `class_alias()` already made the alias resolve for existence, but the acceptance checks compared the two spellings and proved a mismatch. The alias false positives in `type.argument-mismatch`, `type.return-mismatch` and `throw.undeclared` disappear, and a mismatch between two unrelated classes still reports. Chained aliases (`class_alias('A1', 'A2')` after `class_alias(Real::class, 'A1')`) resolve whatever order the calls are written in, and `::class`, string, `__NAMESPACE__`, interface, enum and parent-class aliases all behave the same.
  - **A receiver typed with a chained alias now resolves to its class,** so a member-absence finding on it (`call.undefined-method` and the like) can appear where the receiver used to be unresolved and silent. A name that two `class_alias` routes bind to different classes, or that is also a plain declaration (PHP-Parser's `class_alias(NewItem::class, OldItem::class)` next to `if (false) { class OldItem extends NewItem {} }`), is ambiguous and stays silent when the other class is one the check enumerated.
  - **`Dom\DOMException` is the same class as `DOMException`,** as php-src's stub says and PHP does, so `takes(\Dom\DOMException $e)` accepts `new \DOMException`, and `catch (\Dom\DOMException)` catches a thrown `\DOMException` (and the converse), which removes the matching `type.argument-mismatch` and `throw.undeclared` false positives, with and without `--no-php`. The catalog reads it from the stub's class-level `@alias`. A `class_alias()` whose new name is an engine class (`Stringable`, `Dom\DOMException`) mints nothing, as in PHP, so a guarded polyfill no longer shadows the engine's name.
  - **A target class that names nothing Steins can see now declines instead of proving a mismatch while a dynamic `class_alias($a, $b)` (or an `eval`, or an include it cannot follow) stands in the project,** since the runtime-minted class might be that name. A mismatch between two classes Steins can see still reports. One true positive is lost to this under a dammed project: monolog's `MongoDBHandlerTest` passes `new \stdClass` to a `MongoDB\Client|Manager` parameter on purpose (#972). The throw lane's catch absorption does not decline under a dam yet (#970).
