- **A `&&`/`||` or ternary used as a value (`$r = $n !== null && method_exists($n, 'gone') && f();`, `return … ? f() : 0;`, a call argument) is now judged as the condition an `if` would make of it, so findings inside the operand or arm it never evaluates disappear, and findings can appear where the value is now proven.** The left operand now narrows the right one, a `method_exists`/`function_exists`/`class_exists` guard in either folds against the project, and the operand a decided guard skips is marked unevaluated before the statement's calls are judged. Findings disappear only inside code PHP provably never runs (for example `call.undefined-function` on `f()` above); the same expression under `if` was already silent, and an operand that can run (an undecided or true-left `&&`, a `||` over a possibly-null left) still reports. A decided connective is now a proven `true` or `false` rather than `bool`, so passing or returning it where the other boolean is declared reports `type.argument-mismatch` or `type.return-mismatch` (a TypeError in PHP). `xor`, `echo` values, and a value statement that rebinds a name the condition reads keep their previous behaviour.
