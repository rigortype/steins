- **Passing `null`, an array or a closure where PHP's native type cannot take it is now reported as a proven `TypeError`: `tk(null)` for `K $k`, `ti([])` for `int $i`, `return null;` or `return fn () => 1;` from `: K`, `return [];` from `: int`, `$p->k = null` and `$p->a = new B()` on typed properties, and `foo(42)` or `foo("trime")` for `callable $c` (#951, #941, #952).** Steins stayed silent on all of them on purpose; each is a `TypeError` in both modes on PHP 8.5. **Findings can appear** under `type.argument-mismatch`, `type.return-mismatch` and `type.property-mismatch`; on the ten public corpora exactly one does, PHPUnit's deliberate TypeError fixture.
  - A parameter typed `array`, `object`, `iterable` or `callable` (or one of them with `null`) is now judged: a scalar or `null` against any of them, an array against `object`, a closure against `array` or `iterable`, and an object that is not `Traversable` against `iterable`. A union of one of them with anything else (`array|string`) is still not judged.
  - A `callable` string or `[class, method]` pair is reported only when Steins can prove nothing by that name exists, exactly as `call.undefined-function` and `call.undefined-method` would, so `--no-php` and a project with conditional declarations stay silent. Names on built-in classes (`["stdClass", "nope"]`) are not judged, and neither is a name passed through a variable.
  - `null` to a builtin's `object`, `array`, `callable` or class-typed parameter (`spl_object_id(null)`, `iterator_to_array(null)`) is reported in coercive files too: PHP's deprecation for `null` covers scalar parameters only.
  - **Findings can disappear** where the walk proved a value but could not decide the type test guarding the call: `if (isset($x))`, `is_countable($x)`, `is_a($x, …)`, `get_debug_type($x) === …` and the like over a known `$x` no longer report on `$x` inside the branch, a literal `is_callable('f')` guard now covers `call.undefined-function` as `function_exists('f')` does, and a typed property write that can land elsewhere (another class's private property, a class with `__set`, or one whose ancestors Steins cannot see) is no longer reported.
  - A parameter with a `= null` default, a nullable type, `mixed`, `self`/`static`/`parent`, a by-reference or variadic parameter, and the possibly-grade findings (`type.maybe-argument-mismatch`) behave as before.
