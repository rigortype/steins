- **A body that hands an object to a `string` parameter, returns one through a `string` return type, or stores one into a typed property in a constructor is no longer read as running none of your code, in a file without `declare(strict_types=1)`.** Without strict typing PHP converts such an object through `__toString` at the boundary, and the analysis read every one of these as complete: `takes(new S)` with `function takes(string $s)`, `return new S;` under `: string` or `: ?string` (and under `__toString()`'s implicit `: string`), `$this->name = $s;` in a constructor over `public string $name` (also as a destructuring or `foreach` target, a reference assignment or a chain), a default `function d(string $s = new S)`, and a callback: `$f = takes(...); $f(new S)`, `call_user_func('takes', new S)` and, converting in coercive mode even under `strict_types=1`, `array_map('takes', $objects)`, `array_filter`, `usort` and `array_walk`. An exact class with `__toString` is now an edge to it, so its effects and throws reach the caller (`io.output.buffer` for an `echo` in it); an exact class with none runs nothing (PHP raises `TypeError`); a class a subclass may extend, or an operand nothing shows (an untyped parameter, an array element, a local assigned from a call, a method call on a receiver the scan cannot name), is `operator-to-string` in both lanes, as in a concatenation. The governing file is the one whose code PHP is running: the calling file for a parameter (a coercive caller into a strict callee converts, a strict caller into a coercive callee raises), the declaring file for a return and a default, the writing file for a property. A type converts when it has a `string` member and none of `object`, `mixed` or `Stringable` (`string|array`, `string|iterable` and `string|callable` convert too), an object that is a member of the type (`string|Foo` with a `Foo`, `self|string` with an instance of the class, `string|callable` with an invokable one) is taken as it is, a generator's `return` converts nothing, and a `strict_types=1` file has no such site apart from the callbacks. Four operand readings also recover gaps master had at concatenations and calls: `Foo::class`, a class constant or enum case (an enum cannot declare `__toString`), a scalar global constant such as `PHP_EOL`, and a `match` whose every arm holds no object are no longer an operand that may be an object (a class constant only where its initializer, and every constant it names, ends in a scalar or an enum case: `const X = GO;` over `const GO = new S;` converts, and so does a project constant where the project holds a `define()` with a computed name; a global constant that may hold an object stays unproven), and `getMessage()` is a string again (it converts inside the accessor), so `return $e->getMessage();` under `: string` is complete. Functions in coercive files can read `…?` where they read complete, others can become complete, `effects-envelope` can plan fewer or more tags, and `throw.maybe-undeclared` appears at `strict` on more sites and disappears on others. On the ten public corpus packages (28,847 functions, 7 of them strict nearly throughout) 228 functions gain `operator-to-string` in both lanes (54 through a callback) and 325 lose it (the constant, `::class`, `match` and `getMessage()` readings), 57 lose `user-code-reach`, 9 lose effect exhaustiveness and 15 the throw lane's, 45 become exhaustive in a lane, `effect-diff` reports 25 `coverage-completed` and 9 `coverage-narrowed` events, `transform effects-envelope` plans 734 edits for 726 (+11, -3 `@phpstan-all-methods-pure` on console's `Tester/Constraint` classes), `throws-envelope` and `loop-to-array-map` are unchanged, and `throw.maybe-undeclared` at `strict` gains 67 findings and loses 50 (composer +9 net, console +19, process +9, phpunit -13, monolog -3, guzzle -4). A property write outside a constructor, a call through a declared receiver or an interface envelope, and a method callback (`'Foo::m'`, `[$o, 'm']`) are not read.
