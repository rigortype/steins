- **A body that hands an object to a `string` parameter, returns one through a `string` return type, or stores one into a typed property in a constructor is no longer read as running none of your code, in a file without `declare(strict_types=1)`.** Without strict typing PHP converts such an object through `__toString` at the boundary, and the analysis read every one of these as complete: `takes(new S)` with `function takes(string $s)`, `return new S;` under `: string` or `: ?string`, and `$this->name = $s;` in a constructor over `public string $name`. An exact class with `__toString` is now an edge to it, so its effects and throws reach the caller (`io.output.buffer` for an `echo` in it); an exact class with none runs nothing (PHP raises `TypeError`); a class a subclass may extend, or an operand nothing shows (an untyped parameter, an array element, a local assigned from a call, a method call on a receiver the scan cannot name), is `operator-to-string` in both lanes, as in a concatenation. The governing file is the one whose code PHP is running: the calling file for a parameter (a coercive caller into a strict callee converts, a strict caller into a coercive callee raises), the declaring file for a return, the writing file for a property. A type converts when it has a `string` member and none of `object`, `mixed` or `Stringable` (`string|array`, `string|iterable` and `string|callable` convert too), an object that is a member of the type (`string|Foo` with a `Foo`, `self|string` with an instance of the class, `string|callable` with an invokable one) is taken as it is, and a `strict_types=1` file has no such site. A `match` whose every arm holds no object (the usual `: ?string` return) and a `throw` expression no longer leave a concatenation, a call or a return unbounded. Functions in coercive files can read `…?` where they read complete, `effects-envelope` can plan fewer tags, and `throw.maybe-undeclared` appears at `strict` on more sites. On the ten public corpus packages (28,847 functions, 7 of them strict nearly throughout) 175 functions gain `operator-to-string` in both lanes (symfony/console 134, thephpleague/flysystem 23, symfony/process 14, Carbon 4) and one loses it (a `match` of literals under a concatenation), no function gains exhaustiveness, `effect-diff` reports 8 `coverage-narrowed` events, `transform effects-envelope` plans 3 fewer edits (726 to 723, `@phpstan-all-methods-pure` on console's `Tester/Constraint` classes), `throws-envelope` and `loop-to-array-map` are unchanged, and `throw.maybe-undeclared` at `strict` gains 48 findings (composer 17, all in a vendored `symfony/filesystem` copy under its test fixtures, console 22, process 9) and loses 1. A property write outside a constructor, a call through a declared receiver or an interface envelope, and a class constant or enum case as the operand are not read.
