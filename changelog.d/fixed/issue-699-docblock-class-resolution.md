- **A class a docblock names inside another type, or writes fully qualified, now resolves to the class it names.** In `namespace App`, `@param list<User>|false $l` read the element as the global `User` rather than `App\User`, and so did a map's key and value, a shape field and a callable signature; and `@param \Foo|false $ff` read `\Foo` as `App\Foo`, because the leading `\` was dropped before the name was resolved. The second one could report a finding on the wrong class: with only `App\Foo` declared, `$ff->nope()` reported `phpdoc.undefined-method` for `App\Foo::nope()`, and that finding is now gone. **Findings can appear or disappear** where a docblock names a class this way, since the declared-receiver checks and the `foreach` element read the right class now. `\PHPStan\dumpType()` output changes for such parameters (`false|list<App\User>`, and a nested class is printed in its declared casing), and a class named by a type alias imported from another namespace (`@phpstan-import-type`) no longer reads with the importer's namespace prefixed onto it (`App\Vendor\Row` for `Vendor\Row`).
