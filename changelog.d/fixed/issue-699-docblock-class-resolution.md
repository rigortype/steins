- **A class a docblock names inside another type, or writes fully qualified, now resolves to the class it names.** In `namespace App`, `@param list<User>|false $l` read the element as the global `User` rather than `App\User`, and so did a map's key and value, a shape field and a callable signature; and `@param \Foo|false $ff` read `\Foo` as `App\Foo`, because the leading `\` was dropped before the name was resolved. The second one could report a finding on the wrong class: with only `App\Foo` declared, `$ff->nope()` reported `phpdoc.undefined-method` for `App\Foo::nope()`, and that finding is now gone. **Findings can appear or disappear** where a docblock names a class this way, since the declared-receiver checks and the `foreach` element read the right class now. `\PHPStan\dumpType()` output changes for such parameters (`false|list<App\User>`, and a nested class is printed in its declared casing).
  - The same holds for names that travel from one namespace to another: a class named by a type alias imported with `@phpstan-import-type` no longer reads with the importer's namespace prefixed onto it (`App\Vendor\Row` for `Vendor\Row`), and neither does the class a `template-type<…>` reads off another namespace's `@extends` (`Other\App\User` for `App\User`).
  - `@phpstan-assert \Foo` and `@phpstan-assert !\Foo` in a namespace now narrow by the global `Foo` rather than by the namespace's own `Foo`, so the arms they keep or remove change, and so can what is reported on the variable afterwards.
