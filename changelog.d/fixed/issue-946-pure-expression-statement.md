- **A statement that only evaluates a pure expression, and a `match` arm that is a literal or a variable, no longer make Steins forget every local.** `$s = "a"; $v = match ($i) { 1 => 10, default => 20 }; return $s;` in a function declared `: int` threw a `TypeError` at run time but reported nothing, and a `dumpType($s)` after the `match` printed `unknown`; the same went for `1;`, `$i;`, `$i + 1;` and `1 === 2;` as statements. An expression that calls nothing, writes nothing, prints nothing and cannot run a `__toString`, `__get`, `offsetGet` or autoloader now leaves the known values alone. A fetch of a property, array element, static member or constant, a `.` or loose comparison over a variable, `@`, `++` and `clone` still forget them, as before.
  - **Findings can appear:** every walked finding on a local that is read after a literal-armed `match` or a pure expression statement, such as `type.return-mismatch`, `call.on-null` and `call.undefined-method`, and `type.invalid-operand` on a pure operator expression used as a statement (`[] + 1;`).
  - **Findings can disappear:** a finding that relied on the lost values being unknown, such as a `*.maybe-*` verdict, now judges the known value.
