- **A statement that only evaluates a literal, and a `match` arm that is a literal, no longer make Steins forget every local.** `$s = "a"; $v = match ($i) { 1 => 10, default => 20 }; return $s;` in a function declared `: int` threw a `TypeError` at run time but reported nothing, and a `dumpType($s)` after the `match` printed `unknown`; the same went for `1;`, `$i;` and `[1, 2];` as statements. Only an expression that can neither raise a diagnostic nor throw counts, because a warning or deprecation reaches `set_error_handler` and a throw leaves the scope: arithmetic, casts, `.`, comparisons, fetches and any read of a variable inside a larger expression still forget them, as before.
  - **Findings can appear:** every walked finding on a local that is read after a literal-armed `match` or a literal expression statement, such as `type.return-mismatch`, `call.on-null` and `call.undefined-method`.
  - **Findings can disappear:** a finding that relied on the lost values being unknown, such as a `*.maybe-*` verdict, now judges the known value.
