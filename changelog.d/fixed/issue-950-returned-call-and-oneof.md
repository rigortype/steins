- **A returned call and a value that is one of several literals are now judged like the variable that would hold them: `function g(): int { return s(1); }` with `s(): string` reports `type.return-mismatch`, and `$b = $r ? null : 1; ti($b);` or `return $b;` into `int` reports (#950).** Steins stayed silent on both although each is a `TypeError` on PHP 8.5. **Findings can appear** under `type.return-mismatch`, `type.argument-mismatch`, `type.maybe-return-mismatch` and `type.maybe-argument-mismatch`.
  - `return f(args)`, `return $o->m(args)`, `return K::m(args)` and `return strtoupper("x")` are judged exactly as `$v = f(args); return $v;` is, with the same return summary and the same declared floor.
  - A value that is one of several known literals is judged member by member in the file's own mode: every member refused is a definite finding, since every path throws, some refused is the possibly grade (`type.maybe-*`, strict profile), none refused is silent. A `null` member is admitted by a `?T` type, a `= null` default, and a builtin's scalar parameter in a coercive file.
  - **Findings can change shape**: an argument that is a call whose proven summary is such a set now names the summary (`one of false, "value"`) where it used to name the declared type, and two differing bad literals joined by an `if`, a ternary or a `match` now report where they were silent.
