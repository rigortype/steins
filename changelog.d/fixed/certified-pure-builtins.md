- **The `is_*` type predicates, `get_debug_type()` and the array readers (`array_values()`, `array_keys()` with one argument, `array_key_exists()`, `array_slice()`, `array_flip()`, `array_reverse()`, `array_is_list()`, `array_first()`, `array_last()`, `array_key_first()`, `array_key_last()`, `key_exists()`) are now catalogued pure, so a body that calls them is no longer `…?` for that call.** Before, a builtin counted as pure only if Steins could also execute it while folding constants, so `function f($c) { return is_int($c); }` was `…?`. On the ten public corpora 305 bodies become exhaustive and none stops being exhaustive, and `steins transform effects-envelope` writes 79 more tags. 50 of them are in PHPUnit, where the exceptions built on its base exception, whose constructor calls `is_int()` and `array_keys()`, can now take `@phpstan-all-methods-pure`. Each name is certified from php-src: it runs no user code for any argument its types accept, takes no reference, and reads nothing but its arguments.
  - `array_keys($a, $value)` still marks the caller `…?`, because comparing an object with a string runs its `__toString()`, and so do `current()`, `key()`, `get_class()`, `array_search()` and the string functions.
  - **Findings can appear:** `statement.no-effect` can now report a discarded call with literal arguments such as `is_int(1);` or `array_values([1, 2]);`. It is never reported for `array_flip()`, `array_key_exists()` or `key_exists()`, which can warn or deprecate on a literal. A pure row adds no label, so `effect.envelope-exceeded` cannot newly fire through one.
  - `function_exists()` on one of these names now folds to true under `--no-php` too, and a call to a project's own global polyfill of one of them is `…?`, because the polyfill and the builtin share the name.
