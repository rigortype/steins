- **`isset($v)` now proves `$v` is not null inside the guarded branch, and a guard proving an array is not empty (`$a !== []`, `$a != []`, `if ($a)`, or the else side of `$a === []` / `$a == []`) proves the one optional key of a sealed shape such as `array{0?: int}` present, so the strict-profile `type.maybe-return-mismatch`, `offset.maybe-missing` and kindred possibly-grade findings these guards already ruled out no longer fire.** `isset($v)` narrows exactly as `$v !== null` does on its true side and nothing on its false side; `$a != []` also drops `null`, since `null == []` is true. A shape with two optional keys or an open tail (`array{0?: int, ...}`) is not promoted, so reads there keep reporting. Findings can also appear on the strict profile: a nullable array shape past a null check (`if ($a === null) { return; }`) now loses its null arm, so an unguarded read of one of its optional keys reports `offset.maybe-missing` as the same read on the non-nullable shape already did.
