- **A write through `$GLOBALS['name']` is now a write of the variable `name`, and a write through `$GLOBALS[$key]` makes the scope unanalyzable.** Steins recorded `$go = true; while ($go) { $GLOBALS['go'] = false; }` as a write of `GLOBALS`, so it kept `$go = true`, read the loop header as always true, and treated the code after the loop as unreachable although PHP runs it; `$x = null; $x->bar();` after such a loop reported nothing. The same went for `unset($GLOBALS['go'])`, `$GLOBALS['go'] .= …`, `$GLOBALS['go'][] = …`, `++$GLOBALS['go']`, a destructuring or `foreach` target `$GLOBALS['go']`, and a by-reference argument `sort($GLOBALS['go'])`. A literal key now counts at file scope; inside a function body `$GLOBALS['go']` is the global, which no local aliases (apart from `global $go`, a reference or a by-reference `use`, which already make the scope unanalyzable), so it writes nothing local. A key that is not a literal poisons the scope the way `extract()` and `$$name` do, except as a call argument inside a function, where it cannot reach a local. Reading the `do`-`while` header afterwards is a separate follow-up.
  - **Findings can appear:** `call.on-null` and the other walked findings on code after a loop whose body writes a variable through a literal `$GLOBALS` key, which were lost to the unreachable-successor reading.
  - **Findings can disappear:** every walked finding in a scope that writes through `$GLOBALS[$key]` with a key that is not a literal, or, at file scope, hands such an element to a call (`f($GLOBALS[$key])`), the same silence as after `extract()`.
