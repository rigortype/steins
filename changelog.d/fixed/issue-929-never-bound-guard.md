- **`variable.undefined` no longer reports a read that an `isset()` or `empty()` guard on the same never-bound name keeps from running, wherever the guard is written.** A guard on a name nothing in the function binds is constant (`isset` is false, `empty` is true), so these reads are dead code and PHP runs them without the warning, yet `!isset($x) || print($x)`, `isset($x) && $x > 1`, `if (!isset($x)) { return; } print($x);` and `if (isset($x) || isset($y)) { echo $x; }` each reported "Undefined variable $x". A guard now covers a read on the side where it proves the name bound: the right operand of `&&` and `and` takes what the left operand proves when true, and of `||` and `or` what it proves when false; the body of an `if` or `?:` takes what its condition proves when true, and the `else` side what it proves when false; and an `if` with no `else` whose body returns, throws, exits, breaks or continues covers the statements after it in the same block by what its condition proves when false. A condition that is true or false in more than one way (a disjunction when true, a conjunction when false) covers a read only while every name any of its operands tests is never bound.
  - **Findings only disappear.** On the public corpora `variable.undefined` stays at 1 and, under `--profile strict`, `variable.maybe-undefined` at 20, with `check` output unchanged byte for byte under both `default` and `strict`.
  - **What still reports**, because it warns in PHP: `isset($x) || print($x)`, `!isset($x) && print($x)`, `if (isset($x)) { return 1; } return $x;`, `if (!isset($x) && $c) { return; } print($x);`, `if (isset($x)) {} echo $x;`, `isset($x) || $y > 0` and `isset($x) || isset($y)` with a `$y` the function binds somewhere, and a read in a block the guard does not precede.
