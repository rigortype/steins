- **`variable.undefined` no longer reports a read that an `isset()` or `empty()` guard on the same never-bound name keeps from running, whichever way the guard is written.** A guard on a name nothing in the function binds is constant (`isset` is false, `empty` is true), so these reads are dead code and PHP runs them without the warning, yet `!isset($x) || print($x)`, `isset($x) && $x > 1`, `if (!isset($x)) { return; } print($x);` and `if (isset($x) || isset($y)) { echo $x; }` each reported "Undefined variable $x". The right operand of `&&`, `and`, `||` and `or` is now covered by the names its left operand tests; a condition that is a conjunction covers its body and arms by the names it tests; a disjunction covers them only while every name any disjunct tests is never bound; and an `if` with no `else` whose body returns, throws, exits, breaks or continues covers the statements after it in the same block.
  - **Findings only disappear.** On the public corpora `variable.undefined` stays at 1 and, under `--profile strict`, `variable.maybe-undefined` at 20, with `check` output unchanged byte for byte under both `default` and `strict`.
  - **What still reports:** `isset($x) || $y > 0` and `isset($x) || isset($y)` with a `$y` the function binds somewhere, `if (isset($x)) {} echo $x;`, and a read in a block the guard does not precede. The cover goes by the names a guard tests at either polarity, as the `if` and `?:` guards already did, so `isset($x) || print($x)` and `if (isset($x)) { return; } echo $x;`, which do warn in PHP, are silent too.
