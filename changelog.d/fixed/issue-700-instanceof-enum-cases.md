- **An `instanceof` guard over an enum-typed parameter no longer empties it.** `function f(Suit $s) { if ($s instanceof Suit) { … } }` read `$s` as `*NEVER*` inside the branch, and so did `Suit|string|null`, `Suit|int` and `instanceof \UnitEnum`, because each of the enum's cases was judged as if it were not an object. A case is now judged by its enum: it is an instance of the enum, of `UnitEnum`, of `BackedEnum` when the enum is backed and of the interfaces the enum declares, so the guard keeps every case, and `!($s instanceof Suit)` now removes them (`Suit|string` reads `string` there). `\PHPStan\dumpType()` output changes inside such branches.
  - **Findings can appear:** a `default`-less `match` inside or after an `instanceof` guard that misses a case now reports `throw.undeclared` for its `UnhandledMatchError` (`if ($s instanceof Suit) { return match ($s) { Suit::Hearts => 1, Suit::Spades => 2 }; }`), where the emptied branch kept it silent.
  - **Findings can disappear:** a `default`-less `match` with an arm Steins cannot subtract, such as a variable or a class constant holding a case, no longer reports a missing case because an earlier guard narrowed the subject (`if ($s === null) { return 0; }` before `match ($s) { Suit::Hearts => 1, Suit::Spades => 2, $clubs => 3 }` reported a false `UnhandledMatchError` escape).
