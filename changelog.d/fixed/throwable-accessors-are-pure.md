- **The engine exception accessors (`getMessage()`, `getCode()`, `getFile()`, `getLine()`, `getPrevious()`, `getTrace()`, `getTraceAsString()`) are now catalogued pure, also when called through a project exception, so a body that calls one is no longer `…?` for that call.** They are `final` on `Exception` and `Error`, so `$this->getTrace()` in a project exception's constructor, and `$e->getMessage()` on a parameter or property declared as an exception class, run the engine's code whatever subclass the object is. An exception whose constructor forwards to the engine's and keeps `$this->getTrace()` is exhaustive, and so is every `throw new` of it; `steins transform effects-envelope` can write `@phpstan-all-methods-pure` over exception classes whose methods only read the accessors. `__toString()` is not final and still marks the caller `…?`, and so does `$e->getMessage()` on a `catch` variable.
  - A call that names its class exactly (`parent::query()`, `(new MyPdo())->query()`) now reaches the engine method's catalog row through a project subclass that does not override it, so `effect.envelope-exceeded` can fire where the caller used to be `…?` and silent: `parent::query()` in a `PDO` subclass is `io.db`. `$this->query()` there still marks the caller `…?`, because a subclass may override `query()`.
