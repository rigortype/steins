- **`new C(...)` now carries `C`'s constructor throws to the function that instantiates it, so `throw.undeclared` can fire where it used to stay silent.** A function declaring `@throws` that returns `new Port(-1)`, whose constructor throws a checked exception, was judged clean; it now reports the escape, and `annotate` shows the class on the caller. A `catch` around the `new` dams the constructor's throws like any call's, an inherited constructor counts, a class with no constructor contributes nothing, and `throw new X(...)` adds whatever `X`'s constructor throws to `X` itself. A class Steins cannot resolve (`new $class()`, a class no analyzed file declares, a trait-using class, `new static` in a non-final class, an anonymous class with a constructor) marks the caller's throws `…?` where they used to read as complete.
  - Engine classes answer from a new catalog of constructor throws. `new PDO(...)` throws `PDOException`, which Steins now knows is a `RuntimeException`: it counts as checked, so a `PDOException` escaping a `@throws` that does not cover it can be reported, including one thrown explicitly, and a `catch (RuntimeException)` provably absorbs it. Every engine exception constructs without throwing, so a project exception forwarding to `parent::__construct(...)` stays complete. `new DateTime(...)`, `new DateTimeImmutable(...)` and `new DateInterval(...)` throw only for an argument that does not parse, and a different class from PHP 8.3 on, so they mark the caller `…?` instead of reporting a guess; any other uncatalogued engine class does the same.
  - `steins transform throws-envelope` can write the classes a constructor throws into the caller's `@throws`.
