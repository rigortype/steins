- **`new C(...)` now carries `C`'s constructor effects to the function that instantiates it, so `effect.envelope-exceeded` can fire where it used to stay silent.** A `@pure` or `#[\Steins\Pure]` function returning `new Clock()` whose constructor calls `time()` was judged pure; it now reports `nondet.time` at the `new`, and `annotate` shows the label on the caller. An inherited constructor counts, and a class with no constructor contributes nothing. A class Steins cannot resolve (`new $class()`, a class no analyzed file declares, a trait-using class, `new static` in a non-final class, an anonymous class with a constructor) marks the caller `…?` and reports nothing, where it used to read as proven pure.
  - Engine classes answer from the catalog: every engine exception and `Error` constructs purely (so `throw new InvalidArgumentException(...)`, and a project exception forwarding to `parent::__construct(...)`, stays exhaustive), `new DateTime()`/`new DateTimeImmutable()` is `nondet.time` like `date()`, `new PDO(...)` is `io.db`, and the SPL containers, `ArrayObject`, `WeakMap`, `DateInterval` and `stdClass` are pure. Any other engine class marks the caller `…?`.
  - `steins transform effects-envelope` writes fewer tags over bodies that instantiate an unresolvable class, and now writes `@phpstan-all-methods-pure` over exception classes whose constructor only forwards to the engine's.
