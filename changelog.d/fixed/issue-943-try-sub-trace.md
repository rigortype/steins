- **Code inside `try`, `catch` and `finally` blocks is now analyzed, and code after a `try` that always returns, throws or exits is treated as unreachable.** Steins used to skip everything inside a `try` statement and always assumed the code after it could run, so `$x = null; try { return; } finally { echo 1; } $x->bar();` reported `call.on-null` on a line PHP never reaches, a `do`-`while` around `try { return 1; } finally { … }` was reported by `type.return-maybe-missing`, and no finding that needs the function to be walked (`call.on-null`, `call.undefined-method`, argument and return checks, `PHPStan\dumpType`) fired inside the statement. The `try` block is now walked like the code around it. A `catch` is walked from what Steins still knows when an exception can arrive, with the caught variable typed as the caught class (when every caught class is a `Throwable`). A `finally` is walked the same way. A `try` ends the code after it when its `finally` always returns or throws, or when the block and every `catch` that can run do; a `catch` of a block in which nothing can throw (only plain assignments of literals or variables and a `return` of a literal) never runs. What the statement leaves behind for the code after it is unchanged, so a value assigned inside a `try` is still unknown after it.
  - **Findings can appear:** every finding Steins computes while walking a function, on code inside a `try`, `catch` or `finally` block; and `type.return-missing` on a function that ends in a `try` that can fall through (`try { $x = 1; } finally { $y = 2; }` in an `: int` function, which PHP rejects with "none returned"). A finding inside a `try` block is reported even when a `catch` would handle the error it predicts. On the ten public corpus packages at `strict`: 3 `phpdoc.maybe-argument-mismatch` and 1 `phpdoc.param-mismatch`, nothing at `default`.
  - **Findings can disappear:** `call.on-null` and the other walked findings on code after a `try` that always returns, throws or exits; `type.return-missing`, `type.return-maybe-missing` and `variable.maybe-undefined` where such a `try` ends a function, a loop body or an `if` arm. On the ten public corpus packages: 2 `variable.maybe-undefined` at `strict`.
  - `transform phpdoc-honesty` keeps refusing a function whose body holds a `try`, because a `finally` that returns replaces the return values inside the block. The `transform` dry-runs plan the same edits on the public corpus, and `effect-diff` reports no event.
