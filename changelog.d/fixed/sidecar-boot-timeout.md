- **A slow-booting PHP no longer degrades the run or withholds the generation.** The PHP sidecar charged its 2-second per-request budget from the moment a request was written, so on a loaded machine (a busy CI runner) a freshly started `php` that took longer than that to boot lost its first answer, was replaced up to three times, and the run announced a degraded sidecar on stderr, omitted the findings that need PHP, and published no generation, leaving every later run cold. A new `php` child now has to answer an `env` handshake under its own 20-second boot timeout before any request is sent; real requests keep the 2-second budget, so hang detection is unchanged. A `php` that starts but never completes the handshake turns the sidecar off for the run, prints the degraded notice (not the `no PHP sidecar` one), and publishes no generation, as a sidecar that stopped answering already did; on a revive it counts as one respawn strike. `STEINS_SIDECAR_BOOT_TIMEOUT_MS` changes the 20-second budget. Findings do not change on a machine where `php` boots in time.
