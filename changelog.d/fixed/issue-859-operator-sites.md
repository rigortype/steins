- **An operator that can run your code through an operand's class is no longer pure and throwless by default.** `'a' . $o`, `"a{$o}"`, `(string) $o`, `echo $o`, `$o == 'x'`, `$o->p`, `$o->p = 1`, `isset($o->p)`, `$o['k']`, `foreach ($o as …)`, `yield from $o`, `...$o`, `clone $o` and `clone($o, […])` now resolve against the operand's class in both the effect lane and the throw lane. When the class is exact (a `new Foo`, `$this` in a final class, a declared final class) the site draws an edge to the user method the engine runs (`__toString`, `__get`/`__set`/`__isset`/`__unset`, the `ArrayAccess` `offset*` methods, the `Iterator` methods or an `IteratorAggregate`'s `getIterator`, `__clone`, `__set` for clone-with), so that method's effects and throws reach the caller; an exact class proven not to have the method runs nothing; and a class a subclass may extend (`$this` in a non-final class, an interface, a non-final class), an operand nothing is known of and a hooked property are a coverage gap, so the body reads `…?` and its throw set is not exhaustive. A property declared on a non-final class and visible at the access stays covered unless that class's chain, or some subclass in the project, declares a property magic method or a hook, or the chain leaves the project. A method missing from an exact class that declares `__call` or `__callStatic` is now an edge to it instead of `method-not-found`. Five gap kinds are new in `annotate --format json` and the effect baseline: `operator-to-string`, `operator-magic-property`, `operator-array-access`, `operator-iteration` and `operator-clone`. Findings can appear where a `__toString` or magic method with effects is now reached, and functions that read `…?` can lose their `effects-envelope` and `loop-to-array-map` rewrites; destructors and the engine's own `Error` raises at operators are not modelled.
