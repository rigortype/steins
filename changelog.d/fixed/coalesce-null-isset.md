- **`($a['k'] ?? null) !== null` now narrows the way `isset($a['k'])` does.** Comparing a null-defaulted coalesce with `null`, in either operand order and with either `===` or `!==`, lowers to `isset`, so an optional key read after the guard is no longer reported as possibly missing and a null-stripped slot is no longer left nullable; a default other than `null` still proves nothing. Findings can appear as well as disappear.
  - A key read in the branch where the coalesce is null (`=== null` body, or after an early return on `!== null`) changes id from `offset.maybe-missing` to `offset.undeclared`, as `!isset($a['k'])` already does.
  - A bare variable with a proven value is now decided as `isset($v)` is, so the branch PHP enters is analysed: `$v = "abc"; if (($v ?? null) !== null) { return $v + 1; }` now reports `type.invalid-operand`, as the `isset($v)` spelling already did.
