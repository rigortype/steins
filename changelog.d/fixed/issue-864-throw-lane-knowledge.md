- **The throw lane no longer reads a builtin it has no throw row for as throwless.** `strlen($o)` converts `$o` through `__toString`, which can throw, yet its throw set read as empty and exhaustive; now a call is throw-exhaustive only where the catalog has a throw row or an audited "raises nothing" entry for the name, and the arguments cannot reach user code (the call-site rule the effect lane already used). A function whose throw set was exhaustive can therefore gain `throws: {…?}` in the `annotate` margin, and `loop-to-array-map` and `effects-envelope` read the same bit. `eval` and `include` also leave the throw lane non-exhaustive, as they already did the effect lane. In the other direction, names the audit evidences (`array_keys`, `dirname`, `implode`, `in_array`, `str_replace`, `trim`, the `is_*` predicates and many more) and names with a recorded `ValueError` (`dirname($p, 0)`, `max([])`, a path with a NUL byte for `unlink`, `fopen` and their kin) now make a body throw-exhaustive where an unknown name used to make it `…?`. `json_encode` and `json_decode` raise `JsonException` only under `JSON_THROW_ON_ERROR`: they are throw-exhaustive when the flags argument is absent or a constant expression without that flag, and `…?` otherwise. On the ten public packages 261 functions became throw-exhaustive and 294 became `…?`; no proven effect label, no `check --profile strict` finding and no transform plan changed.
  - A project function that shadows a builtin the catalog knows only through its mined signature (`levenshtein`, `array_find_key`) is now ambiguous for every pass, as one that shadows a coloured builtin already was, so a call to it is `…?` instead of an edge to the project body.
  - `statement.no-effect` no longer reports a discarded call to a builtin whose throw behaviour nobody has audited, and the ones the audit gives a `ValueError` row (`date_create_from_format()`). On the corpora's names that removes `date_create_from_format()` and `date_create_immutable_from_format()` from its reach, and no finding moves on the ten public packages.
