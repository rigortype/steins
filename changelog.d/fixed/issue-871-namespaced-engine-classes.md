- **The engine's namespaced classes are now known by their full names, so a body that builds or throws `Random\RandomException`, `Random\BrokenRandomEngineError`, `Uri\WhatWg\InvalidUrlException` or any other namespaced engine exception is no longer marked `…?` for that class.** The class list Steins mines from php-src's stubs read a `namespace Random` whose `{` is on the next line as no namespace at all, so 41 classes (the whole of `Random\*`, `Dom\*`, `BcMath\Number` and `Pcntl\QosClass`) were listed under their bare names (`randomexception`, `text`, `node`, `engine`), and an engine class with a backslash in its name was never treated as an engine class at all. On the ten public corpora nothing changes, because none of them names one of these classes; the change shows only in code that does.
  - **Findings can appear and disappear for the classes that move:** `throw new \Random\RandomException(...)` and `throw new \Filter\FilterFailedException(...)` in a function declared `@throws void` now report `throw.undeclared`, since both are `Exception`s and the second had lost its parent. `throw new \FFI\ParserException(...)` no longer does, because it is an `Error` (through `FFI\Exception`), which Steins had recorded as an `Exception`.
  - A name your own namespace makes up (`App\PDO`, or an unimported `PDO` inside `namespace App`) is still not an engine class. A namespaced engine class with no catalog row (`Random\Randomizer`, `Dom\Element`) is still a gap, now named as a missing row rather than an unknown class.
  - Because the bare names are gone, `class.undefined` no longer treats an undeclared `Text`, `Comment`, `Node` or `Engine` as a class the engine may declare; with a PHP sidecar the running engine decides those, and under `--no-php` it stays silent as before.
  - A call through a parameter declared as a class Steins does not know (`\Redis $r`) is now a `declared-receiver` gap in the effect lane, the name the throw lane already gave it, where the effect lane said `unknown-class`. It stays `…?` either way.
