- **The engine's namespaced classes are now known by their full names, so a body that builds or throws `Random\RandomException`, `Random\BrokenRandomEngineError` or any other namespaced engine exception is no longer marked `…?` for that class.** The class list Steins mines from php-src's stubs read a `namespace Random` whose `{` is on the next line as no namespace at all, so 41 classes (the whole of `Random\*`, `Dom\*`, `BcMath\Number` and `Pcntl\QosClass`) were listed under their bare names (`randomexception`, `text`, `node`, `engine`), and an engine class with a backslash in its name was never treated as an engine class at all. On the ten public corpora nothing changes, because none of them names one of these classes; the change shows only in code that does.
  - **Findings can appear and disappear for the classes that move.** `throw new \Random\RandomException(...)` and `throw new \Filter\FilterFailedException(...)` in a function declared `@throws void` now report `throw.undeclared`, since both are `Exception`s and the second had lost its parent; `throw new \FFI\ParserException(...)` no longer does, because it is an `Error` (through `FFI\Exception`), which Steins had recorded as an `Exception`.
  - **`type.argument-mismatch` moves with the corrected parents.** `new \FFI\ParserException` passed to an `\Error` parameter is no longer reported, a false positive, and two proven `TypeError`s are now reported: `new \Random\Engine\Mt19937(1)` passed to a `\Random\CryptoSafeEngine` parameter, and `new \FFI\ParserException` passed to an `\Exception` parameter.
  - **Two engine constructors that check a value now say so.** `new \Uri\WhatWg\InvalidUrlException('x', [1])` and `new \SoapFault(['a'], 'x')` raise a `ValueError` for an argument of the right type but the wrong content, so a body that builds one has that throw instead of none; `new \SoapFault(...)` was throwless on every earlier release.
  - **A class the stubs declare and your PHP does not is no engine class.** The hierarchy comes from php-src's development stubs, so it lists `Io\Poll\PollException`, `Openssl\OpensslException` and `StreamException`, which PHP 8.5 does not have; the miner now marks the rows its cross-check PHP lacks, and `new` or `throw new` of one stays `…?` (the two global ones, `StreamException` and `com_exception`, were answered as engine classes before).
  - A name your own namespace makes up (`App\PDO`, or an unimported `PDO` inside `namespace App`) is still not an engine class. A namespaced engine class with no catalog row (`Random\Randomizer`, `Dom\Element`) is still a gap, now named as a missing row rather than an unknown class.
  - Because the bare names are gone, `class.undefined` no longer treats an undeclared `Text`, `Comment`, `Node` or `Engine` as a class the engine may declare; with a PHP sidecar the running engine decides those, and under `--no-php` it stays silent as before. `steins doctor`'s "reflected class world" line no longer lists `Random\Randomizer`, since the catalog now knows it (`2 of 4` becomes `1 of 3` on a project that names it and `Random\IntervalBoundary`).
  - A call through a parameter declared as a class Steins does not know (`\Redis $r`) is now a `declared-receiver` gap in the effect lane, the name the throw lane already gave it, where the effect lane said `unknown-class`. It stays `…?` either way.
