- **A `break 2`, `continue 2` or `goto` inside a `switch` case is followed to where it lands, and a `switch` whose last case has no `break` is analyzed.** Steins used to read `case 1: foreach ($xs as $v) { break 2; } return;` as a case that always returns, so when every other case returned too it treated the code after the `switch` as unreachable and checked none of it, although PHP runs it. A `goto`, a `continue`, a `break` inside braces, or a last case without `break` used to make Steins skip every case of the `switch`. Each jump now counts the loops and `switch`es it leaves, as PHP does (a `continue` that targets a `switch` acts as its `break`). A `switch` whose cases do not run into one another is walked case by case, and the last case may end without `break`. The `variable.maybe-undefined` check at `strict` follows jumps the same way.
  - **Findings can appear:** findings on code after a `switch` that a jump in a case reaches; every finding Steins computes while walking a function, inside the cases of a `switch` it used to skip; `variable.maybe-undefined` at `strict` after such a `switch`.
  - **Findings can disappear:** findings on code after a `break 2` out of a case when every other case returns; `variable.maybe-undefined` where a case runs into a later one that binds the variable, or where a `finally` binds it before a `break` lands.
  - On the ten public corpus packages, no finding, `transform` dry-run or `effect-diff` event changes.
