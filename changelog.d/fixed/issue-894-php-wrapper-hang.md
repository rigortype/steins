- **A `php` wrapper script that does not `exec` the interpreter no longer hangs `steins check`.** When the `php` on `PATH` was a shell script running the real interpreter as its own child (`/path/to/php "$@"`, a common shape for version managers and container shims), closing a sidecar child killed only the wrapper and then waited forever on the interpreter, which still held the child's output open. The run hung at its end, and earlier at the revive that replaces a child after a request timed out. A close now drops the child's stdin, kills the child's whole process group on Unix (the child leads a group of its own, so the kill reaches every descendant that stays in it), and stops waiting for the child's output after half a second. An interpreter that leaves the group (for example behind `setsid`) can still outlive the kill; the first close that has to give up waiting on one stops replacing the sidecar for the rest of the run, which then reports as degraded and publishes no generation, as any run that lost a sidecar answer already does. On 0.1.8 and earlier, make the wrapper `exec` the interpreter. Findings do not change.
