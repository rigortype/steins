- **Destructuring a scalar no longer reports `offset.on-unsupported` where PHP is silent.** `[$x] = $v;`, `list($x) = $v;` and `['k' => $x] = $v;` were judged as the plain read `$v[0]`, which warns `Trying to access array offset on <type>` on every version; destructuring is a different operation. A `null` source is now silent on every PHP version, and a proven `int`, `float`, `bool` or `string` source is reported only where the whole analysed interval is PHP 8.5 or later, with PHP 8.5's own wording, `Cannot use <type> as array` (witnessed: 8.1 through 8.4 are silent for all of them, 8.5.11 warns for all but `null`). The interval is the declared target's floor when the project declares one (`require.php`), else the sidecar's PHP minor, so a project that admits 8.4 (`^8.1`), an 8.4 sidecar, a run with no sidecar and a project that defines its own `PHP_VERSION_ID` constant are all silent. Findings only disappear from `null` sources and from scalar sources below 8.5; a plain read `$v[0]` and a destructured array source with a missing key (`offset.missing`) are unchanged. An object source is a fatal on every version and is still not reported, and `foreach ($xs as [$x])` is still not judged.
