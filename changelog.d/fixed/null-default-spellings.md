- **A parameter whose default PHP folds to `null` at compile time is now implicitly nullable whatever the spelling, so `null` passed to `int $x = \null` (also `\NULL`, `null ?? null`, `true ? null : 0`, `[null][0]`) is no longer reported as a proven `TypeError`.** Before, only the bare keyword counted, so these parameters were read as plain `int`: an argument check, the type seeded for the parameter inside the body, and the phpdoc promotion and honesty transforms all treated them as non-nullable, where PHP accepts `null` (and emits the implicit-nullable deprecation on 8.4 and later). A default that reads a user constant (`= N` with `const N = null`) is still non-nullable, as PHP does not substitute it at compile time, so omitting the argument is a `TypeError`.
