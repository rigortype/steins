- **A call nested many levels deep no longer costs time exponential in its depth.** Steins worked out the value of each argument once for every rule that read it, and each of those did the same for the argument's own argument, so `strlen(strlen(…))` cost about three times as much per level of nesting and did not finish in a minute at 18 levels. Nested project-function calls, and calls nested through array literals such as `count([count([…])])` or `implode(',', [implode(',', […])])`, doubled or worse per level; a nested method call, static call or `new` doubled per level while the file was being read. Within one reading of a value, each argument's value is now worked out once, however many rules ask for it. These shapes now take well under a second at 20 levels; at 200 levels reading the file still takes about a second, since that part grows with the cube of the depth. Findings do not change: the ten public corpus packages report the same findings, at `strict` and at `default`.
