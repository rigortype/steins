- **Code after a `do`-`while` loop whose body always returns, throws or exits is now treated as unreachable, so findings that depend on reaching it no longer fire there.** A `do`-`while` body runs at least once, but Steins read the loop as one that might run zero times, so `$x = null; do { return; } while (false); $x->bar();` reported `call.on-null` on a line PHP never reaches, and `function f(): int { do { return 1; } while ($c); }` was reported by `type.return-maybe-missing`. Only the body decides: a `break` or `continue` of the loop (including `break 2` or `continue 2` from a nested loop or `switch`), or a path that does not end in `return`, `throw`, `exit` or a `: never` call keeps the code after the loop reachable. The condition is not consulted, so a `do { … } while (true);` whose body can reach its end is handled exactly as before.
  - **Findings can disappear:** `call.on-null` and the other findings Steins computes while walking a function, on code after such a loop; `variable.maybe-undefined` when an `if` arm ends in such a loop (as it already did for an arm ending in `return`); and `type.return-missing` or `type.return-maybe-missing` on a function that ends in one, or in a `do`-`while` whose body holds a `try` that returns.
  - **Findings can appear:** a `switch` case holding a loop with a `break 2` or `continue 2` inside was read as ending in its `return`, although that jump leaves the switch. Code after such a `switch` is now reachable and reported.
