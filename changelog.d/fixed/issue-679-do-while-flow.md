- **Code after a `do`-`while` loop whose body always returns, throws or exits is now treated as unreachable, so findings no longer fire there.** A `do`-`while` body runs at least once, but Steins read the loop as one that might run zero times, so `$x = null; do { return; } while (false); $x->bar();` reported `call.on-null` on a line PHP never reaches, and `function f(): int { do { return 1; } while ($c); }` was reported by `type.return-maybe-missing`. A body that can reach the condition or the code after the loop keeps it reachable: a `break` or `continue` of this loop (including `break 2` or `continue 2` from a nested loop or `switch`), or a path that does not end in `return`, `throw`, `exit` or a `: never` call.
  - **Findings can disappear:** anything reported after such a loop, and `type.return-missing`/`type.return-maybe-missing` on a function that ends in one. `do { … } while (true);` with no `break` now also makes the code after it unreachable for the findings Steins computes while walking a function, as `while (true)` already did.
