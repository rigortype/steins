- **With the PHP sidecar, `method_exists(C::class, 'm')` now answers from the running PHP when the class chain reaches a builtin class or interface, so a guard on a builtin method folds instead of staying undecided.** The start class, a parent or an interface that is a PHP builtin (`\ArrayObject`, `\Countable`) is read from the sidecar's reflected class, which lists the methods it inherits: `method_exists(AbsB::class, 'count')` over `AbsB implements \Countable` is true, `'nope'` is false and the body it guards is dead. A private method of a builtin parent does not count for its subclass, as in PHP. Findings can disappear from a body the fold proves dead (a strict-floor `type.maybe-argument-mismatch`, for one), and appear, or be upgraded from maybe to proven, in a body the fold proves live. The fold answers only when the project's declared PHP target is the sidecar's minor alone or absent: a wider target (`>=8.1` on an 8.3 sidecar) may run on a PHP without the method, so the guard stays undecided. A `require.php` constraint Steins cannot read (`>= 8.1`, `^8.1 | ^8.2`) counts as a declared target, so it leaves the guard undecided too. A vendor class, a class the sidecar cannot reflect and a run without PHP stay undecided too, and `--no-php` output is unchanged.
