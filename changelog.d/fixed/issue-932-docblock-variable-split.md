- **A `$name` in a docblock tag's description no longer counts as the variable the tag declares, so `/** @var Foo the result, unlike $other */` stops reporting `phpdoc.stale-var` for `$other`.** `@var`, `@param`, the assertion tags and `@property*` now take the variable from the token that follows the parsed type, the way `phpstan/phpdoc-parser` reads them: `@var Foo $x the result` declares `$x`, `@var Foo the result, unlike $other` declares nothing, and `@param int the count $n` is an invalid tag. Steins took the first `$name` anywhere in the line.
  - A `$name` inside the type no longer stands in for the variable either: in `@param callable(int $a): void $cb` the tag now declares `$cb` with the whole callable type, where it declared `$a` with the bare word `callable`. The same holds for `\Closure(...)` parameters and a conditional return type that names a parameter.
  - **Findings can disappear and can appear:** a `@var` or `@param` that was read against the wrong variable no longer casts or checks it, and a tag that now carries its full type is checked as written. On the ten public corpora no finding changes on `default` or `strict`; 17 of about 19,000 tags change the variable they name.
