- **`variable.undefined` now judges a read inside an `if` or `?:` by the side its `isset()` or `empty()` test reaches, so it reports a read of a never-bound name the guard leaves unbound and no longer reports a read in an arm such a guard makes dead.** An `if` or ternary used to silence every read of a name its condition tested, in either arm, so `if (empty($u)) { echo $u; }`, `if (!isset($u)) { echo $u; }`, `if (isset($u)) {} else { echo $u; }` and `empty($u) ? $u : 0` were silent although PHP warns "Undefined variable $u" on each; they now report. A guard covers the side where it proves the name bound: the body of `if (isset($u))`, the true arm of `isset($u) ? $u : 0` and the false arm of `empty($u) ? 0 : $u` stay silent, and a name the function binds anywhere stays `variable.maybe-undefined`'s. An arm that only a guard on a name nothing in the function can bind reaches never runs, so a read in it is no longer reported whatever name it reads: `if (isset($v)) { echo $u; }` and `isset($v) ? $u : 1` over a never-bound `$v` reported "Undefined variable $u" and PHP runs them clean. A function that contains a `goto` or a label keeps the old behaviour in both directions, because a jump can land inside an arm without evaluating the condition (ADR-0078, #1108).
  - **Findings can appear and disappear.** On the ten public corpora `check --profile strict` output is unchanged byte for byte.
