- **`variable.undefined` now reports a read of a never-bound name inside an `if` or `?:` whose `isset()` or `empty()` test of that name leaves it unbound on the read's side.** An `if` or ternary used to silence every read of a name its condition tested, in either arm, so `if (empty($u)) { echo $u; }`, `if (!isset($u)) { echo $u; }`, `if (isset($u)) {} else { echo $u; }` and `empty($u) ? $u : 0` were silent although PHP warns "Undefined variable $u" on each. A guard now covers only the side where it proves the name bound: the body of `if (isset($u))`, the true arm of `isset($u) ? $u : 0` and the false arm of `empty($u) ? 0 : $u` stay silent, and a name the function binds anywhere stays `variable.maybe-undefined`'s. A function that contains a `goto` or a label keeps the old silence in both arms, because a jump can land inside an arm without evaluating the condition (ADR-0078, #1108).
  - **Findings only appear**, each one a read PHP warns on. On the ten public corpora `check --profile strict` output is unchanged byte for byte.
