- **A variable assigned a condition is that condition where it is tested: `$has = $v !== null; if ($has) { return $v; }` narrows `$v` as `if ($v !== null)` does.** Before, only an existence guard (`function_exists`, `method_exists`, …) stored in a variable was read back, and only to vouch for the symbol it names. Now a comparison, an `is_*` type predicate, `isset`, a bare variable, and `!`, `&&` and `||` over them are stored too, and a test of the variable narrows by them (a stored `is_int($n) || is_float($n)` narrows along both paths) and is decided under what the walk knows at the test, so `$has = $v === 3; if ($v !== 3) { return; } if ($has) { … }` treats the code after the `if` as dead. Findings disappear on a stored condition's guarded side (`type.maybe-return-mismatch` on `return $v` above), and on a proven value a stored test the walk cannot decide may make dead (`$s = 'abc'; $ok = is_callable($s); if ($ok) { return $s; }`), as they already did for the inline test. A proven value such a test forgets past `if (T) { return; }` still decides a later test, so `$s = 'abc'; if (is_callable($s)) { return 'c'; } if ($s === 'abc') { return 'fine'; } return 1;` no longer reports the dead `return 1`. Nothing is stored from a property read, an offset read, a userland call, or in a scope with a reference, `global` or `extract`; rebinding a variable the condition reads, or writing or unsetting an offset of it, forgets the condition, so `$has = $v !== null; $v = null; if ($has) { return $v; }` keeps reporting.
