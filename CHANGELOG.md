### Added

- **`resource` is a type Steins knows now: a stream handle handed to a `string`, `int`, `float` or `bool` parameter is a finding (ADR-0056 §8).** PHP has no syntax for a `resource` return type — `fopen` declares nothing and never will — so the reflected return envelope every other builtin return fact hangs from was structurally unavailable, and the call-site rejections were silent. Nineteen producers mined from php-src's own stubs (`fopen`, `tmpfile`, `opendir`, `popen`, `proc_open`, the `stream_socket_*` and `stream_context_*` families, `gzopen`, `bzopen`, `fsockopen`, …) now seed a `resource`/`resource|false` arm on the variable they are assigned to; the ordinary `if ($h === false)` guard discharges the failure arm exactly as it does for any other `T|false`, and what is left is a proven resource. **This is a new true positive and turns a green CI red where the bug is real** — it fires at the default layer, and `type.argument-mismatch` is the existing id, so a baseline entry or `@steins-ignore` is the usual way out. Unlike every other argument mismatch, the verdict does not depend on `declare(strict_types=1)`: there is no `__toResource`, so a resource reaches a scalar parameter with nothing to coerce through, and the message says "in either mode" rather than naming a mode you could try to change. `@param resource $h` also stops being decoration — it was an unmodeled spelling that accepted everything, and a scalar handed to it is now reported (`open-resource` and `closed-resource` mean the same thing to Steins, which models the kind and not the state). What deliberately stays silent: an **object** handed to a `@param resource` parameter, because PHP 8 migrated most of the resource world to classes and left a decade of stale `@param resource $ch` docblocks on parameters that now receive a `CurlHandle` — the docblock is rot, the value is fine, and convicting there would be calling you a liar about someone else's prose. The same migration is why the rows are safe at all: a curated row is admitted only while your PHP still declares *no* return type for the name, so the 89 `functionMap` entries that now return `GdImage`, `LDAP\Result` or `Odbc\Result` are refused mechanically, and the day some future PHP turns `fopen` into an object the row switches itself off. With `--no-php`, or on a PHP minor other than the catalog pin, nothing is seeded and the behaviour is unchanged.

- **Tolerated effects: a project can now declare which effects its envelope judgments discharge, without a lie anywhere in the catalog (#323, ADR-0084).** A system-wide logger transitively reaches the clock and the filesystem, so under whole-program propagation every declaration that can touch logging loses purity — thousands of honest, unactionable `effect.envelope-exceeded` findings on classes whose author already wrote `@phpstan-ignore impure.methodCall` at the log call. An ignore suppresses a report; it does not discharge an effect, and under propagation the effect resurfaces at every pure declaration upstream. The new top-level `[effects]` table in `steins.toml` gives that intent a spelling: `tolerated = ["telemetry"]` names the labels the judgment subtracts before comparing proven effects against a bound, and `[effects.attribution]` marks a class, a `Class::method`, or a global function as being *for* something (`"Monolog\\Logger" = ["telemetry"]`). Attribution is fact and changes no verdict by itself; tolerance is policy and is inert without something to grip. Together they distinguish the same `time()` call by what it was for — the log timestamp discharges, the business-logic clock read in the same class keeps its finding. Nothing is subtracted from the catalog or from propagation: `time()` stays `nondet.time`, `annotate` still prints every label (marking a wholly discharged one `~nondet.time`, with a `tolerated` array beside `labels` in `--format json`), and `steins check --no-tolerated-effects` runs the judgment with an empty tolerance set so every discharged finding comes back for an audit. The discharge applies to `effect.envelope-exceeded` on both strata — checked `#[\Steins\Effect]` attributes and ADR-0082 interop envelopes — and to the purity oracle behind `pure-callable`/`pure-closure`, so envelope checking and purity queries never disagree about the same function. It deliberately applies to **no** spelling-producing site: `steins transform effects-envelope` keeps judging by the undischarged effects and will not write a `@phpstan-pure` a function earned only under your policy, because a docblock outlives and out-travels the config file. This is not a profile field — profiles select which findings surface, and this changes which findings exist. **Adding a tolerance can only remove findings, so no green CI turns red on it**; the movement is in the other direction, and `--no-tolerated-effects` is how you see it. Guidance is in `docs/user-manual/03-configuration.md`: tolerate semantic labels rather than transport labels, never attribute a PSR-14 `dispatch()` (real frameworks consume the returned event), and keep compliance `audit` logging on its own label rather than riding `telemetry`.
- **Five more builtins fold to real values: `array_unique`, `range`, `preg_split`, `str_split` and `array_fill` (#354).** An all-literal call to any of them is now evaluated by your own PHP and comes back as the array it actually returns, instead of the type a hand-written rule could guess at — `str_split("abcdef", 2)` is `list{'ab', 'cd', 'ef'}`, `array_fill(-5, 3, "x")` carries the key sequence PHP 8.3 changed, `array_unique([1, "1", 2])` drops what `SORT_STRING` says is a duplicate. None of these semantics is re-derived in Rust, which is the point: `range` changed its character and float behaviour across minors, `str_split` changed its empty-string return at 8.2, and the engine that answers is the one your code will run on. A more precise value can turn a `Maybe` into a `Yes` and surface a finding that was previously withheld, so a green CI can go red where the bug is real; nothing new is reported without a working PHP sidecar. In the browser playground three of the five fold and two do not: `range` and `preg_split` are refused on a 32-bit engine with a recorded divergence beside each (`range("3000000000", …)` yields floats there where a 64-bit engine yields ints, and that build's PCRE has no JIT, so it honours inline `(*LIMIT_MATCH=…)` verbs a JIT-enabled build ignores). An oversized reply is still declined rather than truncated — `array_fill(0, 1000000, "x")` widens to a type, exactly as a 257-piece `explode` does.

### Fixed

- **`vendor/bin/steins` no longer leaves the analyzer running when the wrapper is killed.** The Composer shim is a PHP launcher that fetches the binary and hands the process over, and it used to hand over by spawning a child and waiting on it — with no signal handling, so a SIGTERM addressed to the shim killed the shim alone. The analyzer kept running, still holding the caller's stdout, and its output kept arriving after the shell prompt was back or after CI had already recorded the step as finished; its PHP sidecars and temp files outlived the run too. `timeout 300 vendor/bin/steins check`, `docker stop`, and a cancelled CI job all signal one pid, so all three hit it. Ctrl-C never did, because a terminal signals the whole foreground process group. Where ext-pcntl is available the shim now `exec`s the analyzer in place — same pid, same descriptors, nothing left over to be killed separately — and where it is not, the spawning path relays SIGTERM, SIGINT, SIGHUP and SIGQUIT to the analyzer and reports its fate as 128+signum. Stream handling is unchanged and still inherited rather than piped, so colour detection, progress rendering and a piped `--format json` behave exactly as they did. The other channels (Homebrew, `cargo install`) put the binary on PATH directly and were never affected.

## [0.1.5] - 2026-08-13

This release is about the effect system meeting PHPStan halfway. Steins now reads the parameterized purity tags PHPStan's author sketched — `@phpstan-impure io.db` — as declared effect bounds, checks a function against the bound it wrote, writes those tags back from proven effects, and reports the typos without ever mistaking a human's one-word note for a bound. Underneath that, the effect vocabulary moved output under `io` and the builtin catalog stopped claiming a filesystem read where a URL wrapper can reach the network. Alongside the effects work: SARIF and GitHub Actions output, extension classes resolved against your own PHP, the `variable.maybe-undefined` / `property.maybe-undefined` pair firing on `strict`, a `pedantic` profile, and a precision wave through generics, `count()` narrowing, assert tags and comparisons in value position.

**Findings can appear and disappear in a `0.1.x` release.** The preview series continues through changes that move which findings fire (owner decision at v0.1.1); this one does, in the ways each entry names — most consequentially the retired `output` label and the effect-envelope soundness fix, both breaking for a green CI on `--profile contracts` or above.

### Added

- **Steins now reads the parameterized PHPStan purity tags as interop envelopes: `@phpstan-impure io.db, nondet.time`, `@phpstan-pure`, and the class-level `@phpstan-all-methods-pure` / `@phpstan-all-methods-impure` pair (#303, ADR-0082), built on the syntax PHPStan's author sketched for the tag.** A call covered only by one of these now contributes to the caller's declared effect lane at an abstraction-typed call site exactly as a checked `#[\Steins\Effect]` would, and the declaring function itself is contract-checked against its own tag. This can start firing on a project whose docblocks already carry these tags and lie about what they cover: `effect.envelope-exceeded` is contract layer, so it is **breaking** only for a CI already running `--profile contracts` (or `strict`/`pedantic`), and a baseline entry or `@steins-ignore` on the id is the usual way out. A label the run's registry does not know reads the *whole* tag as unspecified rather than as a narrowed subset of what it named — current PHPStan discards everything after `@phpstan-impure`, so wild prose like `@phpstan-impure database` stays exactly as harmless as it is today — and `effect.unknown-label` stays attribute-only, never firing from one of these tags; typo detection for the docblock spelling is the separate opt-in `effect.interop-unknown-label` above, which reports the evident typos and changes no bound. The finding quotes the tag back in its own family's spelling (`@phpstan-impure ...`), never translated into `#[\Steins\Effect]` syntax. A bare `@phpstan-impure` stays unread on purpose — it is ⊤, exactly what the tag's absence already means, so there is nothing to check.

- **`steins transform effects-envelope` writes these interop envelopes from proven effects (#303, ADR-0082 §7): `@phpstan-impure <labels>` for a declaration whose inferred effects are exhaustive, `@phpstan-all-methods-pure` on a class whose every declared method is provenly and exhaustively pure, and nothing at all for a non-exhaustive summary, a per-method pure declaration, or a declaration already carrying the checked `#[\Steins\Effect]` / `#[\Steins\Pure]` spelling — and it refuses by name, byte-untouched, rather than guess at a tag it cannot read: an existing tag carrying an unknown label (`existing-tag-unreadable`, most likely a human's prose note) or a computed bound that would itself contain one (`bound-label-unknown`).**

- **`effect.interop-unknown-label` (#311): the typo check for labels written in PHPStan's purity tags, contract layer at the `contracts` floor.** A label the registry does not know still reads the whole tag as unspecified — that reading is unchanged — but where the token *shows* it was meant as a label, the declaration now says so instead of silently checking nothing: the token is within an edit or two of a real label (`@phpstan-impure io.netw` → did you mean `io.net`?), some other member of the same list is a real label, it has two or more dot segments, or it is a spelling Steins retired. **A one-word note far from every label and alone in its list — `@phpstan-impure database`, which current PHPStan discards and which therefore appears in real docblocks — never reports, on any profile, ever.** Retired spellings carry migration guidance an edit-distance suggestion cannot reach: `@phpstan-impure output` is told to write `io.output.buffer` for echo-shaped code, `io.output.header` for `header()`/`setcookie()`, or the umbrella `io.output`, and the same guidance now appears in the attribute stratum's `effect.unknown-label` message for `#[\Steins\Effect('output')]` (same id, same layer, same firing rule — only the sentence changed). Nothing new prints on a bare `steins check`; the id rides with `effect.envelope-exceeded`, so enabling envelope enforcement is what enables the check that keeps enforcement honest, and unlike the mechanics-layer `effect.unknown-label` it is suppressable by baseline or `@steins-ignore` while a rename is in flight.

- **`steins check --format sarif`: a SARIF 2.1.0 log for code-scanning upload (#14).** One `run`, a `tool.driver.rules` table carrying one entry per id present in the results (deduped and sorted — not the whole registry) with its layer and default level, and one result per displayed finding with `ruleId`, `ruleIndex`, `level`, the message verbatim, and the same 1-based line and column every other format prints. `partialFingerprints` carries `steinsFindingHash/v1` — the *same* hash the baseline uses to recognize a finding across unrelated edits — so alert tracking across runs gets the stability the baseline already has from one identity function rather than two. `run.automationDetails.id` is `steins/<profile>`, so a `default` gate and a `contracts` debt dashboard can upload in parallel without clobbering each other's alert categories, and `run.properties` carries the same accounting envelope `json` does: counts, never entries. There is deliberately **no `suppressions` section** — re-emitting a baselined or `@steins-ignore`d finding as a SARIF "suppressed result" would make the format a fourth suppression channel and would publish your baseline's contents into every upload. `sarif` is never auto-selected; it is a file artifact you ask for in an upload step. A run with findings still exits 1 — `continue-on-error` on the check step is how a workflow uploads anyway, and there is no flag that makes `check` report success on a failing tree. See `docs/user-manual/ci-templates/github-actions-sarif.yml`.

- **`steins check --format github`: GitHub Actions annotations, selected automatically inside Actions (#14).** Each displayed finding becomes a workflow command (`::error file=…,line=…,col=…,title=…::message`), so a run annotates the pull request diff inline with no `jq` recipe and no action wrapper — the id rides in `title`, and GitHub's escaping is applied in both of its registers (`%`/CR/LF in the message; additionally `:` and `,` in `file`/`title`). The command name follows the exit level: fail-level is `::error`, a profile-demoted `warn` is `::warning`, and the debug lane's dumps are `::notice` — carried, never dropped, because a rendering that hid a fail-level dump would leave a red job with nothing explaining it. **With no `--format` flag, `check` now emits `github` instead of `text` when `GITHUB_ACTIONS=true` is in the environment.** An explicit `--format` always wins, in both directions, and detection changes only the spelling — the surface, the profile, the suppression pipeline and the exit code are identical either way. Nothing else is detected: a generic `CI=true` names no rendering anything can consume. A CI step that parses `check`'s stdout as text should pass `--format text` explicitly.

- **Classes from loaded PHP extensions now resolve against your own PHP (#269).** A class an installed extension provides — `Redis`, `Random\Randomizer`, `Dom\Element` — appears in no source file and in no list Steins ships, so until now it was simply unknown. Steins now asks the same `php` the sidecar already runs for the class's own declaration: its methods and their signatures, its constants, its properties, and its parent and interface edges, tagged with the extension that declares it. The answer is only ever your PHP's: there are no bundled extension stubs, and a class your runtime cannot reflect stays unknown exactly as before. **No finding is added by this**, in any profile. A reflected declaration is the runtime's claim about its own class, so nothing that reports a missing member (`call.undefined-method`, `property.undefined`, `class-const.undefined`) is premised on it — turning PHP on can make Steins know more about `Redis`, and cannot make it start reporting your calls on one. `steins doctor` names what it resolved, in a new Coverage-posture line. With `--no-php`, with no `php` on `PATH`, or when the sidecar stops answering, behavior is unchanged down to the byte.

- **`steins doctor` grows Catalog/Registry/SAPI posture sections, `--format json`, and `[doctor] require` (#268).** The Runtime section now names the A6 SAPI-existence-oracle standing (`[runtime] sapi` is undeclared by design today, so the curated `fastcgi_finish_request`/`apache_*`/`litespeed_*` names are never reported Absent) and the Coverage posture section adds the A2(ii) sound-subset id list, the ADR-0015 vendor-suppression policy line, and the `[transform.vouch]` site count with its checker-side boundary named honestly. Two new sections land: Catalog (the builtin catalog's php-src pin versus the analysis version, the A11 skew consequence when they diverge, and the hierarchy/foldable table sizes as freshness context) and Registry totality (the diagnostic registry's own emittable/pending partition, self-checked in the shipped binary). `--format json` renders the identical section list as `{"schema":"steins.doctor/v1","sections":[{"name":...,"lines":[...]}]}` — text and json are two renderings of one internal structure, never two code paths to keep in sync. `[doctor] require = ["sidecar", "catalog-pin-match", "no-monkey-patch", "no-dormant-baseline"]` turns a named posture line from report-only into an exit-1 assertion, the lenient-default opt-in ADR-0054 promised; an unrecognized name is a hard config error, and a misspelled `[doctor]` key is too. Two ADR-0054 C4 lines are not implemented, each named rather than silently dropped: the dump-site count waits on the still-unlanded D3/D4 recognizer, and `contract_touches_class`'s project-wide count would need a second, index-only entry point into the checker's private symbol index, which does not exist yet.

- **`variable.maybe-undefined` fires (#267).** The `strict` profile now reports a read of a variable that only *some* of the paths reaching it bind — `if ($c) { $x = 1; } echo $x;`, `$y = $x; $x = 1;`, a name bound only inside a loop body, a name bound only inside a `try`. This is the sibling registered ahead of emission in v0.1.4, so a baseline entry or an `@steins-ignore` that already named the id keeps meaning what it meant, and nothing changes for `default`, `contracts`, `throws-direct` or `pedantic` — a partial-path claim is a possibly-grade finding and stays behind `strict`. The claim is about the syntactic control-flow graph: a branch arm that provably ends in `return`/`throw`/`exit` carries no path to the read and is subtracted, a loop body is read as running zero times or many, and a `try` block is read as able to throw at any point. Boundness guards are consumed with polarity, so the defaulting idiom `if (!isset($x)) { $x = fallback(); } use($x);` is silent — the then-arm binds, the implicit else-arm holds `isset($x)`, and every path reaching the read carries a binding. Every silence `variable.undefined` documents is inherited unchanged: `extract`/`compact`/`$$x`/`eval`/`include` dam the scope, top-level scripts and arrow-function bodies never report, `isset`/`empty`/`??`/`unset`/`@` reads are not this finding, superglobals and `$this` are always bound, and an out-parameter confirmed by the callee's declaration binds its name — here from the call site forward rather than scope-wide. A statement-position `assert(isset($x))` binds `$x` for everything after it — a failed enabled assertion throws, so the next statement is reached exactly when the condition held — and a boundness guard reads through its offset and property chain, so the `if (!isset($info['a']['b'])) { return; }` prologue silences the reads after it. A `goto` or a label anywhere in the scope dams this id and this id only. The two `variable.*` ids are disjoint by construction: a name the scope binds nowhere is `variable.undefined`'s and reports at `default` exactly as before.

- **`property.maybe-undefined` fires (#267).** The `strict` profile now reports a `$o->prop` read whose receiver was narrowed to a **union** of natively declared types where some arms declare the property and the rest provably lack it — `function f(Has|Lacks $o) { return $o->nope; }`. This is the declared-shape possibly leg ADR-0078's floor table named, and it carries no path reasoning: the arms are declared types, not control-flow paths. The routing between the two `property.*` ids is a partition, so no site is reported twice — every arm provably lacking it is `property.undefined` at `default` exactly as before, some arms lacking it is this id at `strict`, and a single arm the absence ladder cannot close silences both, because "some arms lack it" is still a claim about all of them. Every premise of the definite leg applies unchanged: the `warning-handler` posture gate, the project-wide dynamic-write obstacle, `__get`/`__set`/`__isset`, `#[AllowDynamicProperties]`, `@property`/`@method`/`@mixin`, the live-sidecar requirement, the complete descendant closure, and the Verified-stratum floor that keeps a docblock-premised union off the proof surface.

- **`srand`, `mt_srand` and `clearstatcache` are catalogued `global.write` (#318).** All three replace process-global state — the RNG's generator state, the engine's stat cache — and were previously uncatalogued, which is sound but needlessly vague: an otherwise-provable function containing one of them reported "these effects, and possibly more" (`annotate`'s `…?`), and under `#[\Steins\Pure]` or `@phpstan-pure` the call was silent taint rather than a violation. It is now a reported `effect.envelope-exceeded`, and the exhaustiveness marker disappears wherever these were the only unknowns. Drawing from the RNG is unchanged and stays `nondet.random`: seeding *writes* the state a draw reads, and the two are not the same effect.

- **A fifth built-in profile, `pedantic`: `contracts` plus the house-style asks.** A house-style ask is a rule about how code should be *written*, where Steins itself has no finding to make — the first one is `untyped.class-constant` (see below). `pedantic` is a **branch off `contracts`, not a step above `strict`**, and the two are independent: `strict` never reports `untyped.class-constant`, `pedantic` never reports `offset.maybe-missing`. Wanting your constants annotated and wanting the some-paths-only claims are separate decisions, so neither profile drags in the other, and there is deliberately no built-in that means "everything on" — write `extends = "strict"` with `enable = ["untyped.class-constant"]` if that is what you want. Selecting a single house-style rule without the profile works from any base, as it always did: `extends = "contracts"` with the same `enable` line. `pedantic` joins `default` / `contracts` / `throws-direct` / `strict` as a name that cannot be redefined by a `[profile.pedantic]` table.

### Changed

- **The `output` effect label is retired: output is now an ambient channel under `io` (#316, ADR-0083).** `output` and `output.header` are gone, replaced by `io.output` and a family split on the one question a future `ob_start()`-aware analysis has to answer — can the output buffer capture this? `io.output.buffer` is OB-capturable output (`echo`, `print`, `<?=`, inline HTML, `printf`, `print_r`, `var_dump`, `flush`, `ob_flush`), `io.output.header` is response metadata (`header()`, `setcookie()`, the old `output.header`), `io.output.stdout` / `io.output.stderr` are process-fd writes an output buffer cannot touch, and `io.input` joins them as the symmetric ambient input channel (registered for declarations; no builtin carries it yet, and `$_GET`-style reads of parsed request memory stay `global.read`). The move also fixes what the vocabulary was fighting: an operation whose stream happens to end at stdout no longer has to be spelled as two unrelated roots. **Breaking, in three named ways.** `#[\Steins\Effect('output')]` now earns `effect.unknown-label` — mechanics layer, on in every profile, with no suppression channel; on `--profile contracts` and above the stale attribute also reports `effect.envelope-exceeded`, since an unknown label subsumes nothing and the body's `io.output.buffer` now escapes the bound — and because `output` → `io.output` is three edits apart, past the suggestion cap, neither finding carries a "did you mean": the migration table is in `docs/type-specification/effects.md`, and the rewrite is `output` → `io.output.buffer` for `echo`-shaped code, `output.header` → `io.output.header`, or the umbrella `io.output` when a declaration means both. A bare `io` envelope now **admits** output, deliberately — output is an `io` child, bare `io` is what stream work says when its destination is unknown, and stdout is one of the destinations; fine-grained envelopes are untouched (`io.db` still catches an `echo`), and "io but no output" is spelled by enumerating the children. And new true positives fire where the catalog was previously silent: `readfile` and `fpassthru` (`io.fs.read` + `io.output.buffer`), `system` and `passthru` (`io.process` + `io.output`), `curl_exec` (`io.net` + `io.output`), and inline HTML between `?>` and `<?php` inside a function body, which ADR-0008 always called output and the scan never implemented — whitespace-only inline text is still silent, since a function's effects should not depend on its indentation. Docblocks are safe throughout: an interop `@phpstan-impure output` degrades to an unspecified tag under the ADR-0082 amendment — no bound arrives and no finding is invented — and `steins transform effects-envelope` refuses a docblock carrying the old spelling as `existing-tag-unreadable`, byte-untouched, while its emission side writes the new vocabulary.

- **A generic object keeps its type arguments when you assign it to a variable (#295).** `$box = new MutableBox(1);` knew `$box` was a `MutableBox` but had forgotten it was a `MutableBox<int>`, so passing it to a `@param MutableBox<string>` parameter went unreported. The arguments now ride with the object, and — the harder half — they are dropped again wherever they could have gone stale: calling a method on the object drops them, and so does handing the object to a function that could touch it at all. Only a function that never mentions the parameter keeps them, which is provable from the function's own text. The conservative direction was chosen deliberately: an argument this analyzer reports on should never be one you have to argue with, and a type argument that silently went out of date is exactly how that happens. As a consequence, an object passed by value to a function now keeps its class identity across the call, which it previously lost outright — its mutable state is still discarded.

- **`@extends Box<int>` is now read (#294).** A subclass that declares its parent's type arguments in a docblock — `/** @extends Box<int> */ final class IntBox extends Box` — told Steins nothing, so passing an `IntBox` to a `@param Box<string>` parameter went unreported. The declaration is now read, on `@extends` and `@implements` alike, and the argument is judged against the parameter's. Deliberately narrow: the declaration is read one level from the class you actually instantiated, a class that declares its own `@template` is unaffected, and a covariant or contravariant template stays silent rather than guessing — reading those as invariant would report code that is correct. An argument naming a type Steins cannot resolve is silent too, since it may be an alias for something that would make the comparison meaningless.

- **A `@template T of array` bound is now enforced (#293).** A template's declared bound — `@template T of array`, `@template T of int|list<int>` — was read as far as the template's name and no further, so a helper that declares what it accepts got no help from the declaration: `new Collection(1)` under `@param T $items` reported nothing. The bound is now an upper-bound contract, which is what it always meant. Only vocabulary bounds are read this release (`array`, `int`, `string` and their unions); a bound naming a class declines rather than half-checking it. The check can only miss, never invent: whatever binds to `T` inhabits `T`, and `T` is at most its bound. On a large private codebase this surfaced fifteen call sites passing values their helper's own bound excludes — including one where two sibling call sites disagree about whether the same constant holds strings or ints.

- **Destructuring now reports the keys it reads, and a function's declared array shape reaches its caller (#288).** `[$a, $b] = $m;` reads `$m[0]` and `$m[1]` exactly as `$x = $m[0];` does, but Steins judged only the second spelling — so a destructure of a string-keyed array warned at runtime and reported nothing. The keys are derived the way PHP derives them, witnessed against the real runtime: a positional element takes the next index, a hole (`[, $b]`) consumes its index without reading it, a keyed element takes its own key, and a nested pattern reads the outer key too. A by-reference target, a spread, a computed key, and the mixed keyed/positional form PHP rejects outright are each silent — `[&$a] = $m;` creates `$m[0]` rather than reading it. Separately, `$rows = getRows();` now carries `getRows()`'s declared `@return` array shape into `$rows`, which the `@param` direction has done since v0.1.x — so an offset read, a guard, or a contract check downstream of a call sees the shape the callee promised.

- **A `count()` comparison now narrows the array it counts (#272).** `if (count($items) > 0)` proves `$items` non-empty on the true arm, `assert(count($rows) === 3)` pins a sealed shape's exact size (promoting its declared keys to present), and the false arms carry the complements — the missing half of the picture the v0.1.4 `count()` reading started, and the capability behind +116 nsrt rows. The guard is exact about what it refutes: a literal array that provably cannot reach an arm no longer rides into it, which also removed four pre-existing false `phpdoc.param-mismatch` reports where an empty-array default survived past the guard that excluded it. Three new `phpdoc.param-mismatch` findings this precision exposes on real code are genuine declared-contract debts (a `@return` shape whose keys outgrew the `@param` it feeds), each verified against the source.

- **A `@phpstan-assert Guest $v` tag now narrows (#266).** A class-typed assert tag on a helper established nothing at all — the identical `instanceof` guard narrowed, the tag did not. It now narrows the declared-type lane at the trust grade a docblock claim carries: it can silence, and it can premise a contract-layer finding like `phpdoc.undefined-method`, but it can never premise a proof-layer finding — a lying tag cannot forge a proof. The `-if-true`/`-if-false` polarities ride the same route.

- **A comparison in value position now evaluates (#260).** `$eq = $a === $b;`, a comparison passed as an argument, returned, or dumped, previously answered `unknown` unless it sat in an `if` condition; it now answers through the same comparison engine conditions use — a decided comparison is its boolean value, an undecided one is `bool`, which is the operator's own guarantee in PHP. This is the largest single precision step since v0.1.4 measured by the nsrt instrument: +527 rows, including 304 of the 369 loose-comparison cases, with zero regressions and no finding movement on the corpus. Arithmetic and bitwise operators still decline (an unimplemented operator answers nothing rather than guessing) — their evaluator belongs to the sidecar and is tracked on the same issue.

- **String refinements now survive the calls between them (#41).** A proven `non-empty-string` used to be erased by the next call the analyzer could not vouch for — one `escapeshellarg($s)` anywhere in a function condemned every premise established above it, and a builtin imported with `use function strtolower;` resolved to nothing at all, condemning its own arguments the same way. The by-value string family (25 names, including the `mb_*` set) is now certified against the real PHP's reflection, imported builtins resolve like their backslashed spellings, and `strtr` and zero-offset `substr` transfer the non-emptiness they actually preserve. Refinements PHPStan ships that a one-line witness refutes — `strtr` non-falsiness, `sprintf` non-emptiness from non-empty arguments, `sprintf('%x')` as numeric-string — are deliberately declined and recorded on the issue. An *aliased* import (`use function trim as t;`) still condemns; tracked as #279.

- **An untyped class constant no longer reports on `--profile contracts`.** `untyped.class-constant` moves to the new `pedantic` profile, and no built-in reports it otherwise. A class constant is the one member kind whose missing type declaration withholds nothing: a constant is inherently static, its initializer is a constant expression, so `const MAP = ['a' => 1];` has exactly the type it would have with the declaration written out. Every other arm of the `untyped.*` family names real lost information — a parameter, property or return with no type is `mixed` and the analyzer has to guess. Inheritance can still overwrite a constant with a differently shaped value; that risk is accepted knowingly, and unlike a property Steins does not ask for the declaration. Teams that *do* want to require it opt in by name, which is why the check was recalibrated rather than deleted. The id, its layer, its message and its emission conditions are all unchanged, so a `@steins-ignore` or a baseline entry naming it keeps meaning what it meant. This unblocks the shape it fired on hardest — a `key-of<C::MAP>` / `value-of<C::MAP>` docblock, where the constant it points at is exhaustively typed *by* its value and the finding arrived alongside the real contract violation the file was testing for.
- **`steins: unknown profile …` now lists every built-in.** The hint spelled out four names and had already drifted; it is derived from the built-in list now, so it cannot drift again.

### Fixed

- **An effect envelope no longer admits the network read it never named (#318).** Every filesystem builtin in the catalog — `file_get_contents`, `file_put_contents`, `fopen`, `copy`, `rename`, `readfile`, `fpassthru`, `fread`, `fwrite`, and the stat-and-unlink family `unlink`, `mkdir`, `rmdir`, `touch`, `scandir`, `file_exists`, `is_file`, `is_dir` — was coloured `io.fs.read` / `io.fs.write` / `io.fs` whatever its argument said, so `@phpstan-impure io.fs.read` over `file_get_contents('https://…')`, `io.fs.write` over `unlink('ssh2.sftp://…')`, or either over an `fread()` on a socket, passed silently, and the bound the spec defines as "every effect the body performs is subsumed by some listed label" was not being checked. None of those functions is filesystem-only: a URL wrapper, a socket, a process pipe and the output channel all sit behind the same call, and the stat family is no exception — `unlink` deletes over `ssh2.sftp://` and `file_exists` stats over `ftp://`. Each now defaults to `io`, the parent of every channel a stream wrapper can reach (`fgets` and `fputs` join the table on the same footing), and the precise label comes back from the **call site** whenever the target is a constant: a literal path is still `io.fs.read` / `io.fs.write`, and `fopen` now composes its direction from a literal mode instead of always saying `io.fs`; `https://` is `io.net.http`, `ftp://` and `ssh2.*://` are `io.net`, `unix://` is `io.ipc`, `expect://` is `io.process`, `php://output` is `io.output.buffer`, `php://stdout` / `php://stderr` are `io.output.stdout` / `io.output.stderr`, `php://input` and `php://stdin` are `io.input` — the first builtin rows to produce that label — `php://memory` and `data://` are `mutate.local`, `php://filter/…/resource=` resolves the stream it wraps, and `fwrite(STDOUT, …)` is `io.output.stdout` rather than a filesystem write. Each target is read in its own role, so `copy('/a', '/b')` is now `io.fs.read` **and** `io.fs.write` — the source read the old write-only row never named, which an `io.fs.write` envelope over a `copy()` call will now report — while `rename` writes both sides and keeps the single label. Code that names its files with literals — the overwhelming majority — reports exactly what it reported before, byte for byte. **The flip side is real and is breaking for a green CI on `--profile contracts` or above**: an envelope written against the old precise row over a call whose target is *not* a literal now reports, so `@phpstan-impure io.fs.read` over `fread($resource)` or `file_get_contents($url)` earns `effect.envelope-exceeded` where it used to pass — widen the declaration to `io`, or baseline the id. An unknown scheme, a userland `stream_wrapper_register` wrapper included, keeps the `io` default rather than guess; `copy`/`rename` narrow only when both of their targets are constant, because a union with `io` is `io`; and the stat-and-unlink eight decline a `php://` target outright, since they open no stream for one to name.

- **An aliased builtin import now resolves (#279).** `use function trim as t;` left every `t($s)` call an unresolved unknown: its arguments were condemned (erasing the string refinements above the call), a pure function calling an aliased `rand` went unflagged, and an aliased `usort` neither dispatched nor colored its callback. The alias now resolves to the builtin's canonical name everywhere the catalog is consulted, while diagnostics keep printing the name your code actually wrote. A project function that *shadows* a builtin name is never treated as the builtin — aliased or not, which also fixes a latent inconsistency where the spelled call and the aliased call disagreed about the same shadowing function.

- **A finding inside code PHP never evaluates is no longer reported (#266).** A decided `&&`/`||` skips one operand, a decided ternary takes one arm, and a `??` whose left side is proven present never evaluates its right — but the analyzer's direct pass still reported findings inside those spans, the unimplemented half of a rule the narrowing design had already written down. Five witnessed false-positive shapes are gone; a docblock-only claim deliberately cannot silence a span this way — reachability stays proof-grade.

- **The browser playground no longer dies on a deeply nested expression (#264).** The wasm module runs on a stack fixed when it is linked, and a browser's own recursion limit is not something a web page can raise, so the fix that covered every command-line surface (#246, below) could not reach it: pasting a file with a long `->`/`[…]`/`.`/`&&` chain killed the module outright, and what the page had to show for it was a JavaScript error naming neither PHP, nor a file, nor a line. Such a file is not exotic — phpstan-src's own benchmark fixture is 1,000 links long, and the module gave up between 300 and 600. The analyzer now measures how much stack it has actually spent while walking a file and stops before the module dies, reporting `syntax.unparsable` with a message saying the expression nests deeper than it can walk. The findings for that file are withheld, as they already are for a file the parser cannot read — a partly-walked file is not evidence — but the run finishes, the page renders, and the module keeps working. Files below the limit are analyzed exactly as before; the limit is measured in stack, not in a fixed nesting count, so it never trims an answer the browser could have given. Nothing changes on the command line, where the analyzer keeps buying itself a bigger stack instead of refusing.

- **`count()` and `array_is_list()` over a literal array now answer exactly (#262).** A subject the analyzer had as a literal value — `$v = [1, 2, 3]; count($v)` — was answered with the bare envelope (`int<0, max>`, `bool`) instead of the exact count and verdict the literal already carries, because the literal short-circuited past the shape logic built for exactly this question. The same wiring gap covered `current`/`next` on literal arrays. Declared array *shapes* were already answered; this closes the gap for values the analyzer proved outright.

- **A file with a deeply nested expression no longer kills the whole run (#246).** Lowering walks the syntax tree with one stack frame per node, so a long property-fetch, array-index, concatenation or `&&` chain — the kind machine-generated PHP and benchmark fixtures produce — could exhaust the operating system's default 8 MiB stack and abort the process with `fatal runtime error: stack overflow`. Nothing was reported: not the file that caused it, not the rest of the project, and no exit code a CI job could interpret. Every subcommand now analyzes on a thread with a 256 MiB stack, which raises the depth a release build tolerates from roughly 2,700 chained operations to well past 10,000, and a debug build's from roughly 520. The stack is address space the operating system hands out page by page, so a run over ordinary code costs nothing extra. The wasm playground is **not** covered — a browser caps recursion in a way no setting on our side can raise — and is tracked separately.

## [0.1.4] - 2026-08-08

This release is about breadth. Thirty-nine new diagnostic ids land — two of them registered ahead of emission, the rest firing — and most sit on the default profile, which closes the gap that made a checker silent on `$foo->tyop()` and on a class that cannot load. **Upgrading changes which findings fire**: a CI that was green on v0.1.3 can go red on v0.1.4 with no change to your code, and in nearly every case it goes red on code that would fatal, warn, or fail to load if it ran — budget a baseline refresh. The type system grew alongside it: `class-string` became a type Steins can judge rather than a word it tolerated, a refined string now prints every predicate it holds instead of one, object intersections resolve their members, `preg_match` teaches the engine what it wrote into `$matches`, and PHP strings are compared by their bytes rather than through a lossy UTF-8 decode that could forge equality between distinct values. The version stays 0.1.x by owner decision; treat the finding changes as breaking anyway.

### Added

- **Two new default-profile findings report a class PHP refuses to load at all: `class.abstract-unimplemented` and `class.extends-final` (#183).** A concrete class that inherits an abstract method — from an abstract ancestor or from an interface it implements — and never defines it is a fatal at class load (`Class C contains 1 abstract method and must therefore be declared abstract or implement the remaining method (B::m)`), as is `class X extends F` where `F` is `final` (`Class C cannot extend final class F`). Both are decided from the declaration graph alone: no flow analysis, no receiver, no sidecar, and no dynamism dam — `eval` can mint a class, but it cannot add a method to one that is already declared. A green CI can newly go red on either, and it is red for code that would not run.
  - **The closure conditions are strict, and each one is silence.** The `extends` chain must be enumerable end to end, because an unresolvable parent is exactly where the missing implementation could live; any `use`d trait anywhere in the chain is silence, since trait members are not flattened into the class; an ambiguous name (two declarations of the same FQN) and a conditionally declared ancestor under a standing dynamism site both leave which declaration binds to load order. Abstract classes, interfaces, enums and traits are never the subject of the abstract-method finding, and neither are anonymous classes, whose bodies are not read. `__call` is deliberately **not** an obstacle: PHP fatals on the unimplemented abstract method whether or not the class defines one.
  - **An interface Steins cannot resolve is dropped rather than silencing the class.** A PHP interface never carries a method body, so an unenumerable one can only add requirements — `class C implements Countable {}` reports nothing, while a class that also inherits a proven-unimplemented method from an enumerable parent still reports that one. The neighbouring fatals stay out of these ids and out of this release: extending an enum, implementing a non-interface, re-declaring a concrete method abstract, and narrowing an implementation's visibility each raise a different runtime error and belong to their own ids.

- **Five new default-profile findings report a method override PHP refuses to load: `override.final`, `override.static-mismatch`, `override.visibility-weakened`, `override.parameter-variance` and `override.return-variance` (#184).** Overriding a `final` method (`Cannot override final method P::m()`), flipping a method between `static` and non-`static` in either direction (`Cannot make non static method P::m() static in class C`), narrowing an override's visibility along public → protected → private (`Access level to C::m() must be public (as in class P)`), narrowing a parameter type (`Declaration of C::m(int $x) must be compatible with P::m(string|int $x)`) and widening a return type (`Declaration of C::m(): string|int must be compatible with P::m(): int`) are each a fatal at class load, and each is now reported at the offending method — a **breaking** finding expansion for a green default-profile CI, on code that would not run. Implementing an interface goes through the same path as extending a class, so a wrong-signature implementation reports the same way.
  - **The legal counterpart of every one of them stays silent, and it is the counterpart PHP actually accepts.** Widening visibility, widening a parameter type (`int` → `int|string`, `int` → `?int`, or dropping the declaration entirely), narrowing a return type (`int|string` → `int`, `iterable` → `array`, `int` → `never`), adding a return type where the parent declares none, adding an *optional* parameter, renaming a parameter, and sealing an override with `final` in the child are all legal PHP and all silent. Only one finding is emitted per overriding method, in PHP's own precedence — final, then static, then visibility, then parameters, then return — so the id never misnames which fatal fires.
  - **`__construct` is exempt, but only as far as PHP exempts it.** A constructor may narrow its parameters and weaken its visibility against a *concrete* parent constructor, and does; but it does not escape `final`, and the exemption ends the moment the parent's `__construct` is abstract — declared in an interface or `abstract` — where both checks apply again. A `static` constructor is its own separate fatal and is not reported here. `__destruct` and the other magic methods are not exempt from anything.
  - **Only native declarations are read.** A `@param` or `@return` type is a docblock claim PHP does not consult when it decides this fatal, so it never convicts — not even when it contradicts a perfectly legal native pair. Variance is judged by the one acceptance relation Steins already owns, so an answer it cannot decide is silence: two unrelated class names, a `bool` against a `true`/`false` literal, and an `int`/`float` pair are all left alone. So are a changed parameter *count* and a by-reference mismatch, which are real fatals with a shape these ids would misname. The closure conditions are issue #183's, verbatim: the `extends` chain must be enumerable end to end, any `use`d trait anywhere in the chain is silence, an ambiguous name and a conditionally declared ancestor under a standing dynamism site both leave which declaration binds to load order, and enums and anonymous classes are never subjects.

- **Three new default-profile findings report a member PHP refuses to let the caller touch: `call.inaccessible-method`, `property.inaccessible` and `class-const.inaccessible` (#185).** Calling a `private` method from outside its declaring class, a `protected` one from a scope outside its hierarchy, reading or writing a `private`/`protected` property, and fetching a `private`/`protected` class constant are each a fatal `Error` raised before the member is reached — `Call to private method C::m() from global scope`, `Cannot access private property C::$p`, `Cannot access protected constant B::K` — and a green default-profile CI can newly go red on all three, on code that would fatal if it ran.
  - **Steins already computed this and threw it away.** The resolver read a method's visibility and used it only to give up quietly, so the call went unchecked and nothing was reported. Resolution still gives up — a member you cannot see is not a dispatch target, and arity, effects and every other consumer must keep seeing "no target" — and the finding is emitted by a separate check that asks the same question for the opposite purpose.
  - **`private` is not inherited, and that asymmetry is the whole design.** A subclass's scope is *outside* a private member's scope, so a private method of an ancestor fires from a subclass exactly as it does from anywhere else (`Call to private method A::m() from scope B`), while `protected` is inherited and stays silent from a subclass — and, in both directions, from a superclass's scope and from a sibling subclass's, which is what PHP itself allows. For a *property* or a *constant* the same asymmetry lands differently and the ids follow it: an ancestor's private property or constant reached through a subclass is `Undefined property: B::$p` / `Undefined constant B::K` — absence, a different consequence, and not these ids — while the inherited `protected` spelling of each is the inaccessibility fatal and fires.
  - **A `__call` / `__callStatic` / `__get` / `__set` anywhere in the chain is silence, and that leg is not a formality.** PHP routes an *inaccessible* member through the magic fallback exactly as it routes an undefined one: a class with a private `m()` and a `__call` prints `__call:m` and raises nothing at all, and the same holds for `__get` on an inaccessible read and `__set` on an inaccessible write. An ADR-0049 A14 `@method` / `@property` / `@mixin` tag in the class-like's reach declines the claim one door earlier, and the plugin lane is where a framework's real magic surface discharges it. Two exceptions are witnessed and honoured: a constructor is **not** rescued (`new C()` on a private `__construct` beside a `__call` is still the fatal), and a class constant has no magic fallback at all.
  - **The receiver must be exact, and the hierarchy fully enumerable.** `$this->m()`, `self::`, `static::` and `parent::` are silent, because the enclosing object's runtime class is only a lower bound and a descendant may both override the member publicly and carry a `__call` — both rescues are `php -r`-witnessed on the very same site. What fires is the reach the member checks already have: a `new`-typed receiver, an allocation-proven variable, and an explicit `C::m()` naming a static method. On top of that, an unresolvable or ambiguous ancestor, a `use`d trait anywhere in the chain (trait members are not flattened, so a public override could be hiding there), and a conditionally declared node under a live dynamism dam are each silence. There is no sidecar leg and no dam otherwise: these are positive claims about resolved declarations, and `eval` cannot reopen a declared class to widen a member's visibility.
  - **Four more shapes are silent, each because the evidence for the verdict is genuinely missing.** A closure body is never judged: a closure declared inside a class runs *in that class's scope*, and the analyzer does not thread the owner into a closure scope, so its "no class" would be read as the global scope and convict legal code. A PHP 8.4 hooked property is not judged either — a hooked declaration overrides an inherited one, and hooked members are not lowered, so the name is declined wherever it appears in the chain. `new` on an abstract class, an interface or an enum keeps its own `Cannot instantiate …` fatal rather than being renamed. And the first-class-callable form `$c->m(...)`, which PHP does refuse at closure-creation time, simply does not reach the checker yet.

- **Two new default-profile findings complete the absence family over the remaining member kinds: `property.undefined` and `class-const.undefined` (#197).** Reading a property no declaration in the receiver's hierarchy provides is `Warning: Undefined property: C::$nope` and evaluates to `null`; fetching a class constant nothing in the receiver's member reach provides is the fatal `Error: Undefined constant C::NOPE`. Both are breaking finding expansions for anyone with a green default-profile CI, on code that warns or fatals if it runs.
  - `property.notFound` is the single highest-volume identifier in the fourteen-application survey and Steins had neither id. They are two ids rather than one because only the warning demotes under a declared `warning-handler = "null"`, and an id has to demote whole or not at all.
  - **A declared property is silent however it is spelled** — plain, inherited, a promoted constructor parameter, `readonly`, `static`, or a PHP 8.4 **hooked** property, which binds no value and so is not lowered as a property at all but is declared all the same. A `private` property inherited from an ancestor is genuinely absent on the child at runtime, and is nonetheless treated as declared: the check under-fires there rather than reason about name mangling, which is also what keeps it disjoint from `property.inaccessible` at every site.
  - **The magic-property protocol is silence, and so is an open property set.** `__get`, `__set` or `__isset` anywhere in the chain declines the claim — only `__get` actually rescues a read, but a class declaring any of the three is running the protocol — as does `#[AllowDynamicProperties]` anywhere in the chain, `stdClass` and everything descending from it, and an ADR-0049 A14 `@property` / `@method` / `@mixin` tag in the class-like's reach. That last leg is what keeps the survey's Eloquent- and facade-shaped volume silent, and it is the leg a plugin pack discharges member by member.
  - **A property name written anywhere in the project takes that name off the surface.** Writing an undeclared property on a plain class is a deprecation, not an error, and the read that follows is clean — so any `$o->p = …` in the project means `$x = $o->p` elsewhere might be reading something real. A write through a computed name (`$o->$n = …`) could create any name at all and silences the id entirely. The typo shape the check exists for — `$user->emial` — is written nowhere and survives.
  - **Class constants have no magic channel at all, which makes them the cleanest member in the family**: a class carrying both `__get` and `__callStatic` still raises `Undefined constant`. What matters instead is the *reach*, which is wider than a method's — an interface constant answers through an implementor and through `interface B extends A`, an enum's **cases** answer in the same syntactic position as its constants, and a trait constant answers through the using class, so a `use`d trait anywhere is silence. `X::class` is excluded outright: it is a plain string since PHP 8.0 and errors on nothing, even for a class that does not exist.
  - **The receiver reach is the two lanes the member family already has.** An allocation-proven exact receiver fires; a receiver declared by a **native** type (`function f(C $c)`) fires under the stricter declared-receiver ladder, which adds descendant closure — a subclass could declare the property. `$this` is a lower bound and never fires. A receiver narrowed only by a docblock claim is **silent**: the method family routes such a claim to `phpdoc.undefined-method`, and the property family has no such twin registered, so a docblock-premised property absence gets no id rather than being routed onto the proof surface.
  - **Two shapes are named and deferred.** `C::$prop` on an undeclared *static* property is a fatal `Error` with a different consequence from the instance read, so it could not share the id and is not reported yet. And the write side (`property.dynamic-write`) is designed but unregistered: creating a dynamic property is a deprecation today and a fatal at PHP 9.0, and calling it proof while your own PHP tolerates it would be a claim about a runtime you are not running. The possibly-grade sibling `property.maybe-undefined` is registered ahead of emission at the `strict` floor so it is named rather than scoped out of existence.

- **Fetching a global constant nothing defines is now reported — `constant.undefined` (#198).** `echo TYPO_CONST;` is a fatal `Error: Undefined constant "TYPO_CONST"` in every PHP since 8.0, and it is now a default-profile proof-layer finding — a **breaking** finding expansion for anyone with a green CI, on code that would fatal if it ran. `X::CONST` is a *class* constant — a different member namespace, and not this id.
  - **A constant is silent if anything in the universe declares it, by either spelling.** A `const FOO = 1;` statement (resolved against its namespace, exactly like a function declaration) and a `define('FOO', 1)` call with a literal name (always an *absolute* name — inside `namespace App;` it declares the global `FOO`, not `App\FOO`) both count, in any file including `vendor/`. Conditionality is deliberately not recorded, so the ubiquitous `if (!defined('X')) { define('X', …); }` idiom resolves rather than reporting: the branch exists precisely so the constant ends up defined either way.
  - **A namespaced fetch falls back to the global namespace, through the same resolution a function call uses.** Inside `namespace App;` an unqualified `FOO` tries `App\FOO` and then the global `FOO`, and either one declaring it is silence; a *qualified* `Sub\FOO` and the `namespace\FOO` relative form get no fallback, as in PHP. `use const` imports are lowered and win outright over both candidates.
  - **Constants are case-sensitive, and only their namespace prefix is not.** With `namespace App; const LOCAL = 'l';`, PHP answers `defined('App\LOCAL')` and `defined('app\LOCAL')` true and `defined('App\local')` false, so that is exactly what the index key does. There is no version fork: the case-insensitive third argument to `define()` was removed in PHP 8.0 and the supported floor is 8.1.
  - **Everything the runtime provides is refuted by the runtime, never by a curated list.** An extension constant (`JSON_THROW_ON_ERROR`), an engine constant (`PHP_EOL`), and anything an already-loaded bootstrap defined are silent because the project's own PHP is asked, through a new `defined` sidecar method. The builtin catalog is not consulted at all — a constant missing from a curated list proves nothing about the engine actually running the project (ADR-0049 §1). With `--no-php`, no `php` on `PATH`, or a runtime-redefinition extension loaded, the check is silent entirely, like the rest of the absence family.
  - **A `define()` with a computed name dams the check universe-wide**, the constant-side twin of a runtime-minted `class_alias`: it can mint any name, so no absence claim survives it, in `vendor/` as much as anywhere else. It is the first dam kind with a *narrower* blast radius than the rest — it silences this id only, since `define()` cannot mint a function or a class, and `steins doctor` says so when one stands. Every other dam site (`eval`, an unproven include, an unparsable file) silences this id too. A dominating `defined('X')` guard needs no separate mechanism: the guard folds to `false` under the same closure the finding rests on, so its branch is already proven dead.

- **Reading a variable your code never binds anywhere in the scope is now reported — `variable.undefined` (#194).** `function f(): int { return $reuslt; }` warns at runtime (`Warning: Undefined variable $reuslt`) and quietly evaluates to `null`; the typo beside the `$result` you meant is exactly the shape this catches, and it is a **breaking** finding expansion for a green default-profile CI, on code that warns if it runs.
  - **The proof is closed-world over one scope's own text and needs no flow analysis.** The name must appear as **no** binding form at all — not a parameter (promoted constructor properties included), not an assignment target anywhere (compound, `list()`/array destructuring, an offset or property write), not a `global` or `static` declaration, not a closure `use` by value or by reference, not a `catch` binding, not a `foreach` key/value/by-ref binding, and not a by-reference out-parameter at a call whose target declares one.
  - **Deliberately ordering-blind, and that is the guarantee.** One binding form *anywhere* in the scope is silence — before the read, after it, or in a branch that never runs. So `$y = $x; $x = 1;` and a variable assigned on only some paths are both silent here: those are claims about which paths reach the read, and they belong to the sibling id `variable.maybe-undefined`, which is registered now (so a baseline entry and an `@steins-ignore` mean one fixed thing) but does not yet fire — it waits on the reachability foundation, and sits at the `strict` floor when it lands, since a partial-path guess is exactly the false positive the proof layer forbids.
  - **`isset($x)`, `empty($x)` and `$x ?? d` are not this finding.** PHP legalizes all three on an unbound variable, so they are excluded where reads are collected, along with `unset($x)` and any read the author already silenced with `@`. Whether a *pointless* guard deserves an id of its own is deferred entirely: mechanics there would be un-disableable against defensive house styles, so the shape gets measured before it gets a name.
  - **The closed world is what makes it sound, so every hole in it is silence.** A scope containing `extract`, `compact`, `get_defined_vars`, a variable variable (`$$x` / `${$x}`), `eval`, or any `include`/`require` reports nothing at all — each can mint or consume a binding without spelling it. Top-level script scopes never report, because `include` splices the *including* scope's whole symbol table into the included file (the template-partial idiom), and arrow-function bodies never report, because `fn () => $x` auto-captures every free variable it mentions. Superglobals, `$this`, `$GLOBALS` and `$http_response_header` are always bound. Warning-grade, so a declared `warning-handler = "null"` demotes it out of the proof surface exactly as it does `offset.missing`.
  - **Out-parameters count as bindings, resolved through the callee.** `preg_match($p, $s, $m); return $m;` is silent because the catalog's by-reference row for `preg_match` says position 2 is written, and `fill($z); return $z;` is silent when your own `function fill(&$out)` says so. Every call shape with no name to resolve — a method, static or dynamic call, a `new`, any named argument — binds its bare-variable arguments outright, and so does a function whose signature Steins cannot certify by value; only a certified by-value position (`strlen($s)`) leaves the read standing.

- **A method call or a property read on a value that is provably not an object is now reported — `call.on-non-object` and `property.on-non-object` (#190).** `$x = 1; $x->m();` is the exact same fatal `Error` that a `null` receiver raises, only with the runtime type in its place (`Call to a member function m() on int`), and `$y = $x->p;` raises `Warning: Attempt to read property "p" on int` and quietly evaluates to `null` — a **breaking** finding expansion for a green default-profile CI, on code that would fatal or warn if it ran.
  - Both fire on a receiver the value domain has proven to be an `int`, `string`, `float`, `bool` or `array` — a literal assignment, a native scalar parameter, a proven property, whatever already proved the null case.
  - **`call.on-null` is untouched.** Its id, its meaning and its sentence are exactly what they were, so a baseline entry or an `@steins-ignore call.on-null` still suppresses precisely the null receiver it always did: ADR-0022 makes an id a contract, and widening one in place would silently change what everyone's existing suppressions cover. The two ids are disjoint at every site. The property side has no such twin to defer to, so it owns the `null` receiver as well — PHP raises the same warning there.
  - **`?->` is not a licence to call a method on an int.** Nullsafe short-circuits on `null` and on nothing else, so `$x?->m()` on a proven non-null non-object is still the fatal, and is reported; `$x?->m()` on a proven `null` remains the legal form and stays silent.
  - **Only a *definite* non-object fires.** A receiver that might be an object — a `?Foo` parameter, an `int|Foo` union, a class the project cannot resolve — carries no value fact at all and is silence, as is a receiver narrowed only by a docblock claim (`@phpstan-assert`), and a nullable scalar (`?int`), which fatals under both arms but has no single type to name. The property check reads assignment and `return` operands, the same two positions `offset.missing` judges, and is warning-grade: a declared `warning-handler = "null"` demotes it exactly as it does `offset.missing`, while the fatal call side is never demoted.

- **A new proof-layer finding, `foreach.non-iterable`: a `foreach` subject proven a non-array scalar or `null` is reported, since PHP warns and skips the loop body entirely rather than running it (#192).** `foreach (42 as $v)`, `foreach ($s as $v)` where `$s` is a proven string, `foreach (true as $v)`/`foreach (false as $v)`, and `foreach (null as $v)` all fire, quoting PHP's own consequence verbatim (`php -r`-witnessed, 8.5.9): `foreach() argument must be of type array|object, {type} given`.
  - The `SourceTree::foreach_sites()` enumeration (ADR-0076) is reused rather than re-lowered, and the subject's value fact is read from the same env lane `offset.missing` does — a bare variable proven `Verified`, never an `Asserted` docblock claim.
  - **Every silence leg falls out of the same value-domain gate, with no special-casing per leg.** An array (a literal, a proven shape, an empty array) is iterable and never fires; a plain object stays silent too — object iteration over accessible properties is legal PHP, and neither a `Traversable`/`Generator` implementor nor a class whose hierarchy is not fully enumerable get a value-domain fact at all, so they are unproven by construction. An `iterable`-declared parameter contributes no fact either, and a `Maybe`/union-with-iterable/unknown subject (an unguarded parameter, a branch join mixing an array with a scalar) stays silent under the same default "Maybe ⇒ silence" floor the rest of this port wave uses.
  - Warning-grade, so it rides the same `warning-handler` gate `offset.missing` does (ADR-0049 §7): a declared `warning-handler = "null"` posture demotes it out of the proof surface, since the application tolerates the warning and continues.

- **Putting a value where PHP wants a string is now checked, in every context that does it — `"x $v"`, `echo $v`, `print $v`, `<?= $v ?>`, `(string) $v` and `'a' . $v` — under two new default-profile ids (#193).** `string.non-stringable` reports an object whose class has no reachable `__toString`, which is a fatal (`Error: Object of class App\Widget could not be converted to string`); `string.array-conversion` reports an array, which is `Warning: Array to string conversion` and yields the literal string `"Array"` (so `(string) [1,2,3]` is `"Array"` and `'x' . [1,2,3]` is `"xArray"`). Both are breaking finding expansions for anyone with a green default-profile CI, and they are two ids rather than one because only the warning demotes under a declared `warning-handler = "null"`.
  - **Every scalar stays silent, because every scalar is legal.** An `int`, a `float`, a `bool`, a `string` and `null` all convert totally and without a diagnostic — `"n=$n"` with `$n === null` is the empty string, by design — so a precisely-proven scalar in string context is never a finding, in any of the six contexts. `(int)`, `(array)`, `(bool)` and the other casts are not string contexts and are untouched.
  - **The object case is an absence proof and carries the whole absence ladder.** A class implementing `Stringable`, or declaring `__toString` anywhere up its `extends` chain, is legal and silent; so is a chain Steins cannot enumerate end to end — an unresolvable or ambiguous ancestor (which is exactly where an inherited `__toString` could be hiding), a builtin ancestor, any `use`d trait, an enum, and any `@method`/`@property`/`@mixin` docblock tag in the class's resolved reach. The receiver's class must be *exactly* known: a parameter typed `A` is a lower bound (a subclass may define `__toString`), and `$this` counts only in a `final` class. As with the rest of the family, `--no-php`, a missing `php` or a loaded monkey-patch extension keeps the id silent entirely.
  - **The array case is a value-domain fact and asks nothing.** It fires where the value is a *proven* array, so an `array|string` proves nothing and a docblock `@param array` is a claim rather than a proof and stays silent. A bare native `array $x` declaration is currently silent too — the array vocabulary is not yet part of the native type envelope — which is a known gap rather than a judgement.
  - **Where it looks:** expression statements, `return` operands, both `echo` forms, and an arrow function's body. Branch conditions, loop headers and `match` subjects are deliberately outside, the same position boundary the other value-reading checks carry.

- **A new proof-layer finding, `type.invalid-operand`: an operator whose operands the value domain has proven, applied to a pair PHP itself refuses with a `TypeError`, is now reported (#191).** `$a = []; $a + 1;` fires (`Unsupported operand types: array + int`), and so do `[]` in `- * / % ** & | ^ << >>` (`array - array` included — only `+` unions arrays), a proven string with no leading numeric prefix in any arithmetic or shift operator (`'abc' * 2`, `'' + 1`), unary `-`/`+` on an array or such a string, and `~` on a proven array, `bool` or `null` — a **breaking** finding expansion for a green default-profile CI, on code that would fatal if it ran.
  - One id covers binary, unary and comparison operators, and it reports **fatal rows only**: every row was `php -r`-witnessed at 8.5.9 with runtime variables, and the witness is recorded in the code beside the row it justifies.
  - **The survivors are the whole point, and each is pinned by a test.** `[] + []` is the array union; `'5' + 5` is `10`, as are `' 5' + 5`, `'5 ' + 5`, `'5.5' + 5` and `'017' + 5`; `null + 1`, `true + 1` and `1.5 + 1` are all legal; `'abc' & 'abc'` and `~'abc'` are the byte-wise **string** operators, not arithmetic; and `'5abc' + 1` merely raises `Warning: A non-numeric value encountered` and computes `6`, so it is warning-grade and not this id at any posture. Because every row is a fatal, the `warning-handler` posture never demotes this finding.
  - **Concatenation and every comparison are deliberately out.** `.` belongs to the string-context family (#193): array-in-concat is a warning, and an object without `__toString` is a different id's fatal. And `<`, `>`, `<=`, `>=`, `<=>`, `==`, `===` and their negations were witnessed legal for **every** operand pair, arrays and objects included (`[] < 1` is `false`), so PHPStan's `InvalidComparisonOperationRule` folds into this id with zero rows. `++`/`--` on an array is a real fatal but a mutation statement rather than an operand expression, and stays out of this version.
  - **Both operands must be proven, and an object operand is always silence.** A `Maybe` operand — an unguarded parameter, a branch join mixing an array with an int, a `?array`, a docblock-only `@phpstan-assert` claim — is silence, as is an abstract `string` whose *content* is unknown (only the content separates `'5' + 1` from `'abc' + 1`). Objects carry no value-domain fact at all, which is the correct posture rather than a limitation: PHP has no userland operator overloading, but internal classes like `GMP` do overload arithmetic, so a `$gmp + $gmp` is legal and stays quiet. No version fork is needed either — both moving boundaries became `TypeError` in PHP 8.0, below the 8.1 floor (ADR-0011).

- **Steins now has a reachability analysis, and its first findings are the pair `type.return-missing` and `type.return-maybe-missing`: a function, method or closure that declares a non-`void` return type and whose body runs off the end (#199).** `function name(): string { if ($this->user) { return $this->user->name; } }` is a fatal `TypeError` the moment the condition is false — `name(): Return value must be of type string, none returned` — and the default-profile half is a **breaking** finding expansion for anyone with a green CI, on code that would fatal if it ran.
  - Every function-like body now carries a terminality judgment covering `return`, `throw`, `exit`/`die`, `if`/`elseif`/`else`, `match`, `switch`, every loop form, `try`, `goto` and a call to a callee declared `: never`.
  - **The two ids are one consequence at two floors, and which one you get is the difference between "always" and "on one path".** `type.return-missing` (default profile) fires only where the body exits **nowhere** — an empty or stub body, a body of pure side effects, the `function (): bool {}` test double. Every call fatals. `type.return-maybe-missing` (`--profile strict`) fires where the body *does* return, throw or exit, just not on every path: a `switch` over a string with no `default` whose every case returns, an `if` with no `else`, a loop that returns on the first match. The escape edge is real, but it may be taken only for inputs the program never produces — phpstan-src's own `src/` carries two of exactly that shape and passes PHPStan's own missing-return rule. Same layer, same message ending, same fatal; only the floor differs, so the conditional class is named and addressable without putting it in front of everyone on a bare `steins check`.
  - **A declared return type is an obligation even when it accepts `null`.** `?int`, `int|string`, `mixed`, `array` and a class type all demand an explicit `return`; PHP does not quietly hand back `null` for any of them. Only `void` and a missing type declare no obligation, and `never` is excluded because falling off *its* end is a different fatal with a different sentence.
  - **Silence when the analysis cannot prove the body falls through — never a guess in the accusing direction.** A `try`/`catch` is excluded whole, because `finally` overwrites the exit point (`try { return 1; } finally { return 2; }` returns 2, witnessed on 8.5.9), and neither direction can be read off the blocks alone; a `goto` or a label is an unbounded jump; a `switch` whose case body runs into the next case is not modelled; an `include` can pull in code that exits the script. Each of these is undecided, and undecided means no finding. The mirror-image reading — a construct whose terminality is undecided is *not* terminal, so nothing after it may be called dead — is what the deferred level-4 dead-code family will read off the same judgment.
  - **The constructs that provably never reach the end are silent for the right reason, not by omission.** `while (true)` / `for (;;)` / `do … while (true)` with no `break` anywhere inside have no exit edge at all; a `match` with no `default` throws `\UnhandledMatchError` on no match, so every-arm-terminating proves the whole construct terminal; a `switch` with a `default` whose every case returns does too; and a call to a function or method declaring `: never` has no return edge, so `function g(): never { exit(1); } function f(): int { g(); }` is correctly silent. A generator body (anything containing `yield`), an abstract method, an interface method, a constructor and an arrow function are excluded by construction.

- **A new proof-layer finding, `call.printf-too-few-arguments`: a `printf`/`sprintf`/`fprintf`/`vprintf`/`vsprintf` call whose literal format string demands more placeholders than the call supplies (#188).** `printf('%s %s', 'one')` is a fatal `ArgumentCountError` in PHP 8 (`vprintf`/`vsprintf` instead raise a `ValueError` against the values array), and this is a **breaking** finding expansion for a green default-profile CI.
  - Proven only off a folded literal format string — a plain literal, a local variable proven to hold one, or a foldable concatenation, exactly as every other proof-layer fold consumer works. `%%` is not counted, `%1$s`-style positional references count by their maximum position rather than additively, and width/precision/flag runs (`%05.2f`, `%-10s`, `%'x10d`) parse correctly; an unrecognized conversion character or any other unparseable specifier leaves the whole format unproven, so the finding declines rather than guesses.
  - Passing *more* arguments than the format needs is never a finding, matching `call.too-few-arguments`'s asymmetry. `vprintf`/`vsprintf` report only against a values array proven to a concrete literal size; an array of unknown size stays silent. This is a distinct id from `call.too-few-arguments` because the evidence is the format string, not a resolved callee signature.

- **A `preg_*` call whose pattern your own PHP's PCRE cannot compile is now reported, quoting PCRE's own complaint — `preg.invalid-pattern` (#189).** `preg_match('/(unclosed/', $s)` warns and returns `false` at runtime, and every `preg_*` function that takes a pattern is covered — `preg_match`, `preg_match_all`, `preg_split`, `preg_grep` (which return `false`), and `preg_replace`, `preg_replace_callback`, `preg_replace_callback_array`, `preg_filter` (which return `null`) — including the array pattern forms, where each proven literal element is judged on its own and an unproven sibling stays silent. `preg_quote` takes text to escape, not a pattern, so it is not in the set.
  - **The refusal is your engine's, not Steins' reading of the pattern.** The pattern reader that types `$matches` decides only that the pattern *is* a proven literal worth asking about; the verdict comes from compiling it on the project's own PHP through the sidecar. So a pattern Steins' reader does not fully understand but PCRE compiles happily is never reported, and a refusal always carries the engine's own words (`Compilation failed: missing closing parenthesis at offset 9`, `Delimiter must not be alphanumeric, backslash, or NUL byte`, `Unknown modifier 'Z'`) under the name of the function at the call site. A pattern that compiles and then blows a *runtime* limit — `/(?R)/` — is not a compile refusal and is not reported.
  - **Without a PHP engine there is nothing to report.** `--no-php`, a missing `php`, a monkey-patch extension loaded, or a runtime outside the version range the project declares it supports each keep the check silent, like the rest of the family. The finding is warning-grade, so a declared `warning-handler = "null"` demotes it exactly as it does `offset.missing`. Each distinct pattern is compiled once per run however many call sites spell it, and an unproven pattern is never sent to the engine at all.

- **A new mechanics-layer id, `array.duplicate-key` (#187): a literal array expression that declares the same PHP-normalized key twice, silently dropping the earlier value.** `[1 => 'a', 1 => 'b']` fires; so does every PHP key-coercion pair — `[1 => 'a', '1' => 'b']`, `[true => 'a', 1 => 'b']`, `[null => 'a', '' => 'b']`, `[1.7 => 'a', 1 => 'b']` — and the auto-increment interplay, where an unkeyed element collides with an explicit one it lands on (`['a', 0 => 'b']`). This is a breaking finding expansion for any green CI with a literal array like this already committed.
  - The finding is positioned at the later (winning) occurrence and names the line of the earlier one it overwrites; a key the fold gate cannot pin — a variable, a call, a spread, and every unkeyed element after one of those, since its own auto-assigned position becomes unprovable too — is silently skipped rather than guessed, and `'01'` stays its own key, distinct from `1`/`'1'`.
  - Purely syntactic (no PHP sidecar needed) and mechanics-layer (ADR-0078), so it is on by default, disable-proof, and unaffected by `--no-php`.
  - **String keys are compared by their bytes, so a key that is not valid UTF-8 participates honestly.** `["\xC0" => 1, "\xD0" => 2]` is two distinct keys and is silent, while `["\xC0" => 1, "\xD0" => 2, "\xC0" => 3]` reports the repeat — and a literal that repeats a *genuine* `"\u{FFFD}"` is an ordinary duplicate rather than being passed over. This rests on the byte-string work below (ADR-0080), which retired the narrower replacement-character guard this check was first built with.

- **A PHP file that does not parse is no longer analysed in silence: `syntax.unparsable` names it, and `steins check` exits non-zero (#180).** A file `php -l` rejects used to reach exit 0 with nothing printed — the parser recovered, inference walked the recovered tree, and the operator was never told. Any project with a committed unparsable file goes red on upgrade.
  - The new mechanics-layer finding is emitted **once per broken file**, positioned at the first parse error, quoting the parser's own complaint and naming the count of further errors in that file (one per file, not one per error: recovery cascades make every position after the first a guess). Like the rest of the mechanics layer it is on by default, fail-level, disable-proof, undemotable and suppression-exempt — a file that does not parse is apparatus rot, not a style opinion, and the remedy is fixing the file.
  - **A broken file outside `vendor/` also silences the existence-absence family project-wide.** A recovery point is a place the world is not enumerated: it may have swallowed a `function` or a `class` declaration outright, and every absence proof rests on complete enumeration. So an unparsable first-party file joins the dynamism dam alongside `eval` and unproven includes — `call.undefined-function` and `class.undefined` go quiet everywhere until it is fixed, and `steins doctor` lists it among the dam sites. Sharper than the `eval` case in one direction: `eval` can mint a new name but cannot reopen a defined class, whereas a mangled class body can have lost methods, so the class-likes a broken file declares are also treated as member-incomplete and `call.undefined-method` declines through them (a class declared in a file that *does* parse keeps its method-absence findings, even with a broken sibling in the project).
  - **The broken file itself reports nothing else, and its recovered declarations still count as present.** A finding built on a misparse is a manufactured false positive, so no other id fires from a file that failed to parse. What survives recovery still enters the index as presence evidence — presence can only silence an absence claim, never raise one — so a class the recovery kept still resolves a `new` in another file instead of being reported missing. Under `vendor/` the existing dynamism presumption carries over verbatim: a broken vendor file is **not** a dam site and its classes are not member-incomplete (parser test suites ship deliberately broken PHP), and its `syntax.unparsable` finding rides the ordinary vendor filter — hidden by default, visible under `--vendor-diagnostics`.

- **Six new mechanics-layer findings report annotations that have drifted from the code they annotate — `phpdoc.unparsable`, `phpdoc.stale-param`, `phpdoc.stale-var`, `phpdoc.misplaced-var`, `phpdoc.throws-not-throwable` and `closure.unused-use` (#186).** They print on a bare `steins check`, and like every mechanics id no profile can disable or demote them, so this is a breaking change for anyone with a green CI and a rotted docblock.
  - What each one says: a `@param` / `@return` / `@var` / `@throws` whose type payload does not parse, so the tag declares nothing; a `@param $x` naming a parameter the signature does not have; a statement-level `@var $x` naming a variable that exists nowhere; a `@var` in a position where nothing can adopt it; a `@throws` naming a class that is not a `Throwable`; and a closure `use ($x)` the body never mentions.
  - **Every premise is textual — does the subject the tag names still exist — never an inference, which is what makes the family safe enough to be un-silenceable.** The bounded-tag-set discipline holds throughout: Steins reads a bounded tag vocabulary and drops tool-specific and unknown tags before any check sees them, so a vendor tag is never a finding however malformed — only rot *inside* the read set is.
  - **The silences are as deliberate as the findings.** A `@param`'s subject is the `$name` that follows the *type expression*, so the parameter names inside a `callable(Foo $f): bool $cb` type are never mistaken for it; a by-ref `@param int &$x` and a variadic `@param int ...$xs` name real parameters and parse cleanly; a line-wrapped `array{` shape is a limitation of the line-based docblock scanner, not rot, and never reports; a payload the parser rejects is `phpdoc.unparsable` alone and never also stale; a `@throws` on a class whose hierarchy Steins cannot fully enumerate is silence, since non-membership is provable only under closure; a by-ref `use (&$x)` is an out-channel and never fires; a mention of `$x` inside a nested closure — its body or its own `use` clause — counts as a use; and a scope holding `compact`, `extract`, `get_defined_vars`, `$$name`, `eval` or `include` can consume a name without spelling it, so it goes quiet.
  - **`@var` reuses the statement-adoption rule the inline-`@var` cast and `@psalm-trace` already use, rather than inventing a second one — and it reports Steins's own semantics, not another tool's.** The inline cast re-declares *the variable the tag names*, whatever the statement below it binds, so `/** @var Echo_ $echo */ $dnumber = $echo->exprs[0];` and a docblock naming several in-scope variables at once are both perfectly legal: `phpdoc.stale-var` fires only on a name that appears nowhere at all — a typo like `@var Echo_ $ecoh`. A comment in the gap breaks the adjacency exactly as it does for the cast; a bare `@var T` speaks about the statement's own binding; a `@var T $this->prop` speaks about a property, not the receiver; a `@var` over a `foreach` stays silent; and a property declaration's own `@var` is a legal position, never misplaced.
  - **A family prefix now spans two layers.** `phpdoc.*` carries both contract ids (`phpdoc.param-mismatch` and its siblings) and these mechanics ids. A `disable = ["phpdoc.*"]` or `warn = ["phpdoc.*"]` in a profile still removes or demotes the contract members and still cannot touch the mechanics ones — the layer decides, never the spelling.

- **A new contract-layer family answers "how much untyped surface do I still have, and where": `untyped.parameter`, `untyped.return`, `untyped.property`, `untyped.class-constant`, `untyped.iterable-value` and `untyped.generics` (#200).** A parameter, return, property or class constant with **no native type and no `@param`/`@return`/`@var`** reports; a native `array`/`iterable` whose docblock never states the value type reports `untyped.iterable-value`; and a docblock naming a class that declares `@template` parameters, written without type arguments, reports `untyped.generics`.
  - These are PHPStan's level-6 `missingType.*` rules, and level 6 is the level a large share of PHPStan shops actually target. All six sit at the **`contracts` floor**, so a bare `steins check` is byte-identical to before and the family is reached only by `--profile contracts` (or `strict`) — nothing here can turn a green default-profile CI red.
  - **The boundary is presence, not agreement.** A native type makes a declaration typed; so does a docblock claim of any provenance (`@param`, `@phpstan-param`, `@psalm-param`, and the `@return`/`@var` equivalents) — *including one that disagrees with the code*. An absent claim is declared debt, which is what the contract layer reports; a wrong claim is `phpdoc.*`'s finding, and always was. This is also why the family is deliberately not spelled `phpdoc.*`, and why it is not a lint rule: a missing type is information withheld, not a style opinion.
  - **Declaration reading only** — no inference, no receivers, no value domain, no PHP sidecar, so `--no-php` changes nothing. `array<T>`, `T[]`, `list<T>`, `iterable<T>` and array shapes all count as stating the value type, and a docblock that merely restates a bare `array` does not. A promoted constructor property is reported once, on the parameter, never twice. Enum cases are excluded (a case's type is its enum), `__construct`/`__destruct` are excluded from the return arm (PHP forbids a return type on either), and a `yield` body with no declared return **is** reported — `Generator` is a claim the code did not make. Traits, enum method signatures and closures/arrow functions are outside the family's reach in this release.

- **A new `steins.toml` key, `[runtime] final-keyword = "enforced" | "stripped"`, lets a project declare that the runtime it is analyzed for rewrites the `final` keyword away (#234).** Test code legitimately wants the type `FinalClass&MockObject`, and `dg/bypass-finals` makes it real: its stream wrapper strips `final` from the source as it loads, so under the test harness a mock subclass of a final class genuinely exists. Declaring `final-keyword = "stripped"` tells Steins that such an intersection is inhabited rather than empty; the default is `"enforced"` — PHP's own rule.
  - Its consumer is the intersection-receiver work below: a `FinalClass&MockObject` receiver is silent under the default because the type is provably empty, and reports members absent from both arms under `"stripped"`, where the mock subclass really does exist.
  - **It withdraws a proof; it never adds a claim.** `readonly` is untouched, deliberately: `dg/bypass-finals` strips `readonly` only when explicitly asked (`enable(bypassReadOnly: true)`), so the two stay separate here and `readonly.reassigned` reports identically under both postures. `class.extends-final` and `override.final` are untouched too — source that *spells* `extends FinalClass` is broken under a plain runtime whatever a test harness rewrites at load time. And nothing is inferred: a loaded `uopz`/`runkit7`, or a `dg/bypass-finals` sitting in `require-dev`, does not switch the posture on by itself.
  - **Project-wide in this version.** The library's own `denyPaths([...])` scoping has no equivalent yet; a path-scoped posture would key on ADR-0047 regions, which the check lane does not carry. `steins doctor` now prints both `[runtime]` postures — this one and `warning-handler` — with their value and whether it came from the file or from the default. As with `warning-handler`, an unrecognized *value* warns and falls back to the safe default, while an unrecognized *key* anywhere in `[runtime]` remains a hard config error (exit 2).

- **`$matches` now has a type: `preg_match` and `preg_match_all` teach the engine what they wrote through a by-reference argument, and the shape-changing `PREG_*` flags are modeled for both.** Inside `if (preg_match('/(\d+)-(\w)/', $s, $m))`, `$m[1]` is `numeric-string` and `$m[2]` is `non-empty-string` where both used to be unknown; the sealed shapes can newly report `offset.undeclared` for a key the pattern cannot produce and `offset.maybe-missing` for an unguarded read of a trailing-optional group on a `contracts`/`strict` run.
  - **The `preg_match` shape is exact and measured**: key `0` for the whole match plus one key per capture group in numeric order, a named group additionally under its own string key, and nothing else — a group that can be *trailing* unmatched is an optional key, while an interior unmatched group is required, because PHP drops the first from the array and writes `''` for the second.
  - **Capture entries carry sharper types than `string`, read off the sub-pattern that fills each one.** A sub-pattern that must consume a character is `non-empty-string`; one that must consume two — or spells enough literal text to need two — is `non-falsy-string`, since `''` and `'0'` are exactly the falsy strings; and one that can produce nothing but ASCII digits is `numeric-string`. Anything the reader cannot establish for *every* string a sub-pattern admits stays `string`, silently and with no finding. A middle optional group stays `string` however long its own sub-pattern is: an unmatched group with a populated entry after it is *present* as `''`, and only a group whose unmatched case is absence keeps the non-empty claim.
  - **A sub-pattern that spells out a small finite language types as the literal union itself**: `preg_match('/Price: (£|€)(\d+)/', $s, $m)` types `$m[1]` as `'£'|'€'`. The enumeration answers only where every atom is a literal with exactly one spelling — plain and escaped literal characters, alternations of them (`(foo|bar)` is `'foo'|'bar'`, an empty branch contributing `''` as a real member), nested groups (`(a(b))` types the outer entry `'ab'` and the inner `'b'`), `\Q…\E` runs, and zero-width assertions. Everything else declines silently, per group, to the refinement the entry already had: any quantifier inside the sub-pattern (`?`, `*`, `+`, `{n}`, `{n,m}` — including a fixed `{n}`), any character class (even `[ab]`), any set-denoting or code-point escape (`\d`, `.`, `\x{30}`), backreferences, unions past eight members, and — measured: `/(a)/i` on `'A'` captures `'A'`, so the pattern's spelling is not the language — the `i` modifier in any spelling. A group's *own* `?` keeps its body's union, since the entry holds the body whenever the group participates.
  - **`preg_match_all` gets the measured PATTERN_ORDER shape**: one always-present column per entry — key `0` plus each capture group, a named group beside its numeric twin — every column a `non-empty-list` on the truthy branch, since a truthy return is an int ≥ 1 and proves at least one match landed. Columns are padded, so a group that can go unmatched contributes `''` to its column wherever it sits and its element widens accordingly (a padded column is `non-empty-list<''|'a'>`); `PREG_SET_ORDER` instead types a `non-empty-list` of per-match arrays, each following exactly the `preg_match` success-shape rules.
  - **The flags argument is modeled rather than refused.** `PREG_UNMATCHED_AS_NULL` turns optionality into nullability: every group key becomes required and a can-go-unmatched group's entry gains `|null`. `PREG_OFFSET_CAPTURE` types every entry as its measured `[text, offset]` pair, with the offset floor `-1` exactly where an unmatched entry can be written and `0` everywhere else, and it carries a literal union inside the pair. Flags resolve by value — a literal int, or a bare `PREG_*` constant resolved to its engine value unless the project declares or imports a twin of that name — and anything else declines the whole seed silently: an unknown bit, an unproven variable, a `|` expression, or the invalid combination of both order bits.
  - **The fact holds only where the call proves it wrote.** A truthy result is that proof: `preg_match` returns `1` and assigns the success shape, `0` and assigns the empty array, and — on a pattern PCRE refuses to compile — `false`, leaving the variable holding whatever it held before. So the falsy branch, an unguarded call, and a result the code never tests all stay as untyped as before; `if (!preg_match(…)) { return; }` carries the fact past the guard. A comparison carries it too — `=== 1`, `1 === …`, `== 1`, and the early-return `!== 1` / `!= 1` all prove truthiness — while a comparison that admits a falsy result proves and seeds nothing: `=== 0`, `!== false`, the else branch of `=== 1`, and any comparison against a non-literal all decline. `@phpstan-assert-if-true` envelopes are deliberately **not** widened this way — `f($x) === 1` witnesses truthiness, not that the callee returned `true`.
  - **Everything unproven declines silently, with no finding of its own**: a computed or non-literal pattern, a pattern whose group structure the reader does not fully understand, a named or spread argument, and an out-parameter that is anything but a plain local variable — `$this->matches` and `$row['m']` are refused. Every other by-reference builtin (`sort`, `similar_text`, `str_replace`, …) is untouched.

- **`steins mcp` serves the transform loop to an AI agent over MCP on stdio — a new subcommand, four tools, and no change to any existing surface.**
  - The tools are `list_transforms`, `plan_transform`, `apply_plan`, and `check`. A plan call writes nothing and returns what `transform --format json` prints — the atomic edit plan, the completeness oracle's enumerated/transformed/refused counts, every refusal with its stable named reason, the dynamic-code obstacles, the post-check verdict — plus a unified diff per edited file and a `plan_handle`. `check` returns the findings `steins check` reports, each carrying its `fix` payload where a mechanical remedy exists, so an agent can apply one itself.
  - **Plan and apply are separate calls, and no tool does both**: the approval pause is the interaction model, so an agent that wants to skip it has no tool to do it with. `apply_plan` is the only tool that modifies the tree; it re-reads every target and refuses if the bytes moved since planning, then re-runs the same zero-new-diagnostics post-check `transform` runs, measured on the same surface that transform names.
  - **A plan handle is valid only inside the server process that produced it.** There is no daemon and no plan file. A handle from a restarted server, a second connection, or an apply that already consumed it comes back as a named error (`plan-handle-foreign-process`, `plan-handle-unknown`) rather than as a write against a tree nobody re-verified. Tool failures generally follow the transform-refusal discipline: a stable `reason` an agent can branch on, plus a human `detail`.
  - One deliberate difference from the command line: the `check` tool does not consult the baseline file, because an agent asking what is true about the code should not be answered through a CI ratchet. Vendor filtering, the profile surface, and inline `@steins-ignore` apply exactly as they do to `steins check`.

- **`steins check --fix` now removes committed `\PHPStan\dumpType()` / `\PHPStan\dumpPhpDocType()` statements — the first fix-it family.**
  - The `debug.type` and `debug.phpdoc-type` findings carry their remedy as a machine-readable payload: `--format json` shows a per-finding `fix` object (byte-span edits plus replacement) an agent or editor can apply directly, and findings without a fix carry no such key. `--fix` applies the payloads atomically, re-analyzes the project, and refuses to write with a named reason if any new diagnostic would surface; an applied fix is reported as fixed and no longer counts toward exit `1`. Without `--fix`, text output and exit codes are unchanged. `debug.var-dump` is deliberately not auto-fixed — deleting a legal `var_dump()` is a judgment call.

- **`steins transform throws-envelope` seeds `@throws` tags from proven escapes, so a repo can adopt the `throws-direct` and `contracts` profiles mechanically instead of hand-writing envelopes.**
  - It creates the docblock when there is none and extends an existing one by inserting whole lines before the closing `*/` — every pre-existing line is preserved byte for byte — and only ever writes escapes the engine *proves*: a declaration whose escapes are all `Maybe` is refused with `escape-not-proven`, never annotated. Running it twice is a no-op (`already-declared`), and like its siblings it is dry-run by default with `--apply` gated on the zero-new-diagnostics post-check.
  - Unlike its siblings, its post-check is measured on the default display surface rather than on every layer, because seeding an envelope is *meant* to move the contract surface: writing `@throws` onto an override gives its parent's narrower envelope something to be widened against, so `throw.liskov-widened` can appear on a `contracts` run after seeding. That is pre-existing debt the envelope exposes, not a regression. `phpdoc-to-native` and `phpdoc-honesty` are unchanged and still measured against every layer.

- **`steins transform loop-to-array-map` rewrites an append loop to `array_map`, but only where the engine proves the loop body cannot do anything.**
  - The precondition is a proven effect judgment, not a syntactic pattern: the body's proven effect lane must be empty on every label, every call in it must have resolved, and — a stricter bar than `#[\Steins\Pure]`, which admits `throw` — its proven throw set must be empty, because a body that throws on element *k* leaves the accumulator holding the first *k* results where the rewritten form leaves it unassigned. A declared `≤` effect bound is a cap rather than an occurrence proof and never qualifies.
  - Semantic parity is gated too: the subject must prove `array` and `is_list = Yes` (`array_map` preserves keys, the append renumbers `0..n-1`), the iteration variable must not be used after the loop, the accumulator must not be read inside it, and its `$out = [];` initializer must be the immediately preceding statement — the rewrite consumes both.
  - Every `foreach` in the analyzed set is enumerated and either rewritten or refused with one stable reason (`key-binding`, `reference-binding`, `value-binding-not-variable`, `subject-not-variable`, `subject-not-proven-array`, `subject-not-proven-list`, `accumulator-init-not-adjacent`, `accumulator-not-empty`, `accumulator-read-in-body`, `iteration-var-live-after`, `early-exit`, `body-not-single-append`, `body-effects`, `body-throws`, `body-call-unresolved`), so the refusal counts show how narrow this first version is rather than hiding it. Dry-run by default; `--apply` still holds the zero-new-diagnostics post-check.
  - **An opt-in flag, `--asserted-subjects` (off by default), admits a subject whose list-ness is *declared* rather than proven** — annotate `@param list<T>`, then transform. A subject whose declared type establishes **both** `array` and list-ness at the declared stratum (a docblock `list<T>`; also an inline `@var list<T>` cast) qualifies; a bare native `array $xs` still refuses `subject-not-proven-array` and a declared `array` / `array<K, V>` still refuses `subject-not-proven-list`. Each admitted site carries a trust label in its own report entry, in text, `--format json` (`report.asserted_admissions`), and the MCP `plan_transform` document (which gains a matching `asserted_subjects` boolean argument): the subject's list-ness is declared, not proven, and a wrong claim changes behavior — `array_map` preserves keys where the append renumbered them — which the post-check cannot catch. The completeness oracle stays exact and counts these sites separately (`transformed_asserted`), so proven yield and opted-in yield remain distinguishable.

- **Closure and arrow-function docblock `@return` declarations are now adopted and checked, at the body's return sites and at proven `$fn(...)` call sites.**
  - This is a breaking finding expansion for green `contracts` CI: `phpdoc.return-mismatch` can newly fire on closure bodies. A docblock is adopted from exactly two spellings — inline, immediately before the closure expression itself (`$f = /** @return string */ function () {…}`, inline wins when both are present), or above a simple `$f = <closure>;` assignment statement — while a closure passed directly as a call argument never adopts the statement's docblock. The adopted `@return` also refines the declared floor a `$fn(...)` result keeps when binding declines. Generators stay exempt from return checking, and `@param`/`@throws` on closures remain unread.

### Changed

- **`class.undefined` now reports a missing class-like wherever it actually breaks the program, not only at `new` and the static-access forms — a breaking finding expansion for anyone with a green default-profile CI (#182).** Three position groups join the four it already read: `extends` / `implements` / `use <Trait>` (a fatal at class load, including on an anonymous class's parent and interfaces); `catch (X $e)`, where a class that does not exist means the handler can never run and the code around a live `throw` is silently dead; and parameter, return and property native type declarations, which raise a `TypeError` on the first typed use. Nullable, union, intersection and DNF declarations report once per named arm, so `Widget|Gadget|int $w` reports twice.
  - **Nothing about the proof changed — only where it looks.** The same ladder decides every position: the name is absent from the project's class-like index (alias edges followed), absent from the builtin/extension hierarchy, the run's dynamism dam is clear, and the project's own PHP answers not-found through the sidecar. So the run stays silent for the same reasons it always did, at the new positions too — a `class_exists('X')` guard folds its branch dead at an `extends` exactly as it does at a `new`, and a run without the sidecar reports none of it.
  - **The verified non-breaks stay silent, and are now pinned as such.** `instanceof` evaluates `false`, `X::class` has been a plain string since PHP 8.0, `self` / `static` / `parent` and every built-in type keyword (`int`, `array`, `iterable`, `callable`, `mixed`, `never`, `void`, `null`, `false`, `true`, …) are not class references, and a docblock is a comment: `@param` / `@return` / `@var` naming a missing class remains a deferred contract-layer question, not this id. A `catch` clause whose caught type cannot be named statically contributes nothing at all — not even its resolvable arms.

- **An undefined method called on a natively-declared receiver now reports as `call.undefined-method` on the default profile, instead of `phpdoc.undefined-method` behind `--profile contracts` (#196).** `function stamp(Clock $clock) { return $clock->currentTime(); }` was already proven by Steins — the finding just sat on the contract layer, where a bare `steins check` never printed it. This is a **breaking** change for a green default-profile CI: findings that only ever appeared under `--profile contracts` now appear without it, on code that would fatal if it ran.
  - A native parameter declaration is enforced by PHP itself (the call passes a `Clock` or has already thrown a `TypeError`), so the absence is proof-grade evidence and belongs on the same id and the same surface as the exact-receiver case. Nothing about *when* the lane fires moved — the same ladder, the same silence legs, the same descendant closure, `final` immunity, `__call`, `@method`/`@property`/`@mixin`, dam and sidecar conditions decide it — only which id carries the result.
  - **The id follows the weakest premise the claim rests on.** A `@param`/`@var`-declared receiver, and a native declaration a docblock refines past (`@param A|SubB` over `A|B`), keep `phpdoc.undefined-method` on the contract layer exactly as before: one docblock-derived arm anywhere in the receiver's type is enough. A docblock that merely restates the native type costs nothing and stays on the proof id. No id was renamed, added or removed, so every existing baseline entry and `@steins-ignore` keeps meaning what it meant — but a suppression written against `phpdoc.undefined-method` for a natively-declared receiver now names the wrong id, and needs re-pointing at `call.undefined-method`.
  - **A lying docblock still cannot manufacture a proof.** `@param`, inline `@var` and `@phpstan-assert` claims are unverified premises by construction, so no combination of them produces the proof-layer id — the worst a wrong docblock can do is what it always did, report a contract violation at the contract layer.
  - **The declared type now also travels across a plain copy.** `$c = $o; $c->m();` on a declared `$o` reports where it used to be silent, carrying the declaration and its trust level to the copy unchanged. Property receivers (`$this->prop->m()`) and return-typed call receivers (`mk()->m()`) remain silent.

- **Intersection types are now consumed: a `Svc&Mock` receiver resolves its members, and a member on neither arm is reported (#238).** Until now a declared or narrowed intersection receiver reported nothing at all — not even a method that exists on neither arm — because the declared-receiver lane refused any arm that was not a single class. Both declared-receiver ids now read intersection arms, so `call.undefined-method` / `phpdoc.undefined-method` and `property.undefined` reach a surface they previously could not see. This is a **breaking** finding expansion for anyone with a green CI who types a parameter or property as `A&B`, in PHP 8.1's native spelling or in a docblock.
  - **Member lookup over an inhabited intersection is the union of the arms.** A method or property declared on *either* conjunct resolves and is silent; only a member absent from *all* of them fires, and then only when every conjunct clears the same ladder a lone class arm has to clear — full chain closure, full descendant closure, no `__call`/`__get`, no `@method`/`@property`/`@mixin`. One conjunct that cannot be closed — an unresolvable class, an open descendant set, a non-class arm such as `Foo&callable` — silences the whole receiver.
  - **`[runtime] final-keyword` gets its consumer here.** Under the default `"enforced"`, an intersection carrying a `final` arm that provably is-not-a another arm — the `FinalClass&MockObject` shape — is uninhabited, and a type no value can inhabit is not a receiver, so it is **silent**. Under a declared `"stripped"` the same intersection is inhabited and the ordinary either-arm rule applies. The posture only ever withdraws an emptiness proof; it never turns a resolvable member into a finding.
  - **PHPStan's array accessory predicates are now read as the array types they describe.** `non-empty-array<string, int>&hasOffset('foo')` and `hasOffsetValue('foo', 17)` are PHPStan's spelling for facts Steins' array vocabulary already carries — key presence, and the value at a key — so they lower to the corresponding unsealed shape (`non-empty-array{foo: int, ...<string, int>}`) instead of to a type nothing could judge. A predicate with no array type to attach to (`ArrayObject<int, string>&hasOffset(1)`, or one standing alone) stays unmodeled and, as before, decides nothing rather than being mistaken for a class name.

- **`class-string` is now a type Steins can say, judge, and print — it used to be a word it merely tolerated (#236).** `class-string`, `interface-string`, `trait-string` and `enum-string` all name one thing, "this string names a class-like", which is a property of the value rather than of where it came from, so it is now carried as a string refinement beside `non-empty-string` and `numeric-string` instead of being set aside as unjudgeable.
  - Three visible consequences: a declared `class-string` slot now **refutes** the strings PHP's identifier grammar rules out (`''`, `'0'`, `'123'`), which is a new `phpdoc.param-mismatch` / `phpdoc.return-mismatch` on the contract layer for anyone whose CI is green there; a `class-string` value now **satisfies** `string`, `non-empty-string` and `non-falsy-string` slots on proof rather than on a shrug; and every surface that prints a type — dumps, `steins transform` annotations, the types quoted inside finding messages — now writes `class-string` where it used to write `string` or nothing at all. The builtin function map declares it too, so a `get_class()` result carries the refinement into whatever reads it.
  - **Whether a name resolves to a real class is still never asserted.** `f('App\User')` against a `@param class-string` stays silent, exactly as before: the characters cannot tell you whether the class table has that entry, and Steins does not guess. The refinement is decidable in the refuting direction only, which is why the new reports are confined to strings no class-like could ever be called.
  - **`Foo::class` prints its own fully-qualified name, and `self`/`parent`/`static::class` print `class-string`.** The written form has been resolved to its FQN string since PHP 8.0 resolves it at compile time; the value surface now shows that. The relative three name a class-like whose *declared casing* Steins does not carry, so no literal may be printed for them — `class-string` is the claim that survives, and it is a real gain over the `unknown` they used to render.
  - **`class-string<T>` is carried as plain `class-string` for now.** The bound is dropped, which widens rather than misstates: every `class-string<Foo>` is a `class-string`. Type arguments belong to the generics work (#10) and land with it; `literal-string` and `callable-string` are untouched and stay unjudgeable, the first because it is a provenance claim rather than a value one.

- **A refined string now prints everything it knows about itself, and a `@param lowercase-string&non-empty-string` is finally read as the type it names (#240).** Steins has always *held* several string refinements at once — the value domain is a predicate set — but every surface that printed one picked a single keyword and threw the rest away, so a string proven both non-falsy and lowercase printed `non-falsy-string` and the casing half vanished.
  - Dumps, `steins transform` annotations and the types quoted inside finding messages now spell the whole set as one word, from a closed grid: a length/numeric rung (`non-empty-`, `non-falsy-`, `numeric-`, `non-falsy-numeric-`) followed by a casing rung (`lowercase-`, `uppercase-`, `uncased-`) — `non-falsy-lowercase-string`, `numeric-uppercase-string`, `non-falsy-numeric-string`, and so on. `uncased-string` is Steins' own word for a string with no cased character (PHPStan writes that set `lowercase-string&uppercase-string`), and every one of the twenty cells is read back by Steins' own phpdoc parser, so an annotation it writes it can re-read.
  - **Some of the new spellings are Steins vocabulary that PHPStan does not parse** — `uncased-`, and the `non-falsy-`/`numeric-` casing compounds. A docblock `steins transform` writes with one of them stays valid PHP and is understood by Steins, but PHPStan will read it as a class name.
  - **A declared intersection of string refinements is no longer dropped.** `@param lowercase-string&non-empty-string $s` used to reach *nothing* — the lowering had no intersection case, so the parameter kept whatever its native type said and the docblock's claim was silently unusable. It now folds to the single predicate set it denotes and narrows exactly as one keyword does, which can newly satisfy or newly contradict a declaration on the contract layer (`phpdoc.param-mismatch` and kin). Intersections the fold cannot take — anything with a `literal-string` arm, a class name, `callable` — behave exactly as before: the claim stays in the declared lane, and the value lane is untouched.
  - **No finding changed its rule, and nothing new fires on the proof layer.** This is vocabulary and seeding: what moved is which words a type prints in and which declarations reach the value lane. A refinement that arrives from a docblock is still `Asserted`, so it can never premise a proof-layer finding. The array-key-cast pair (`decimal-int-string`/`non-decimal-int-string`) is still deliberately not a rung, so a declared `decimal-int-string` still round-trips to a wider cell — now `numeric-uncased-string`, since a canonical decimal integer has no cased character.

- **A sealed array shape is written differently, everywhere Steins prints a type.** What Steins knows about these types has not changed at all — only how it spells them, so dumps, `@var`/`@param` annotations produced by `steins transform`, and the types quoted inside finding messages read differently for the same code.
  - **The key layout is spelled the way PHPStan spells it.** Keys exactly `0…n-1` with every one required print positionally — `list{string, int}` rather than `non-empty-list{string, int}`. Anything else prints every key, with `?` on the optional ones — `array{0: string, 1?: int}`, where a leading value used to be abbreviated. `non-empty-` comes off wherever a required key already proves it: `array{a: int}`, not `non-empty-array{a: int}`. And the empty array is `array{}`, not `list{}`.
  - **The head keyword states which type it actually is.** `array{…}` denotes an order-agnostic key *set* and `list{…}` a key *sequence*; Steins has always tracked which of the two it holds, and now says so: `list{…}` where the sequence is proven, `array{…}` everywhere else. So a declared `list{string, int}` prints as one — it is a narrower type than `array{0: string, 1: int}`, which also admits `[1 => 2, 0 => 'a']` — and re-reading anything Steins prints gives back the same type it printed. PHPStan's own writing does not draw this line; on the PHPStan test corpus that costs exact string agreement on the rows where it retains key order under an `array{…}` head, which the harness then reads as "narrower than asserted" rather than "identical". Unsealed shapes — the ones with a `…` tail — are untouched.
  - No finding appears or disappears from any of this, and no inferred type moved; only the sentences some findings print.

- **`array_slice` widening is sharper in two cases: slicing a proven list from offset `0` with `preserve_keys: true` still yields a list, and a slice whose length is a proven `0` is exactly the empty array.**
  - Unknown offsets, lengths, or flags and subjects not proven to be lists keep the previous conservative answer; a `null` length still means "to the end". The added precision can make downstream findings appear or disappear.

- **`array_values`, `array_keys`, and `array_reverse` over a proven list now carry exact types: `array_values(list{string, int})` is `list{string, int}` (identity), `array_keys` the literal `list{0, 1}`, `array_reverse` the reversed `list{int, string}`.**
  - The order consumed is a semantic guarantee, never a declaration artifact: a shape proves its list-ness only when every admitted value has keys `0..n-1` in that sequence, so an `array{…}` key-*set* subject keeps the previous widening exactly — `array_values(array{a: 1, b: 2})` still answers `non-empty-list<1|2>`.
  - On the unsealed forms, `array_values`/`array_reverse` keep the element identity with `non-empty-` preserved, and `array_keys(list<T>)` sharpens to `list<int<0, max>>` — a list's keys are never negative. A trailing-optional sequence keeps its key sequence (`array_keys(list{A, 1?: B})` is `list{0, 1?: 1}`), while `array_reverse` of any optional-length sequence keeps the previous widening, because reversing a variable-length sequence smears every position. The added precision can make downstream findings appear or disappear.

### Fixed

- **PHP strings are byte strings, and Steins now compares them as such: a literal holding invalid UTF-8 is no longer collapsed through a lossy decode that could forge equality between two distinct values (#208, ADR-0080).** Every string literal used to arrive in the value IR through `String::from_utf8_lossy`, so `"\xC0"` and `"\xD0"` became the same value — and equality on lowered string values is a proof premise, not a rendering detail.
  - **Findings move in both directions, each toward the truth.** A manufactured false positive disappears: `call.on-null` no longer fires on `$s = $c ? "\xC0" : "\xD0";` guarded by mutually exclusive `===` checks, where the forged identity had proven an impossible path live. A false negative starts firing: `$a["\xC0"]` read as `"\xD0"` is `offset.missing`, where the collapse had made the key look present. And `array.duplicate-key` compares byte keys honestly rather than passing over every replacement-character-bearing key.
  - **Where a byte string cannot yet be carried, Steins declines instead of guessing.** A fold over a non-UTF-8 argument goes silent rather than returning a wrong constant — `strlen("\xC0")` used to fold to `3` where PHP answers `1`, and `count(["\xC0" => 1, "\xD0" => 2])` to `1` where PHP answers `2`; both now fold to nothing, pending the deferred fold-wire work. A proven byte-string literal prints as its honest supertype (`string`) rather than a lossy spelling, and a shape carrying a non-UTF-8 key widens to its bare `array`/`list` keyword, so `steins annotate` and `PHPStan\dumpType()` never write a literal they cannot stand behind.
  - **A non-UTF-8 string quoted inside a finding message is spelled in PHP's own escape notation** (`"\xC0"`) instead of printing the U+FFFD replacement character.

- **The vendor filter now reads a project's own declared vendor directory instead of assuming the literal name `vendor` (#181).** A project whose `composer.json` sets `config.vendor-dir` — nextcloud vendors into `3rdparty/`, for instance — used to have every third-party finding under that directory reported as if it were the project's own code: 68% of nextcloud's contract findings were someone else's, from `aws-sdk-php`, `pear-core-minimal` and the rest.
  - `steins check` and `steins doctor` now resolve the vendor root from the nearest governing `composer.json` (walked upward from each analyzed path, and downward for a monorepo's subproject manifests), each analyzed root resolving its own; `--vendor-diagnostics` still reaches every suppressed finding, and the ADR-0079 parse-failure dam's vendor presumption follows the same resolved answer, so a broken file under a declared vendor directory is presumed harmless exactly as one under a literal `vendor/` always was.
  - **A new `steins.toml [paths] vendor-dirs` key covers the projects that have no Composer manifest at all.** Zero-config is unaffected: a project with a `composer.json` and no unusual `vendor-dir` resolves byte-identically to before, and a project with no `composer.json` keeps the literal `vendor` floor unless it opts into `[paths] vendor-dirs = ["3rdparty", "lib/vendor"]` — additive to the literal, never a replacement for it.
  - **Whole-path-component matching is preserved everywhere this lands.** `vendor_proj/` and `vendor.php` were never vendor and still are not; a declared or configured entry matches only a full path component (or, for a multi-segment entry like `lib/vendor`, that exact contiguous run of components), never a substring.

- **A directory symlink could make Steins analyze the same file twice, which dropped every declaration-dependent finding silently and doubled every flow-derived one (#179).** `collect_php_files`'s aggregate file list was sorted and deduped by path *string*, so a class-like reachable through two spellings of the same file (a direct path and one through a directory symlink) was declared twice.
  - The absence-family existence guard (ADR-0049) read that duplicated hierarchy as non-enumerable and dropped arity, undefined-method, and `class.undefined` findings with no diagnostic; a flow-derived finding such as `call.on-null` survived the duplication but was reported once per spelling instead of once. Files are now deduplicated by their canonicalized real identity, keeping whichever spelling was named first — argument order, then walk order — so a project with no symlinks sees byte-identical output.
  - The directory walk also gained a cycle guard: nothing previously stopped a self-referential directory symlink from recursing forever.

- **A `@param` that narrows its parameter's native type now takes effect: `@param non-empty-string $s` on a `string $s`, `@param positive-int $n` on an `int $n`, and every other refinement written over a native scalar were silently ignored (#242).** These are among the commonest annotations in typed PHP, and until now writing one changed nothing — the parameter was analyzed as a plain `string` or `int`, so anything the narrowed type would have decided went unreported. The same annotation written on an *untyped* parameter always worked, as did the array vocabulary (`@param array{a: int} $a` on an `array $a`), which is what made the loss easy to miss.
  - Refinements now reach every consumer that reads the parameter's value, and `PHPStan\dumpType($s)` reports `non-empty-string` where it used to report `string`.
  - **This can newly report findings on code that was green**, since a narrowed parameter can now contradict a declaration or an argument requirement it previously said nothing about — expect movement in the `phpdoc.*` family in either direction. It cannot report a *proof-layer* finding: a refinement that arrives from a docblock is a claim the runtime never checks, so it is graded `Asserted` and the proof layer refuses it (ADR-0037). A `@param positive-int` on an `int $n` that a caller passes `-1` to therefore still cannot manufacture a proof-layer claim, which is the whole point of the grade.
  - **A docblock still cannot widen past what the runtime enforces.** `@param int $v` on a `string $v` is a contradiction and is dropped exactly as before, in both directions; a `@param` that merely restates the native type does not re-grade the runtime-enforced fact down to a claim; and two shapes decline deliberately, because the narrowing would not be honest — a `@param int` on a `float $v` (PHP coerces the argument, so the value really is a float) and an implicitly nullable `string $v = null` (whose `null` the annotation does not mention).

- **A class that documents its runtime magic with `@method`, `@property`, `@property-read`, `@property-write` or `@mixin` no longer gets an undefined-method finding: those tags are now read, as obstacles to the absence proof (#195).**
  - `call.undefined-method` and `phpdoc.undefined-method` treat a class-like carrying any of these — or the `@phpstan-type` / `@phpstan-import-type` pair — the same way they already treat `__call`: the members live somewhere the index cannot enumerate, so the class-like is not enumerable and every absence claim over it is silence. The obstacle carries through the whole resolved reach: parents, interfaces, and `@mixin` targets followed transitively (a `@mixin` whose own target is a `@mixin` chains on, and a `@mixin` naming a class the project does not declare is the *most* obstructed case, never a finding). `phpdoc.undefined-method`'s descendant closure honours it too: a subclass of the declared type carrying a tag silences the arm.
  - **This direction only ever removes findings.** The tags are read for presence and subject — the method name, the property name, the mixin target — and never as member *sources*: `$model->scopeActive()` still resolves to no type, and no new finding can come of the tag. Their type expressions are not parsed at all, so an `@method` with generics or a callable signature obstructs exactly like a bare one.

- **The acceptance relation now decides list-ness from a shape's keys rather than from the keyword that spelled it, so two spellings of one denotation get one verdict.** `list<T>` accepts a sealed single-entry shape whatever keyword wrote it — `array{T}`, `array{0?: T}` — a positional `list{…}` acceptor accepts a sealed single-entry `array{…}` subject, and a sealed key-`0`-only shape spelled `array{…}` provably rejects the general `array` exactly as its `list{…}` twin always did.
  - The relation used to answer `Maybe` for `array{null}` under a `list<string|null>` or `list{string|null}` acceptor while answering `Yes` for the identical `list{null}`, and `Maybe` for `array{0?: int}` against `array` where `list{0?: int}` answered `No` — in every case because the verdict read the keyword rather than the keys. All of them are now routed to the domain's one denotational `is_list` judgment.
  - The unsound direction is unchanged: a subject that can realize two keys (`array{0: int, 1: int}`) or a gapped key set (optional keys below a required one) admits non-list members and stays `Maybe`. Sharpened verdicts feed contract comparison and arm deduplication, so results there can move — toward acceptance — where a positional `array{…}` spelling previously read as undecided.

- **Two array-shape spellings did not survive a round trip, so a type Steins itself printed could not be read back (#238).** `non-empty-array{a: int, ...<string, int>}` — an unsealed shape with a typed tail — was parsed under the *list* tail grammar, which has no key slot, and was rejected outright at the comma; only the `array{…}` spelling without the `non-empty-` prefix worked. In the other direction, a **list** shape with a typed tail was printed as `list{17, ...<int, int>}`, naming a key the list-shape grammar does not accept and a list does not need (its keys are `0..n-1` by definition); it now prints `list{17, ...<int>}`. Either defect silently cost anything that re-read a rendered type — `steins annotate` output, and the acceptance relation whenever one of these shapes stood on the expected side.

- **A by-reference write inside a comparison — `if (preg_match('/…/', $s, $matches) === 1)` — is no longer forgotten, so an earlier value of the written variable can no longer survive into the branch as a false fact.**
  - The same call one character away, tested directly rather than compared, always invalidated its by-reference arguments. Compared, it invalidated nothing: after `$matches = [];` the branch reported `$matches` as the *empty* array on the one path where PHP has provably written the match into it. Every comparison operator is affected, as are `f($x, $m) instanceof C`, a comparison inside `&&`/`||`/`!`, a ternary guard, and the non-call writers `$i++ === 5` and `($x = 2) === 2`. Facts that were only true because of the missing invalidation now widen, which can make findings appear in either direction; the strict offset leg loses a premise it should not have had.
  - **An operand that cannot write still forgets nothing.** A property or offset read, arithmetic and concatenation rebind nothing, so `$o->p === $s` keeps both variables' facts, and a variable a callee provably takes **by value** survives the comparison it is compared in exactly as it survives a plain call statement — `count($listA) === count($listB)` and `strlen($s) === 3` keep their subjects. A method receiver keeps its binding, as it does in guard position.

- **A guard call written `namespace\is_string($x)`, or one whose name a `use function … as …` alias binds elsewhere, no longer narrows as though it were the global builtin.**
  - Neither spelling reaches the builtin at runtime: inside `namespace App;`, `namespace\is_string($x)` resolves to `App\is_string` and nothing else — there is no global fallback, so an undefined one is a fatal error — and `use function Other\thing as is_string;` sends the bare call to `Other\thing`. Both were nevertheless recognized as the builtin by the whole guard vocabulary (`is_*`, strict `in_array`, `array_key_exists`/`key_exists`/`array_is_list`, `array_all`/`array_any`, the `*_exists` existence family) and by the `preg_match` out-parameter seed. They now decline, so a type narrowed on one of those guards widens and a finding the narrowing was suppressing can appear. The fully-qualified `\is_string($x)` and `\preg_match($p, $s, $m)` are unaffected — they denote the global function, and always did.

- **A generator function or method with a `@return \Generator` docblock no longer reports `phpdoc.return-mismatch` against its own `return` statements.**
  - A generator's declared return type names the `Generator` object the *call* produces; an in-body `return 42` is what `Generator::getReturn()` later hands back, and comparing the two is meaningless. The native `type.return-mismatch` leg has skipped generator bodies for some time and the closure `@return` leg skipped them from the day it landed, but functions and methods did not — and because the phpdoc check runs exactly where the native one stayed silent, `/** @return \Generator */ function g() { yield 1; return 42; }` reported a mismatch against a perfectly truthful annotation. Generator scopes are now exempt from `@return` checking on every owner. This can only remove findings.

- **A PHP sidecar that died and was replaced mid-run could leave a whole family of checks switched off for the rest of the run (#245).** The transport has always survived a child dying — a literal such as `str_repeat('abcdefghij', 1000000000)` exhausts the runner's memory limit, which is a PHP fatal no `catch` can see, and the child is replaced on the next request. What did not survive was the handful of answers derived from a single `env()` reply and memoized for the whole run, the absence-proof family's availability among them: taken in the window where the child was down, they memoized "unanswerable" and stayed there long after the sidecar was healthy again, so existence findings went quiet for reasons nothing in the output explained. Those answers are now re-taken once per replacement — at most once per respawn, never once per call site, so a genuinely unresponsive sidecar still costs one timeout rather than thousands.

## [0.1.3] - 2026-08-02

Two investments pay off this release. Effects grow real teeth — PDO calls, project-interface envelopes, and Composer-plugin declarations all now contribute to the `effect.*` family, and `steins effect-diff` gives CI a channel of its own for tracking them independently of the diagnostic baseline. And exact values travel much further: project functions, methods, and closures now propagate their proven return value into dumps, nested calls, and argument positions rather than only direct assignments, and a matching growth in the builtin-fold allowlist and its constant-union handling lets more of that precision actually reach a finding.

Alongside that: a browser playground runs Steins entirely client-side, array and shape facts are checked against phpdoc contracts for the first time, inline `@var` casts and `@psalm-trace`/`@phpstan-trace` annotations both gained a seam into the analyzer, and a run of bugs found while writing the user manual against the 0.1.2 binary — a profile `warn` that could demote a mechanics diagnostic, a debug baseline entry that outlived its capture exemption, a sidecar that could go silent mid-run without saying so — are closed. This is still a preview, so the `0.1.x` series continues rather than jumping a minor. **Several of these entries change what your CI reports, in both directions** — read them, not the version number, to know what moves.

### Added

- **A browser playground now runs Steins entirely in-browser with live findings, an `annotate` overlay, profile selection, and themes.**
  - The default remains the no-PHP sound subset; an off-by-default PHP 8.5 engine can be loaded to enable the absence family, reflected return types, and folding for the 32-bit-safe subset of the builtin allowlist, while failed or non-converging engine runs fall back to the sound subset rather than showing partial results.
- **`PHP_VERSION_ID` comparisons now prune branches that cannot run on any PHP version supported by the project.**
  - Findings such as `call.undefined-function` can disappear from compatibility branches that the declared PHP range proves dead; ranges that straddle a comparison keep both branches, and user-defined or imported constants with the same name disable the fold.
- **String concatenation now participates in value inference across assignments, returns, and builtin-fold arguments.**
  - Resolved string, integer, boolean, and null operands can produce exact strings, so downstream findings can appear or disappear where concatenation previously widened to `unknown`; float stringification remains runtime-dependent and is not guessed.
- **A project function's exact return value now resolves in any value position — direct assignment, `dumpType()`, nested arguments, nested calls, and more.**
  - Exact returns can expose findings such as `type.argument-mismatch`; calls that cannot be summarized retain their declared return floor, and recursion or depth exhaustion declines conservatively. The summary walk accounts for returns inside `foreach` and `try` coverage and for nullable fallthrough, so it does not pin an exact value where the function's real range is wider.
- **Statically resolved PDO calls now contribute the `io.db` effect and propagate it through proven call chains.**
  - `effect.envelope-exceeded` can begin firing when `PDO::query`, `PDO::exec`, `PDO::prepare`, `PDOStatement::execute`, `PDOStatement::fetch`, or `PDOStatement::fetchAll` violates a proven effect envelope; unresolved receivers remain conservative.
- **Calls through project-interface types now preserve their declared effect envelopes in caller summaries.**
  - Declared effects are rendered with `≤` and included separately in JSON, but they remain non-proven and cannot by themselves create `effect.envelope-exceeded` or `effect.liskov-widened` findings.
- **`steins effect-diff` now records and reports function-level effect changes independently of the diagnostic baseline.**
  - `--set-baseline` writes `steins-effects-baseline.json`, later runs distinguish proven, declared, materialized, possibly removed, and exhaustiveness changes, `--format json` exposes the same events, and the command always exits `0` so CI policy remains the caller's decision.
- **Composer packages of type `steins-plugin` can now register namespaced effect labels and declared function effects without executing PHP.**
  - Plugin declarations can remove `effect.unknown-label` for registered labels but never become proven facts or manufacture proof findings; labels are restricted to the package's Composer vendor namespace or a core taxonomy root, and `[plugins].allow` can replace automatic discovery with an exact allowlist.
- **When PHP cannot answer, Steins now falls back to catalogued builtin return declarations instead of treating every builtin result as `unknown`.**
  - These facts are asserted rather than proven, so `phpdoc.param-mismatch` and `phpdoc.return-mismatch` can newly appear in `contracts` runs using `--no-php` or a runtime missing an extension, while proof-layer and absence findings cannot be created by the fallback.
- **Array read-position builtins now derive their return types from known array shapes.**
  - `current`, `reset`, `end`, `next`, `prev`, `key`, `array_pop`, `array_shift`, `array_first`, and `array_last` include the appropriate element, key, `false`, or `null` arms, so downstream findings can appear or disappear; mutating by-reference calls still invalidate the source array afterward.
- **Common string builtins now preserve or establish casing, non-empty, non-falsy, and length refinements.**
  - The certified rules cover 25 functions including `trim`, `strtolower`, `strtoupper`, `strrev`, `str_repeat`, `implode`, `str_pad`, escaping and encoding helpers, and `strlen`; asserted inputs can newly affect contract findings, while proven inputs can become new proof-layer premises.
- **The executable builtin-fold allowlist now covers 46 verified functions.**
  - Newly folded names include `ucwords`, both supported `strtr` forms, `preg_quote`, `addslashes`, URL and Base64 codecs, `str_increment`, `str_decrement`, `str_pad`, `substr_replace`, `str_starts_with`, `str_contains`, `str_ends_with`, and `gettype`; `dechex`, `decbin`, `decoct`, `bindec`, `hexdec`, and `version_compare` remain 64-bit-only, and exact results can make findings appear or disappear.
- **Builtin folding now distributes over small unions of constant arguments and joins the exact results.**
  - Steins evaluates at most four possibilities per argument and sixteen combinations overall, declines the entire fold rather than truncating an unanswerable union, preserves asserted provenance, and can newly expose proof findings when every proven possibility yields a decisive result.
- **Strict equality and inequality guards now remove exactly excluded literal arms and narrow representable integer-range endpoints.**
  - `$x !== false` can remove a literal `false` arm, `$x !== 0` can narrow `int<0, max>` to `int<1, max>`, and equivalent Yoda, negated, `&&`, and `||` forms agree; general booleans and interior range points remain unchanged when the remainder cannot be represented safely, while the added precision can change downstream findings.
- **Abstract array and shape facts now participate in `@param` and `@return` compatibility checks.**
  - This is a breaking finding expansion for green `contracts` CI: `phpdoc.param-mismatch` and `phpdoc.return-mismatch` can newly appear when every possible array value violates the declaration, while unknown keys, elements, listness, or a compatible union arm remain silent.
- **`min` and `max` now infer their return types from their arguments.**
  - Integer bounds compose into ranges, non-integer calls return the union of possible arguments, and asserted inputs remain contract-only; more precise proven results can make downstream findings appear or disappear.
- **`array_slice` now preserves element types and computes exact slices of observed arrays.**
  - `preserve_keys: true` or an unknown flag conservatively drops listness, a possibly empty slice remains possibly empty, and declared shapes widen because declaration order does not prove runtime order.
- **Statement-level inline `@var` annotations now reseed a variable with the same asserted type information as a declared parameter.**
  - The cast replaces the previous fact from that statement onward, so `phpdoc.param-mismatch`, `phpdoc.return-mismatch`, `phpdoc.undefined-method`, and strict-profile `offset.undeclared` findings can newly appear; property-target tags and tags immediately above assignment to the same variable remain conservative.
- **`@psalm-trace` and `@phpstan-trace` annotations now emit exit-neutral `debug.trace` reports using the same facts as `dumpType()`.**
  - A trace applies after the next covered statement, may name multiple comma-separated variables in source order, appears in every profile, cannot be suppressed, and never changes the command's exit status.
- **Project method and static-call return summaries now rebind assignments and returns with the same precision as free-function summaries.**
  - Constructors and method calls in argument position remain outside this slice, while newly precise method results can cause `contracts` or `strict` findings to appear where only the declared return envelope was previously available.
- **Closures now check native return declarations and propagate exact `$fn(...)` results through the ordinary return-summary path.**
  - Invalid closure and arrow-function returns can newly emit `type.return-mismatch`, rebound results can expose downstream findings, generators remain exempt from ordinary return checking, and closure phpdoc `@return` declarations are not yet imported.
- **Foldable builtins now consume exact return values proven by nested project calls.**
  - Calls such as `strtoupper(g(1))` can fold when `g` proves a singleton string, making proof or contract findings appear where the argument previously widened; shadowed builtins, conditional declarations, non-singleton returns, recursion, and budget exhaustion still decline.

### Changed

- **Version-sensitive analysis now follows the PHP range declared by the project instead of blindly trusting the local runtime.**
  - `config.platform.php` takes precedence over `require.php`; runtime/target skew can suppress the absence family (`call.undefined-function`, `class.undefined`, guarded `call.undefined-method`) and reflection-derived refinements, ranges spanning PHP 8.3 leave affected negative-key arrays unknown, and `steins doctor` reports the target, source, runtime, and consequences.
- **Facts now survive calls proven to receive scalar, string, or array arguments by value.**
  - This is a breaking finding expansion for green CI: proof findings, especially `type.argument-mismatch`, can appear after calls that previously erased the relevant fact; by-reference, unresolved, dynamic, named, spread, object, and value-tracking-defeating cases remain conservative, `array_slice` is certified as by-value, and `array_splice` is not.
- **Integer unions now normalize and render as canonical PHPStan-style ranges when their denotation is exactly contiguous.**
  - Adjacent literals and intervals merge without bridging gaps, so dumps and type text may change from spellings such as `positive-int|0` to `int<0, max>` without changing finding ids or counts by presentation alone.

### Fixed

- **Typed `float` properties now record the float value PHP actually stores when assigned an integer.**
  - This removes a demonstrated proof-layer false positive in which the wrong integer fact selected a dead branch and produced a false `call.on-null`; promoted properties and literal defaults follow the same conversion, while mode-dependent coercions still widen.
- **Multibyte method names no longer crash reflection-site analysis.**
  - Non-ASCII names are no longer byte-sliced at invalid character boundaries and are simply excluded from the ASCII `invoke*` and `newInstance*` classification when they do not match.
- **Integer literals beyond `PHP_INT_MAX` now follow PHP's float promotion instead of wrapping to the wrong signed value.**
  - Decimal, hexadecimal, binary, octal, legacy-octal, and underscored spellings no longer seed false integer facts, and unrepresentable float array keys widen rather than inventing a key, so findings based on the former wrapped value can disappear or change.
- **An array argument PHP cannot reconstruct no longer kills the resident folding runner.**
  - The affected fold widens while later requests continue, so later exact results and their findings are no longer silently lost.
- **A memory-exhausting fold no longer disables folding for the rest of the run.**
  - The failing request widens without retry, the bounded PHP child is restarted for later requests with a restart cap, and restored later results can cause findings that were previously lost after the failure to appear.
- **`check`, `transform`, and `doctor` now reject nonexistent input paths with exit `2`, and `doctor` no longer walks the filesystem indefinitely for such a path.**
  - This is a breaking exit-code correction for CI with stale or mistyped paths; all missing paths are reported together, no JSON success document is emitted, and an existing path containing no PHP files remains a successful no-op. `effect-diff`, new in this release, rejects a nonexistent path the same way from the start.
- **Type dumps now render builtin classes using the casing declared by PHP.**
  - Names such as `GMP`, `HashContext`, `XMLParser`, and `DateInterval` now match PHP's declarations, with no finding added, removed, or re-identified.
- **Dump and assertion calls now preserve the facts of variables they read.**
  - Repeated `PHPStan\dumpType`, `dumpPhpDocType`, `var_dump`, and harness assertions no longer turn later reads into `unknown`; retained facts can make subsequent findings appear or disappear.
- **A profile's `warn` can no longer demote a mechanics diagnostic, and `--set-baseline` no longer captures the debug layer.**
  - This is a breaking correction for a green CI that depended on either gap: a `warn` pattern matching `suppress.*` or `effect.unknown-label` no longer turns those ids into exit-neutral warnings, and a committed `PHPStan\dumpType()` frozen into an existing baseline starts failing again — a leftover `debug.*` baseline entry is now reported as stale instead of suppressing the dump. `steins doctor` also names the contract layer under the `throws-direct` profile, which it previously omitted from its surface line.
- **`check` and `annotate` now report the degraded posture when the PHP sidecar spawns but a request goes unanswered — at startup or partway through the run.**
  - A `php` that starts and then fails to answer a request — a wrapper script that never execs PHP, a configuration that hangs on startup, or a child that answers fine at first and then stops — previously produced a run that looked complete while the affected fold silently widened. One stderr notice per run now names the case, on the first occurrence regardless of when it happens, and points at `steins doctor`; findings, exit codes, and the sound-subset behavior itself are unchanged.

## [0.1.2] - 2026-07-30

Steins learns arrays. Until now an array was a fact only when every one of its elements was already known, which meant a `@param array{id: int, name?: string}` told the analyzer nothing it could use. This release makes the shape itself a fact — which keys are present, which are optional, whether it is a list, what each slot holds — carried through reads, `isset`/`array_key_exists`/`??` guards, writes, and the array builtins. Two new offset diagnostics and a fourth built-in profile, `strict`, are built on it.

Around that: guard narrowing over the `is_*` family and strict `in_array()`, a handful more builtins whose result is carried forward, a much wider set of phpdoc type spellings that are now *checked* rather than merely parsed, and the two conditional-purity tags. This is still a preview, so the `0.1.x` series continues rather than jumping a minor — read the entries, not the version number. **Several of these change what your CI reports, in both directions**: claims that were always true and merely withheld can start firing, and a phpdoc type that names a class shadowing a pseudo-type stops being misread.

### Added

- **Array shapes are a fact Steins carries, not just a spelling it parses.** `array{a: int, b?: string}`, `list{int, string}`, `list<T>`, `non-empty-list<T>`, `array<K, V>` and `T[]` in phpdoc are read, propagated through the function body, and printed back in the same vocabulary by `annotate` and `dumpType()`. A read of `$row['id']` answers from the declared shape instead of widening to silence, so everything downstream of that read — argument checks, return checks, contract checks — has something to work with for the first time.
  - **Guards narrow a shape and writes update it.** `isset($a['k'])`, `array_key_exists('k', $a)`, `!empty($a['k'])` and `$a['k'] ?? $default` each promote an optional key to present on the branch where they hold, and subtract it on the branch where they do not; a disjunction of guards (`array_key_exists('a', $x) || array_key_exists('b', $x)`) records the disjunctive fact rather than dropping to nothing. An assignment `$a['k'] = …` adds the key; a write Steins cannot follow widens the shape rather than keeping a stale one.
  - **Array builtins project through the shape.** `count()` and `array_is_list()` answer from it; `array_values()`, `array_keys()`, `array_flip()`, `array_reverse()`, `array_key_first()` and `array_key_last()` produce the projected shape; `array_all()` and `array_any()` carry the non-emptiness legs, pinned on both vacuous cases. `array_slice()` is deliberately not among them — its offset and length arguments govern the result's key structure, and a shape-only answer would say no more than the reflected `array` envelope already does.
  - **Declaration order is never trusted.** Where a result depends on the order of an array's keys, Steins computes it only over a value whose order it actually witnessed, and takes the sound widening over a shape that merely *declares* its keys in some order. This is a deliberate divergence from PHPStan, which reads declaration order as runtime order and reports a real false-positive class from it (`phpstan/phpstan#14940`); it is registered in [`docs/type-specification/divergence-registry.md`](docs/type-specification/divergence-registry.md) along with the two others this work added.
  - **This can surface findings that were not firing before.** Knowing what an array holds is exactly what lets an argument, return or property check reach a verdict it previously declined; a green run may go red on claims that were always true. Nothing here is a guess — a key Steins cannot prove present stays unproven, and an unprovable element widens the whole shape.
- **`offset.undeclared`** — a read of a key the declared shape proves is not there. Contract layer, on the `contracts` surface and above. It reached that surface by measurement rather than by argument: a sweep over 99,522 files of clean corpus code produced **zero** findings before it was promoted off the strict rung.
- **`offset.maybe-missing`** — a read of a key the declared shape says is *optional*, with no guard on the path discharging it. On the `strict` surface only, because its corpus sweep found three findings and all three were one discharge gap rather than three real defects; it is not promoted until the ladder covers that case.
- **A fourth built-in profile, `strict`.** `steins check --profile strict` is `contracts` plus the strict-floor ids. Profile selection is now a strictly cumulative rung ladder — `default ⊂ contracts ⊂ strict`, with `throws-direct` sitting beside it as `default` plus one faceted id — and every diagnostic id carries the lowest rung that admits it, which is what lets a single layer hold ids at two rungs. `strict` was a reserved name in 0.1.1 and is now selectable and extendable (`extends = "strict"`); `boundary` stays reserved. The `default`, `contracts` and `throws-direct` surfaces are unchanged, id for id.
- **Guard narrowing over the `is_*` family and strict `in_array()`.** `is_int`, `is_integer`, `is_long`, `is_float`, `is_double`, `is_string`, `is_bool`, `is_array`, `is_object`, `is_null`, `is_numeric`, `is_scalar`, `is_callable` and `is_iterable` narrow on both polarities, as does `in_array($x, [...], true)` against a literal list. A fact the guard *refutes* is dropped rather than carried on, which is the case a one-sided implementation gets wrong.
  - This is the largest single source of newly-surfaced true positives in the release: on one 85,000-file codebase it moved the contract-layer count by ten, every one of them a request-parameter claim that was true and previously withheld.
- **More builtins carry their answer forward** — `explode()`, `range()`, `var_export()`, `preg_replace()`, `get_debug_type()` and `spl_object_hash()` now produce a usable fact about their result instead of widening. `json_decode()` and `dirname()` were deliberately **refused** rather than approximated, with the counterexamples recorded beside the rows that were accepted.
- **A much wider phpdoc vocabulary is enforced, not merely accepted.** `lowercase-string`, `uppercase-string`, `non-empty-lowercase-string`, `non-empty-uppercase-string`, `decimal-int-string`, `non-decimal-int-string`, `non-null-mixed`, `non-empty-mixed`, `non-empty-scalar`, `associative-array`, `non-zero-int`, `number`, `key-of<…>` and `value-of<…>` constrained nothing in 0.1.1 — `lowercase-string`, `uppercase-string`, `key-of` and `value-of` were recognized and then treated as opaque, and the rest were not in the vocabulary at all and fell through to being read as a class name. Each is now a checked refinement, so a value that violates one is a finding where before it was a silence. No spelling was removed or re-read: `numeric-int-string` and the rest of the opaque string family are exactly as they were. The casing pair is the identity `strtolower($s) === $s` (so an uncased string satisfies both), and `decimal-int-string` is the engine's own array-key-cast rule rather than an imitation of it: `'123'` becomes an int key, `'007'`, `'+1'`, `'-0'` and anything past `PHP_INT_MAX` do not. Each spelling's exact reading, including where Steins deliberately decides one PHPStan leaves open, is in [`docs/type-specification/contract-types.md`](docs/type-specification/contract-types.md).
- **The two conditional-purity tags are read** — `@pure-unless-callable-is-impure $callback` makes a function's effect the join of the callables actually bound at the flagged positions, and `@pure-unless-parameter-passed $matches` declares a userland by-ref out-parameter that is colored by its argument at each call site. Bare or `@phpstan-`-prefixed, in the spelling merged upstream in `phpstan/phpdoc-parser` 2.3.3. The unconditional `@phpstan-pure` and `@phpstan-impure` stay unread on purpose: Steins spells unconditional purity `#[\Steins\Pure]`, where inference can check it rather than take it on trust.
- **`mutate.local`** — a new effect label for a by-ref write whose target is a binding of the *calling* frame (`preg_match($p, $s, $matches)`, `sort($localRows)`). Nothing escapes the frame, so no caller can observe it, and every envelope tolerates it — `#[\Steins\Pure]` included. The label is decided per call site from the argument's lvalue root: a frame-private binding earns `mutate.local`, a superglobal earns `global.write`, and a property, static property or unclassifiable target earns the conservative parent `mutate`.
- **A `callable` position can carry a purity obligation**, checked against the closure actually bound there rather than assumed.
- **Your own assertion helpers discharge a guard.** A call to a userland function carrying `@phpstan-assert` / `@phpstan-assert-if-true` / `@phpstan-assert-if-false` (or the `@psalm-` spellings) now discharges the obligation at the call site, so wrapping `isset()` in a helper no longer loses the proof that the direct call would have kept. This closed the only `offset.maybe-missing` residue the corpus sweep found — three findings, all one gap, now zero.

### Changed

- **A phpdoc type naming a class that shadows a pseudo-type now resolves to the class.** PHP reserves its native type words, so `int`, `string`, `bool`, `callable`, `iterable` and the rest can never be a class name and the keyword always wins. Every *other* spelling Steins knows — `integer`, `boolean`, `double`, `numeric`, `scalar`, `closure` — is a legal PHP class name, and 0.1.1 read it as the pseudo-type unconditionally. A project with its own `Integer` or `Scalar` class had every `@param Integer $x` misread as `int`, which is a contract-layer verdict about the wrong type entirely. Hyphenated keywords (`positive-int`, `non-empty-string`) are not legal identifiers, so nothing can shadow them and they are unaffected.
- **A baseline entry may record the profile rung it was captured at.** The entry gains an optional `"surface"` field, and an entry counts as unmatched only on a run whose rung is at or above its own — so a `strict` capture does not read as stale on a `contracts` run. The field is omitted entirely at the `default` rung, which makes a `default`-captured baseline **byte-identical** to one 0.1.1 wrote, and an entry with no tag (or an unrecognized one) reads as captured at `default`, where the rung clause is vacuous and staleness is decided by the id alone exactly as before. Existing baseline files keep working unchanged and do not need recapturing.

## [0.1.1] - 2026-07-26

The first release after `v0.1.0`, and the first one that can change what your CI reports. Three entries below move findings — folding now reaches array arguments, `class_alias` no longer silences absence claims project-wide, and array literals with a negative key are read by your PHP's version rules — so a green run may go red on claims that were always true and merely withheld. Steins is still a preview with plenty unimplemented, so the `0.1.x` series continues rather than jumping a minor; read the entries rather than the version number to know what changes.

Alongside those, the binary now carries its own legal notices and can say what version it is, `doctor` reports the code it declines to reason about instead of leaving a quiet run unexplained, and Steins is installable through Composer.

### Added

- **`steins version` and `steins license`** — the binary now tells you what it is and carries its own legal notices. `steins version` (also `-v`, `--version`) prints the version, the date and commit it was built from, the copyright, and where to read the licenses. `steins license` prints Steins' full Apache-2.0 terms followed by every bundled dependency's notice.
  - Both texts are compiled into the executable, which matters because nothing downstream keeps them beside it: `brew install` puts the binary on your `PATH` without `LICENSE`, and so does `cargo install --git`. Apache-2.0 §4(a) entitles you to a copy of the licence and the bundled MIT/BSD/ISC dependencies require their notices to accompany a binary — now the binary carries both itself, whatever your packager installed.
  - One licence reads as one entry, not one per copyright holder: the MIT permission notice is printed once with every dependency's copyright line above it — which is what "the above copyright notice and this permission notice shall be included in all copies" asks for — and bodies differing only in typography (centred versus flush-left) count as the same licence. That is 877 lines rather than the roughly 1,900 a per-crate listing would print, with no attribution lost.
- **`steins doctor` now says what a quiet run was silent about** — a Coverage posture section inventories the code the analyzer parses and then declines to reason about, so a clean run is a measured claim rather than an unexplained silence.
  - Poisoned scopes as a share of all scopes, with the constructs that caused them broken down by kind: `eval`, `include`/`require`, `extract`, `compact`, variable variables, reference assignment, `global`, `static`, and by-ref capture. Every local in such a scope is unknown by design — that is why Steins does not report false positives there, and now it says so.
  - Dam sites broken down by `eval` / unproven include / runtime-name `class_alias`: the sites where an absence claim about a function or class stays silent because runtime code could mint the name.
  - Reflection-driven invocation sites (`->invoke*()`, `->newInstance*()`, `Closure::bind` with a computed scope, `func_get_args()` under a typed signature), reported as an explicitly incomplete guess: these silence nothing on their own, and the list exists to be corrected against real code.
  - The section reports; it never fails. Nothing here is a diagnostic id, nothing enters a baseline, and `doctor` still exits 0 on every environment fact.
- **A Composer channel** — `composer require --dev typedduck/steins` pins the analyzer in `composer.lock` beside the code it analyzes, so CI and every developer resolve the same version.
  - What Composer installs is a PHP shim, not the analyzer: on first use it downloads the release binary matching the installed version, checks it against the sha256 published with that release, and runs it. Later runs use the cached binary and touch no network.
  - Requires PHP 8.1 or newer. A platform with no prebuilt binary — notably arm64 musl — is refused by name and pointed at a source build, rather than handed an archive that cannot run.
- **The effect vocabulary as its own package** — `typedduck/steins-attributes` supplies `#[\Steins\Pure]` and `#[\Steins\Effect]`, and the Composer package requires it, so one install leaves you able to declare an envelope.
  - MIT and inert at runtime, separate from the analyzer because it is vocabulary rather than tooling (ADR-0025). The Homebrew and release-binary channels are unchanged; the attributes were always yours to install there.
- **`count`, `in_array` and `implode` now compute their value when you write the array out.** Steins evaluates a small set of pure builtins on your own PHP and carries the answer forward as a known value; until now it could only pass scalars to them, so these three — the ones whose whole job is to take an array — never actually ran. `count([1, 2, 3])` is `3`, `implode(",", ["a", "b"])` is `"a,b"`, `in_array(2, [1, 2, 3])` is `true`, and any check downstream of that value now has something to check. Nested literals count too: `count([[1, 2], [3]])` is `2`.
  - **This can surface findings that were not firing before**, in the ordinary way that knowing a value does: a folded result flows into argument, return and contract checks like any other proven value.
  - The array has to be written out in full. One element Steins cannot prove — a variable, a call, an offset read — and the whole array is unknown, because `count([1, $x])` is not `2` when `$x` might be an array. A literal of more than 256 entries or nested more than 8 deep is left alone as well.
  - The keys are your PHP's, not an imitation of them: the array is built by the same engine that evaluates the call, so a repeated key, an omitted key after an explicit one, and the negative-key rule PHP 8.3 changed all behave exactly as they do when you run the code.

### Changed

- **`THIRD-PARTY-LICENSES.md` now reads as one entry per licence, not one per copyright holder.** The file ships inside every release archive, and in 0.1.0 it repeated the MIT permission notice once for each of the 39 dependencies that ship it, because the copyright line above each one differs. Those sections are now grouped by the permission notice, with every crate's copyright notice listed above it — which is exactly what "the above copyright notice and this permission notice shall be included in all copies" describes. The file goes from 1,897 lines and 49 sections to 671 and 9, with **no holder dropped**: the regrouping is checked by a test comparing the before and after sets of copyright notices rather than trusting the eye. The same treatment applies to any licence family whose text carries a per-crate copyright line; MIT is simply the only one in this tree with more than one holder.

### Fixed

- **`class_alias(X::class, 'Name')` no longer silences the absence family across your whole project.** `X::class` is resolved by the PHP compiler — it is a plain string constant, it autoloads nothing, and `X` need not even exist — but Steins was reading it as a name minted at run time and raising the runtime-definition dam on it. That dam is a single project-wide switch, so **one** such call anywhere in the analyzed universe made `call.undefined-function`, `class.undefined`, and the guarded legs of `call.undefined-method` go quiet in every file. Vendoring one package that writes `class_alias(Thing::class, 'Legacy_Thing')` once per class was enough to do it; on one 85,000-file codebase this accounted for 32,749 of 32,914 dam sites. The call now contributes a class-alias edge to the index, exactly as the two-string-literal form already did, and the alias name resolves.
  - **This can surface findings that were being suppressed** — that is the point of the fix. If your project's dam is now clear where it was not, absence findings you have never seen may appear; they are claims that were always true and always withheld. Everything else about the dam is unchanged: a genuinely computed name (a variable, a concatenation, a function call, a constant) still dams, as do `self::class`, `static::class`, and `parent::class`.
  - The `X::class` spelling is resolved against the file's `use` imports (including grouped `use A\{B, C}`), its namespace, and the `namespace\X` relative form — not taken as written — so the alias points at the class PHP would point it at. A string-literal argument keeps its existing meaning as a runtime FQN spelled out in full.
- **A long report piped to `head` or `less` no longer crashes.** `steins check` on a large tree, `annotate` on a long file, `transform`'s diff and `doctor`'s report could all outrun a pipe buffer, and when the reader went away — which is exactly what `| head`, `| grep -m1` and quitting `less` early do — the command died with `failed printing to stdout: Broken pipe (os error 32)`. Reading a long report through a pager is ordinary use, not abuse. All user-facing output now goes through one writer that treats a closed reader as the reader's decision rather than an error.
  - The command's own verdict is untouched: `steins check | head` still exits 1 when the tree has findings and 0 when it does not, so a pipeline under `set -o pipefail` reports what the analysis found rather than what the pager did. What a closed pipe can no longer do is *invent* a failure — no panic, no exit 101, and no failure exit on a run that succeeded.
- **Array literals with a negative key are read by your PHP's rules, not one fixed version's.** PHP 8.3 changed where an omitted key lands after a negative one: `[-5 => 'a', 'b']` puts `'b'` at `0` before 8.3 and at `-4` from 8.3 on. Steins applied the pre-8.3 rule unconditionally, so on any supported PHP it could hold the wrong key for such a literal — and a key is what `===` and `==` compare, so a wrong key is a wrong verdict about whether two arrays are the same. The rule is now chosen from the PHP that runs your project, and both sides of the 8.3 boundary are served, because the supported floor is 8.1.
  - **This can change findings either way** on code with such a literal: a comparison Steins got wrong now decides correctly, in whichever direction correct happens to be for your PHP.
  - When Steins cannot see your PHP's version — no sidecar answered — it does not guess. A literal whose keys depend on the 8.3 change is treated as unknown and nothing is concluded from it, while every other literal (anything without a negative key) is unaffected. Values folded by your own PHP were always right and are untouched.

## [0.1.0] - 2026-07-25

The first public release. Steins is a static analyzer for PHP built on one commitment: **a bare `steins check` reports only what provably breaks at runtime, and stays quiet about everything else.** That is enforced, not aspirational — the release gate runs the analyzer over roughly 100,000 files of real, clean PHP and fails if it emits a single proof-layer finding. This release ships that gate green.

The trade is deliberate. Steins finds less than a conventional analyzer, and what it does report you should not have to argue with. Where it cannot prove something, it widens and says nothing rather than guessing — and where its own coverage is degraded, it says so out loud instead of quietly reporting less.

### Added

- **`steins check`** — the analyzer. Default output is text; `--format json` emits the same findings machine-readably, with the accounting envelope (vendor-suppressed, suppressed, baselined counts).
- **A two-layer diagnostic model.** The *proof* layer carries the zero-false-positive guarantee and is on by default; the *contract* layer judges what your phpdoc claims against what the code proves (`phpdoc.param-mismatch`, `phpdoc.return-mismatch`, `phpdoc.property-mismatch`, `phpdoc.undefined-method`, the `throw.*` family) and is opted into by profile. Sixteen ids are on the default surface, among them `type.argument-mismatch`, `type.return-mismatch`, `type.property-mismatch`, `readonly.reassigned`, `call.on-null`, `call.too-few-arguments`, `call.unknown-named-argument`, `call.undefined-function`, `call.undefined-method`, `class.undefined`, `offset.missing`, and `offset.on-unsupported`.
- **Diagnostic ids are the contract, not message wording.** Every finding carries a stable `family.rule-name` id you can suppress, baseline, and script against; the sentence it prints may be reworded in any release.
- **Value-precise inference via a PHP sidecar.** Steins types literals by executing *your project's own PHP* over IPC — its version, its extensions, its autoload — so a folded value is what your code actually produces on the runtime it actually runs on, not what a model of PHP guesses.
- **Honest degradation when PHP is absent.** With no reachable `php`, or with `--no-php`, the run drops to a documented *sound subset*, prints that it has done so, and names the findings that go silent (the absence family: `call.undefined-function`, `class.undefined`, `call.undefined-method`). The zero-false-positive bar still holds — nothing false is added, some true things are omitted.
- **Profiles and a baseline ratchet.** Three built-in profiles select which layers and ids are surfaced — `default` (proof + mechanics), `contracts` (adds the contract layer), and `throws-direct` — and you can define your own in `steins.toml`, optionally extending a built-in. `check --set-baseline` captures the current findings so an existing codebase can adopt Steins at zero and ratchet down; the baseline records the profile and id set it was captured under, and says so loudly when the active surface has since grown past it.
- **Three suppression channels and no fourth**: the baseline, inline `@steins-ignore`, and config policy. Vendor code is suppressed by default (`--vendor-diagnostics` to see it).
- **`steins doctor`** — a posture report: which `php` resolved and what it reports, the active profile's surface, written-but-unchecked throw envelopes, baseline health, catalog freshness. It runs no checks and never fails on a merely degraded environment, so it is safe as an install smoke test.
- **`steins annotate`** — reprints a file with a right-margin column of the facts Steins actually proved, for seeing the inference rather than only its complaints.
- **`steins transform`** — two verified codemods: `phpdoc-to-native` promotes phpdoc types to native declarations, and `phpdoc-honesty` corrects phpdoc that the code contradicts. Both are gated on preconditions proven across every call site, and `--apply` is opt-in; without it you get a diff.
- **`steins.toml`** — optional configuration for profiles, path sets, policy, and runtime pseudo-constants. There is no `init`: a zero-config run infers everything from `composer.json` and the autoloader.
- **Prebuilt binaries for five targets** — `x86_64`/`aarch64` Linux (glibc), `x86_64` Linux (musl, static), and `x86_64`/`aarch64` macOS — each with a `.sha256` sidecar, and each archive carrying `LICENSE` and `THIRD-PARTY-LICENSES.md` beside the binary. Also installable with `brew install rigortype/tap/steins`.

### Notes

- **Licensed under Apache-2.0.** You may embed Steins in a proprietary tool, run it as a hosted service, and redistribute it, with no source-disclosure obligation, plus an express patent grant. The separate `steins-attributes` vocabulary package is MIT.
- **Requirements**: PHP 8.x for the sidecar (discovered as `php` on `PATH`); building from source needs Rust 1.97 or newer.
- **There is no crates.io package**, and this is structural rather than an oversight: the parser backend is a rev-pinned fork and crates.io rejects crates with git dependencies. Install from a release archive, from Homebrew, or with `cargo install --git https://github.com/rigortype/steins steins-cli`.
- **Windows is not shipped.** The sidecar spawns PHP through a temp-dir path that is unverified there, and a binary that mis-spawned it would degrade silently to the sound subset — worse than not shipping.
- **What Steins does not do yet** is written down rather than left to discovery: see [`docs/type-specification/not-implemented.md`](docs/type-specification/not-implemented.md). It is also not a linter or a formatter, and will not become one.
